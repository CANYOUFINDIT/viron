# Viron 0.1.6 全功能介绍与操作手册

本文面向 Viron 使用者、组织管理员和平台管理员，介绍 0.1.6 版本当前已经交付的全部产品能力、常用操作路径和管理员维护方式。界面操作以当前 Web 与桌面共享界面为准；底层架构、API、安全约束和验收口径见 [TECHNICAL-DESIGN](../TECHNICAL-DESIGN.md)，尚未交付的方向见 [ROADMAP](./ROADMAP.md)。

## 1. 产品概览

Viron 是以“环境”为中心的运维工作台。它把网站入口及其多套登录账号、SSH 主机、MySQL/MariaDB、Redis、日志配置和 Markdown 运维知识组织在同一工作空间中，并直接提供 Web 浏览、SSH 终端、SFTP、实时日志、数据库维护、Redis 维护和环境知识库能力。

典型使用流程是：

1. 选择个人或组织工作空间。
2. 创建环境组和环境。
3. 手工创建、导入或同步 SSH、数据库和 Redis 连接。
4. 把连接关联到一个或多个环境。
5. 从环境详情或全局工作台进入 Web、SSH、日志、数据库、Redis 和知识库操作。
6. 通过当前连接、操作审计、终端录像和 SQL 历史检查运行状态与操作记录。

### 1.2 Web、Lite、Full 与桌面 App

| 使用方式 | 如何进入 | 目标连接从哪里发起 | 适用场景 |
| --- | --- | --- | --- |
| Full 浏览器客户端 | 浏览器打开 Viron 服务地址 | 全部由 Viron 中心服务发起；Web 页面由服务端 Chromium 打开 | 无需安装客户端、统一网络出口 |
| 桌面 App + Lite 服务端 | App 填写 Viron Endpoint | 默认由当前电脑本机发起；也可对服务端支持的分项改用服务端转发 | 中心只提供控制面，不提供浏览器页面 |
| 桌面 App + Full 服务端 | App 填写 Viron Endpoint | 默认本机直连，可切换服务端转发；Web 在服务端不支持代理时仍使用本机 | 同时支持 Web 和 App，按网络位置选择执行端 |

Lite 不提供浏览器客户端静态页面，也不包含用于目标网站代理的 Chromium；但保留桌面登录、凭据授权和 SSH/SFTP/日志/数据库/Redis 服务端转发能力。Full 在同一 Origin 提供页面、API、WebSocket 和全部服务端转发能力。

桌面 App 的共享界面覆盖 macOS 与 Windows 构建；当前仓库已经对 macOS 12+ 的 Apple Silicon 和 Intel 产物进行打包与本机能力设计，Windows x86/x64/arm64 安装包能够构建并完成结构校验，但正式使用前仍需在对应真实 Windows 环境完成运行验收。

## 2. 账号、角色、工作空间与权限

### 2.1 三类管理身份

| 身份 | 管理范围 | 不自动获得的权限 |
| --- | --- | --- |
| 平台管理员 | 创建平台账号、重置密码、启停账号、查看和关闭全平台活动连接、调整终端录像与 SQL 历史保留期、导入导出平台迁移包 | 其他用户个人资源、未加入组织的组织资源 |
| 组织管理员 | 管理当前组织的成员、项目组、邀请、资源和授权；可把自己的个人资源复制进组织 | 其他用户个人空间、其他组织 |
| 组织成员 | 使用直接授权及项目继承到的资源；创建并维护自己的知识库文档 | 查看明文组织凭据、修改未获知识库编辑权的组织资源、继续授权 |

平台角色和组织角色相互独立。平台管理员只有在加入某个组织并具有对应组织角色后，才按组织规则访问该组织资源。

资源授权允许成员进入对应 Web、SSH、SFTP、日志、数据库或 Redis 工作台，并按目标连接本身的账号权限执行读取或写入；它不是 Viron 内置的只读授权。Redis 连接可以单独启用可信执行端只读策略，数据库和 SSH 的最小权限需要由目标系统账号控制。知识库采用单独规则：组织成员可以查看组织工作空间的全部文档并创建、维护自己的文档；组织管理员可按文件夹或文档向成员/项目组增加编辑权。进入环境知识视图或增删环境标签仍要求对应环境访问权。

### 2.2 工作空间

每个用户注册后自动拥有个人空间，也可以加入多个组织。左侧栏顶部的“当前工作空间”决定：

- 当前页面能够查询和使用哪些资源；
- 新建环境、连接、同步源等资源归属于哪里；
- 工作台会话和审计记录归属哪个空间；
- 组织授权是否生效。

切换工作空间后，Web 会重新进入新空间；桌面 App 会回到环境总览并刷新。操作前应先确认左侧栏显示的是正确空间，避免把资源建到个人空间或错误组织。

### 2.3 组织授权继承

组织管理员可以把以下资源直接授权给成员或项目组：

- 环境组；
- 环境；
- SSH 连接；
- 数据库连接；
- Redis 连接。

权限计算规则：

- 成员有效权限 = 个人直授 + 所属项目组授权 + 祖先项目组授权；
- 项目组的子项目组继承祖先项目组授权；
- 环境组授权动态包含组内当前及以后加入的环境，以及这些环境关联的连接；
- 环境授权动态包含该环境当前及以后关联的连接；
- 单连接授权只开放该连接，不反向开放所属环境；
- 组织管理员始终可以管理本组织资源。

知识库编辑授权采用加法继承：文件夹授权覆盖其当前和未来的全部子文件夹及文档，单篇文档授权只作用于该文档；不提供对子节点单独拒绝父级授权。知识库授权本身不会开放环境，成员仍需先通过环境组或环境授权取得环境访问权，才能查看该环境筛选视图或修改对应标签。

## 3. 登录与首次上手

### 3.1 浏览器登录

1. 打开 Full 服务端地址，例如 `https://viron.example.com`。
2. 输入用户名和密码，点击“进入运维桌面”。
3. 没有账号时可点击“没有账号？自主注册”，输入用户名、密码和确认密码后创建账号。
4. 非共享电脑可以选择“记住密码”；该选项保存在当前浏览器站点数据中。共享电脑不应启用，离开前应退出登录并清理站点数据。

生产默认密码规则是至少 10 个字符，并在大写字母、小写字母、数字、特殊字符中满足至少 3 类。管理员可能只在本地开发实例显式放宽该规则。

### 3.2 桌面 App 登录

1. 在登录页填写 Viron Endpoint，只能填写 HTTP(S) Origin，例如 `https://viron.example.com` 或 `http://192.168.1.20:8080`。
2. Endpoint 不能包含路径、查询参数、Fragment 或内嵌用户名密码。
3. App 会先验证健康状态、产品身份和 API 协议兼容性，再允许登录。
4. 输入平台用户名和密码登录。App 不保存登录明文密码；最近成功的 Endpoint 和每个 Endpoint 的 Session Cookie 相互隔离保存。
5. 首次使用本机凭据执行能力时，Viron 会自动创建当前安装的设备密钥。macOS 不会请求钥匙串授权。

桌面 App 与浏览器使用同一登录页，也可以点击“没有账号？自主注册”创建平台账号。Lite 没有浏览器页面时，可以直接在桌面 App 完成注册。

### 3.3 推荐的首次配置顺序

1. 在左侧工作空间选择器确认使用个人空间还是目标组织。
2. 在“环境总览”创建环境组和环境。
3. 需要私钥认证时，由个人空间所有者或组织管理员在“SSH 密钥”中导入或生成密钥。
4. 在“连接资源池”手工新建连接，或通过“导入”“连接工具 → 连接同步”批量取得连接。
5. 在连接资源池勾选连接并执行“关联环境”。
6. 进入环境详情，添加 Web 入口、登录账号和日志配置。
7. 在“连接工具 → 连接巡检”批量检查 SSH、数据库和 Redis 可达性。
8. 从环境详情或全局工作台开始实际运维。

## 4. 主界面与通用操作

### 4.1 左侧主导航

| 菜单 | 用途 |
| --- | --- |
| 环境总览 | 管理环境组和环境，并进入环境详情 |
| 知识库 | 查看和维护当前工作空间全部文档、文件夹及环境标签 |
| 连接资源池 | 管理 SSH、数据库、Redis 连接及其分组、关联、导入和工具 |
| SSH 密钥 | 导入、生成、导出和维护当前工作空间的 SSH 密钥；只向个人所有者和组织管理员显示 |
| SSH 工作台 | 查看当前空间全部有权使用的 SSH 连接 |
| 数据库工作台 | 查看当前空间全部有权使用的 MySQL/MariaDB 连接 |
| Redis 工作台 | 查看当前空间全部有权使用的 Redis 连接 |
| 操作审计 | 查看操作事件、终端录像和 SQL 历史 |
| 组织与用户 | 创建/加入组织，管理架构、邀请、授权和平台账号 |

从“环境总览”进入环境详情后，如果先切换到设置或其他业务页面，下一次点击左侧“环境总览”或 Viron 标识会返回刚才的环境详情并继续保留的操作现场；在环境详情中再次点击同一入口才会进入环境总览。进入总览后这次返回上下文会清除，切换工作空间或刷新到其他页面也不会跨上下文恢复。

侧栏底部还提供：

- Web 专有的“下载客户端”；
- 菜单展开/收起；
- 全局沉浸模式；
- “当前连接：已用/额度”入口；
- 当前用户名与设置入口。

### 4.2 沉浸模式

- 点击侧栏“沉浸模式”隐藏应用外壳，按 `Esc` 退出。
- 环境详情使用可折叠的树形浮层切换 Web、SSH、日志、数据库、Redis、知识库和服务维护。
- 鼠标悬浮到折叠把手时自动展开导航，移出整个导航面板后自动收起；点击和键盘操作仍然可用。
- 折叠把手可以拖动，并吸附到窗口左、右或顶部边缘。
- 切换工作区、页面或沉浸状态不会销毁已打开的工作台现场。
- 刷新浏览器、关闭后重开或重启 App 不保证恢复活动远端连接。

### 4.3 当前连接与额度

Web 账号实例、SSH 终端、日志流、SFTP 传输、数据库与 Redis 工作台逻辑会话计入同一用户额度，并跨设备、客户端、执行模式和工作空间累计。Redis 命令仍使用受控短连接或连接池执行，但首次成功读取、扫描或测试后会建立工作台逻辑会话，用于活动环境切换、额度和空闲回收。

当前工作空间中只要某个环境已经建立至少一条 Web、SSH/SFTP、日志、数据库或 Redis 真实连接，并且该环境不在前台，就会显示在全局环境画中画中；只进入环境但没有建立连接时不会显示。每个环境对应一张 16:9 最后可见画面缩略图，内容直接保存自用户最后实际看到的 Web、SSH、日志、数据库或 Redis 工作区；缩略图内部不可点击、输入或滚动，点击整张缩略图才会切换回该环境最后访问的工作区和保留现场，进入后该环境会立即从画中画中移除。

多个环境缩略图默认以卡片叠层显示，鼠标悬浮或点击叠层时沿同一条左边线纵向展开，移出后自动收起；展开、收起和切换环境时第一张卡片的屏幕锚点保持不动，其他卡片只在固定列内补位。按住卡片任意非按钮区域即可移动整个叠层，并在靠近窗口边缘时吸附，短按仍会切换到对应环境。每张卡片右上角提供关闭按钮，确认后会关闭该环境当前归属的全部活动连接并立即移除画中画。切换到某张缩略图后，该环境从叠层移除，刚离开的前台环境在仍有连接时进入第一张。一个环境的最后一条连接关闭、空闲过期或因权限失效被释放后，该环境自动消失；断开的环境不会固定保留。

画中画包含当前用户、当前工作空间中能够无损返回的全部已连接环境，Web 账号成功访问页面后会像 SSH、日志、数据库和 Redis 一样立即计为活动连接。普通 Web 使用页面内画中画层；macOS 和 Windows App 使用不会激活或夺取主窗口焦点的独立透明原生子窗口，因此即使当前页面正在显示内嵌目标 Web 页面，画中画仍保持在页面上方。前台工作区按受控低频缓存真实画面，并在离开页面或切换工作区前保存最后一帧；后台工作区只保留交互状态并停止缩略图重绘，原生 Web 页面同时隐藏。缩略图只显示降采样后的不可交互图像副本，不会为了刷新画中画重复运行隐藏的终端、数据库网格或 Chromium 页面。

点击左侧“当前连接”后可以：

1. 查看已用额度、单用户上限和空闲断开时间。
2. 按 Web、SSH、日志、SFTP、数据库、Redis 筛选。
3. 按连接、用户或环境搜索。
4. 查看运行客户端、执行位置、所属环境、建立时间和最后活动时间。
5. 点击连接记录返回发起位置：从环境详情建立的连接返回对应环境详情和连接，从全局 SSH、数据库、Redis 或 SFTP 工作台建立的连接返回对应工作台；App 连接尚未识别来源字段的旧版服务端时也会在当前 App 会话保留这次发起位置。
6. 主动关闭自己的连接；平台管理员可以关闭所有用户连接。

连接记录属于当前工作空间时可以直接返回发起位置。其他工作空间中的连接不会触发自动切换，因为切换工作空间会关闭活动连接；界面会保留当前连接并提示工作空间不一致。

关闭中心登记的连接会释放远端资源，但发起连接的客户端保留最后画面、终端输出、日志或数据库编辑内容，并标记为已断开。达到额度上限时系统拒绝新连接，不会抢占已有连接。

## 5. 个人设置、外观语言与桌面设置

点击左侧用户名进入“设置”。

### 5.1 个人信息

- 查看用户名、平台角色、账号 ID 和注册时间。
- 展开“修改密码”，输入当前密码和两次新密码后保存。修改成功会使其他登录会话立即失效。
- 点击“退出登录”。如果仍有活动连接，系统会先提示这些连接将被关闭。

### 5.2 外观与语言

Viron 的共享 Web、macOS 和 Windows 界面支持中文与英文。客户端尚未保存语言偏好时会读取系统首选语言：`zh-*` 使用中文，其他系统语言使用英文。之后可在“设置 → 外观与语言 → 界面语言”选择“中文”或“English”；选择按当前浏览器站点或桌面 App 本地保存，同一客户端上的不同登录账号共用。

语言切换会自动刷新当前 Viron 界面，使导航、工作台、弹窗、校验提示、Element Plus 组件以及桌面 App 原生菜单统一生效。用户录入的名称、备注、SQL、命令、终端输出和数据库内容不会被翻译。

支持浅色、深色和明亮三种主题。切换后立即更新 Vue 页面、终端、Monaco 编辑器和数据网格，不刷新页面，也不销毁活动工作区。

主题只保存在当前浏览器站点或桌面 App 本地，不上传到服务端，也不按登录账号隔离。同一客户端切换账号后仍沿用当前主题。

“设置 → 外观与语言 → 连接质量悬浮面板”可以按当前设备开启或关闭连接监控，默认关闭。开启后出现半透明面板：按住任意位置都可以拖动，靠近边缘时自动吸附；短按非按钮区域可以展开或收起详情。桌面 App 使用独立原生透明层，因此面板不会被本机 Chromium 目标页面遮挡，浏览器、macOS 和 Windows 使用相同的信息结构与交互方式。

面板常态显示两条并列链路：第一条是当前设备到 Viron 服务，第二条是当前执行端到本人最近活动的 Web、SSH、日志、SFTP 或数据库目标。服务端转发显示 `VIRON → 目标`，本机直连显示 `本机 → 目标`。每条链路显示对应执行端发起的探测延迟和最近 5 秒内 Viron 实际观察到的业务上下行吞吐；没有业务数据时显示 `0 B/s`，这不表示链路带宽上限为零。点击展开后可以查看抖动、请求失败率和本人其他活动目标，并切换需要关注的目标。

目标使用“本机直连”执行时，桌面 App 主进程从建立该活动连接的当前设备探测目标地址；其他浏览器或桌面 App 不显示不属于自身执行实例的本机活动目标。真实业务流量不会经过 Viron 服务，因此 Viron 只能显示已上报的本机业务吞吐，未上报时通常为 `0 B/s`。面板会在目标列表中标明“本机直连”或“服务端转发”。

“立即测速”使用 256 KiB 数据测试当前设备到 Viron 的上下行，并按所选目标的实际执行模式刷新本机或 Viron 到目标的 TCP 建连延迟。目标侧探测只连接当前已有权限且仍处于活动状态的目标地址，不登录目标、不执行命令、不写测试文件，因此目标速率继续以真实业务吞吐表示，而不是虚构的带宽容量。数据库 SSH Tunnel、跳板机等多跳连接的 TCP 探测值仅代表保存目标地址从对应执行端的可达性；判断实际操作体验时应同时参考业务吞吐、失败率和工作台错误。

### 5.3 MCP

Web 与桌面 App 都在“设置 → MCP”展示服务端 MCP：

- 服务端由管理员通过 `VIRON_MCP_ENABLED` 配置，默认关闭；页面展示当前状态，开启时展示 Streamable HTTP 连接地址、个人 API Key 认证方式、能力数量和当前账号的客户端。
- 页面只显示当前登录账号的 MCP Session，不显示其他用户，也不显示个人 API Key、Broker Token 或握手秘密。
- 服务端关闭时不注册远程 `/mcp`，但不会影响桌面 App 的本机 MCP。

桌面 App 还显示独立的“本机 MCP”区域。该开关默认关闭并按当前设备持久化；新安装和升级后的首次使用都必须由用户手工开启。开启后页面展示 STDIO 启动器、Broker 地址、运行状态，以及本机客户端名称、版本、连接时间和最后活动时间。关闭时会先提示并立即断开本机客户端、取消仍在等待的本机 MCP Operation。使用服务端 MCP 的用户不需要开启本机 MCP。

本机 MCP 的审批模式在“设置 → MCP”选择并按设备保存；远程 MCP 的审批模式在“设置 → API Key”创建或调整个人 API Key 时选择，同一个 Key 建立的所有 MCP Session 使用同一策略：

| 模式 | Viron 行为 | 推荐 Codex `default_tools_approval_mode` |
| --- | --- | --- |
| 请求批准 | 所有风险 Operation 都打开 Viron 确认页 | `prompt` |
| 替我审批 | 中风险 Operation 自动执行，高风险 Operation 打开确认页 | `auto` |
| 完全访问权限 | 所有风险 Operation 自动执行，不打开业务确认页 | `approve` |

Codex 的批准是另一层客户端安全设置，不能代替 Viron 设置，也不会自动同步到 Viron。用户需要在 Codex 配置中为对应 MCP Server 设置 `mcp_servers.<id>.default_tools_approval_mode`；Viron 页面展示的是推荐映射。无论选择哪一档，创建或更新密码、私钥、Cookie、Token、TLS 私钥等秘密时仍必须在 Viron 安全页面输入，账号安全、成员与授权控制以及秘密读取或导出仍然禁止。

本机确认窗口不会锁住 Viron 主窗口，可以通过窗口关闭按钮取消。Operation 完成、失败、取消或过期后窗口会自动关闭。

连续使用同一 SSH/SFTP/日志、数据库或 Redis 连接时，本机直连和服务端转发都会复用已经建立的传输，空闲 60 秒后自动关闭；Web 页面继续复用当前页面实例。系统不会为此额外保存一份明文凭据。登出，切换 Endpoint、工作空间或执行模式，更新或删除连接，以及设备授权失效都会立即关闭相关传输。

Agent 需要连续读取同一目标时，应优先使用目录中的 SSH、数据库或 Redis 批量读取操作：每次最多 20 项。SSH 只允许可证明为低风险的只读命令，数据库只允许单条 `SELECT` 或 `EXPLAIN SELECT`，Redis 只允许带资源上限的读取命令；任一输入不满足条件时请求会在执行前被拒绝。批量能力不适用于写入、上传、删除或 Web 提交，这些动作仍单独确认并记录审计。

### 5.4 桌面快捷键

桌面 App 可在“设置 → 快捷键”录制、清除、恢复和保存通用快捷键；Viron Agent 快捷输入的唤起快捷键在“设置 → Viron Agent”中修改。默认绑定如下，`Mod` 在 macOS 表示 `Command`，在 Windows 表示 `Ctrl`：

| 操作 | 默认快捷键 |
| --- | --- |
| 打开设置 | `Mod+,` |
| 搜索当前内容 | `Mod+F` |
| 新建当前对象 | `Mod+N` |
| 设计当前对象 | `Mod+D` |
| 关闭当前页签 | `Mod+W` |
| 保存或提交 | `Mod+S` |
| 刷新当前内容 | `Mod+R` |
| 执行当前内容 | `Mod+Enter` |
| 唤起 Viron Agent 快捷输入 | macOS：`Option+Space`；Windows：`Ctrl+Shift+A` |

`Mod+Shift+W` 固定关闭窗口，不能覆盖。系统、窗口和文本编辑保留组合不能保存为业务快捷键；Windows 的 `Alt+Space` 属于系统窗口菜单，不能用于 Viron Agent。Viron Agent 唤起快捷键只在 Viron 获得焦点且入口模式为“快捷输入”时生效，不注册系统级热键。

### 5.5 桌面连接与执行

“设置 → 连接与执行”提供：

- 本机直连：Web、SSH/SFTP、日志、数据库、Redis 和巡检从当前电脑发起；
- 服务端转发：各能力按中心服务声明从服务端发起；
- 实际执行位置列表：逐项显示当前是本机、服务端还是不可用。

切换模式前 App 会统计当前实例的 Web、SSH、SFTP、日志、数据库和 Redis 活动资源。确认切换后关闭这些连接，但保留工作台布局和编辑内容；释放失败时不会切换。目标连接失败后不会静默改变网络出口。

Web 是服务端转发模式的明确例外：若服务端不支持 Web 代理，桌面 App 仍使用本机 Chromium。

### 5.6 Viron Agent

桌面 App 可在“设置 → Viron Agent”选择 OpenAI API 或 Anthropic API，填写模型 Endpoint 和 API Key，并从自动获取的模型列表中选择模型。配置按当前电脑、Viron Endpoint 和登录用户隔离；macOS 使用 App 数据目录中的安装级随机密钥对 API Key 进行 AES-256-GCM 加密，Windows 继续使用当前系统用户的安全存储，API Key 不上传远端 Viron 服务且保存后不回显明文。该页面还提供“悬浮按钮”“快捷输入”和“关闭”三个互斥入口状态，不提供同时开启；尚未保存过入口偏好的设备默认关闭，已经保存的选择保持不变。完整 Chatbox、快捷输入和回复气泡中的助手身份显示为“小 V”，设置、配置、入口和其他功能页面使用“Viron Agent”。

同一页面提供两组相互独立的控制。审批策略包括“请求批准”“帮我批准”和“完全访问权限”：“请求批准”让每个执行动作在对话卡片中确认一次，点击“确认并执行”后不再打开第二个确认窗口；“帮我批准”自动执行能够证明为低风险的只读动作，其他动作仍询问；“完全访问权限”自动执行 Viron 已实现且启用的动作。执行位置包括“在对话中显示”和“直接操作工作台”：前者通过受控后台通道执行并在 Agent 卡片展示结果，后者把命令、SQL 和原始结果显示在当前绑定的 SSH 终端或数据库工作台。所有策略都不会扩大当前用户权限、绕过工作空间和资源绑定、改变执行模式、关闭审计，或开放尚未实现的工具。旧配置默认使用“请求批准 + 在对话中显示”；保存模型、审批策略或执行位置后，正在运行的 Agent 会话会终止，下一轮使用新设置。

Viron Agent 是仍在开发中的实验性功能，生成内容和操作建议可能不准确或不可靠，使用存在风险。请谨慎使用，并在执行命令、SQL 或其他操作前自行核验。

悬浮按钮模式提供完整 Chatbox：点击右下角按钮后可发送消息、查看流式回复、停止当前请求，并拖动按钮或将其吸附到窗口边缘。每轮助手回复完成后，气泡下方会用一行浅色文字显示本轮耗时和总 token；鼠标悬停可查看输入、输出和缓存等明细。Chatbox 顶部可以打开历史会话列表，并支持新建、切换、重命名和删除；删除后窗口和历史列表保持打开，可继续管理其他会话。启动 App 或首次打开 Agent 时进入新对话，不自动展示上次内容；需要时从历史会话手动切换。尚未发送过消息的新对话会一直复用同一条，重新打开 App、再次打开 Agent 或点击新建都不会再堆出第二条空会话。历史会话按“当前设备 + Viron Endpoint + 登录用户”隔离，不绑定工作空间；切换个人或组织工作空间会保留对话，只终止旧工作空间中尚未完成的执行。

快捷输入模式会隐藏悬浮按钮；在 Viron 前台按 macOS `Option+Space` 或 Windows `Ctrl+Shift+A`（均可修改）后，底部居中出现输入条，Enter 发送，Esc 或再次按快捷键关闭。快捷输入与完整 Chatbox 共用当前历史会话。输入条上方会以互不粘连的独立圆角按钮陈列最近 3 个会话名称，名称超过 14 个字符时以省略号收缩，鼠标悬停可看全文；当前会话高亮；会话更多时用 `...` 展开其余历史，最右侧加号新建会话。展开的列表仍可切换、重命名和删除。发送后输入条保持打开，当前回复或执行结束后可以继续下一轮；右下角最多显示三条回复气泡。多轮时默认叠成画中画卡片，最外面只展示最新一轮，以免遮挡工作台；点击后方露出的历史轮次标题栏会平铺成标题列表，再点击某一轮才展开该轮详情。平铺后可用「叠起历史」、发送新一轮或点工作台空白叠回。气泡上方的「隐藏回复」会暂时收起全部气泡，不再遮挡当前画面；需要时在输入条中点「显示回复」即可恢复，发送新一轮或切换历史会话也会重新显示。每轮完成后，气泡底部同样用一行浅色文字显示本轮耗时和总 token，悬停可看明细。展开后显示完整 Markdown 和可用的受控动作，也可单独关闭。启动后不会自动铺上一次对话；手动切换到历史会话后，会恢复该会话最近的回复气泡，并仍默认叠起历史。

Viron Agent 不再显示场景卡片、附件按钮或“加入当前现场”。每次发送消息时，App 才静默采集当前页面以及可见 SSH/数据库工作台的受限摘要，作为该轮优先提示。提示不写入历史会话，也不构成权限；Pi Agent 仍可按任务通过 Viron 工具搜索和调用当前用户有权访问的其他资源。

关闭模式会隐藏悬浮按钮、快捷输入条和回复气泡，唤起快捷键也不响应。该操作不会删除模型配置、快捷键配置或当前 Viron Agent 会话；重新切换到悬浮按钮或快捷输入后可以继续使用。

App 本机 Web 页面会继续显示所选 Viron Agent 入口。SSH、数据库等普通工作台里，Chatbox 和快捷输入仍在当前窗口内悬浮，可直接点击和输入。打开本机 Web 页面时，同一套对话层会叠在原生页面上方，不会挤占或缩小页面显示区域；关闭后页面保持原有尺寸并保留登录状态。

在 App 的 SSH 工作台中，先打开并聚焦一个已连接终端，再从完整 Chatbox 或快捷输入发送消息。App 会在发送时读取该会话最近的受限输出，移除终端控制字符，对常见凭据做脱敏，并把采集范围作为本轮内部提示。需要 SSH 命令时，小 V 可以生成一条结构化单行命令；点击“填入终端”只会把命令放到当前 Shell 提示符，不会发送回车。切换到其他页面、会话、服务端转发模式，或终端不在可输入提示符时，填入会被拒绝。

需要多行 Shell 脚本时，小 V 会显示独立脚本卡片，完整展示脚本、`sh`/`bash` 解释器和风险说明。点击“填入终端”前应逐行检查内容；App 只在当前终端处于普通 Shell 提示符并已启用 bracketed-paste 安全粘贴模式时清空当前命令行并填入完整脚本，不发送回车。一次手工回车可能执行整段已填入内容，因此执行前仍应在终端中复核。Viron Agent 不会把脚本写成远程文件，也不会自动执行；本机操作记录只保存解释器和行数，不保存脚本正文。

能够由 Viron 共享命令策略证明为只读的 SSH 诊断建议可以按当前审批策略执行。需要批准时，L2 卡片显示目标 SSH、完整命令、诊断步骤和执行位置，点击一次“确认并执行”即完成本步授权。选择“在对话中显示”时，本机直连和服务端转发 SSH 都使用绑定当前交互会话的独立受控通道，结果显示在 Agent 卡片中，不向交互终端发送回车。选择“直接操作工作台”时，必须停留在 Agent 绑定的可见终端，且终端已连接、处于普通缓冲区、位于空闲 Shell 提示符并且没有待输入内容；Viron 会把单行命令写入当前终端并发送回车，命令和原始回显保留在终端中，Agent 只读取脱敏、截断后的结果继续分析。小 V 即使改走通用 MCP SSH 命令，只要目标仍是当前可见终端对应的连接，也会改到该终端执行，而不会再开一条后台通道。工作台执行期间会锁住普通终端输入，取消或超时会发送 `Ctrl+C`。无法证明为只读的单行写命令可以使用 `confirm-write`：审批卡会显示高风险原因，确认后按当前执行位置运行。多行脚本仍只能安全填入，不能自动执行。账号安全和服务管理类命令继续被拒绝。

在 App 本机直连数据库工作台中，连接并选择具体数据库后，从完整 Chatbox 或快捷输入发送消息。App 会在发送时采集受限的 Schema、当前或选中 SQL 以及最多 20 行结果预览。小 V 生成的 SQL 可只填入编辑器；单条 `SELECT` 或 `EXPLAIN SELECT` 可按当前审批策略执行。选择“在对话中显示”时，查询通过受控后台连接执行并在 Agent 卡片显示受限结果；选择“直接操作工作台”时，SQL 会写入当前查询页签，完整结果保留在结果网格，并复用工作台现有的查询轮询、历史和取消路径。对当前可见数据库连接，通用 MCP 只读查询也会改到该页签执行。两种位置都只向模型返回最多 100 行、经过截断和脱敏的结果。单条受控写 SQL 可以使用 `confirm-write`：审批卡会显示风险级别、目标对象，以及可解析 UPDATE/DELETE 的预计影响行数，确认后执行并返回受影响行数。多语句、文件输出、锁副作用查询和账号安全/服务管理 SQL 不会进入数据库专用执行工具。本机 Viron Agent 操作记录默认保留 30 天，可在“设置 → Viron Agent”手工清除。

Viron Agent 的多轮 ReAct 和工具循环由 Pi Agent 驱动。Pi 可以使用 Viron 紧凑工具搜索当前业务目录并调用已注册的读、写、高危或凭据安全 Operation，也可以使用当前 SSH/数据库专用工具；审批、权限、审计和执行位置仍由 Viron 控制。需要批准时，Pi 的工具调用会在同一轮中等待内联确认，批准后原地继续，不会重新开始模型阶段。单次执行最多 64 次工具调用，总时限 20 分钟，包含模型生成、等待确认和工具执行。达到限制后不会继续调用工具。关闭相关连接、点击“结束诊断”、禁用 Viron Agent、修改 Agent 设置、退出登录、切换工作空间或切换执行模式都会终止当前执行，但不会删除历史会话。

当前支持本机直连和服务端转发 SSH 现场，但 SSH 命令或多行脚本的“只填入”仍仅用于本机直连终端。Viron MCP 业务目录中已经注册的 Redis、知识库、服务维护、Web 等操作可以通过紧凑网关被 Pi 搜索和调用，并继续受对应权限、风险模式、审批、凭据窗口和审计约束；没有注册为业务 Operation 或尚未完成领域安全策略的能力不会开放。远程脚本文件创建、脚本自动执行、数据库批处理任务、Redis 写命令和 Web 页面操作仍需各自的专用安全工具与影响预览，不能通过 SSH/数据库专用工具绕过。

历史会话文件最多保留 80 个会话、每个会话 240 条消息，只保存经过长度限制和常见凭据脱敏的用户/助手文本，以及助手消息的本轮耗时与 token 用量摘要；不保存 Pi 工具调用、完整终端输出、完整查询结果、瞬时现场提示或凭据。

### 5.7 客户端版本

在“设置 → 客户端版本”查看 App 版本、当前 Endpoint，并点击“检测更新”。服务端版本更高且提供匹配安装包时，App 会下载、校验、安装并重新启动；不会自动降级到更低版本。

## 6. 组织、成员、项目组与授权

### 6.1 创建或加入组织

- 点击“组织与用户 → 创建组织”，填写名称和说明。创建者成为组织管理员。
- 点击“加入组织”，粘贴完整邀请链接。验证成功后进入邀请确认页。
- 也可以直接在浏览器或桌面 App 中打开 `/join/<token>` 邀请链接。

加入组织后默认是普通成员。邀请指定项目组时会自动归组；已经在组织中的成员也可以使用有效链接加入目标项目组。

### 6.2 管理组织架构

组织架构树包含组织根节点、任意层级项目组和成员：

1. 选择组织根节点，点击“新建项目组”创建根项目组。
2. 选择项目组，通过节点操作创建子项目组、编辑、删除或维护成员。
3. 成员可以同时属于多个项目组；未归组成员显示在组织节点下。
4. 选择成员可以查看邀请人、状态、角色、所属项目组和有效授权。
5. 组织管理员可以把成员设为管理员、降为普通成员或移出组织。

删除项目组不会删除成员账号。邀请链接原本指向已删除项目组时，会降级为只加入组织。

### 6.3 生成和管理邀请链接

组织管理员进入“邀请”页：

1. 点击“生成邀请链接”。
2. 可选加入后自动进入的项目组。
3. 选择 1 小时、24 小时、7 天或 30 天有效期。
4. 选择 1、3、5、10、不限人数，或自定义 1–10000 人。
5. 生成并复制链接。

邀请列表展示创建者、目标项目组、状态、到期时间、已用/剩余名额和可追溯加入用户。管理员可以再次复制、撤销或删除记录。过期、名额耗尽、撤销或删除后都不能继续使用；已经加入的用户不受影响。

### 6.4 给成员或项目组授权

1. 在组织架构树选择目标成员或项目组。
2. 点击“授权资源”。
3. 选择环境组、环境、SSH、数据库或 Redis 类型，并在该类型下同时选择一个或多个资源；列表自动排除当前目标已经直接获得或从项目组继承的同一资源授权。
4. 保存后在授权台账查看直接授权和继承来源。
5. 直接授权可在当前节点撤销；继承授权需要回到来源项目组撤销。

### 6.5 平台账号管理

平台管理员可以打开“平台账号”页：

- 输入用户名、初始密码，可选“设为平台管理员”后创建账号；
- 查看账号的平台角色、组织数量和启停状态；
- 重置密码；
- 停用或重新启用账号；
- 不能停用当前正在操作的自己。

平台账号创建不等于加入任何组织，仍需通过邀请或组织管理建立成员关系。

## 7. 环境总览与环境详情

### 7.1 环境组

1. 在“环境总览”点击“新建环境组”。
2. 填写名称、说明和识别色。
3. 创建后可编辑名称、说明和颜色。
4. 拖动环境组名称旁的排序把手，可同步调整左侧目录和右侧分组的先后顺序；“未分组”固定在末尾。
5. 可把环境拖动到不同环境组或“未分组”。
6. 删除环境组时，组内环境保留并移动到“未分组”。

环境组只有一层；连接组和环境组是两套独立分类。搜索环境时排序把手暂不可用，清除筛选后即可继续排序。

### 7.2 环境

1. 点击“新建环境”，填写名称、可选环境组、逗号分隔标签和说明。
2. 通过顶部搜索按环境原名、当前账号设置的别称或标签筛选。
3. 点击卡片地址栏的星星可收藏或取消收藏环境。页面最上方的“收藏”分组使用与其他环境组相同的完整卡片，收藏环境也继续保留在原分组中。收藏仅对当前账号可见，个人和组织工作空间均可使用，并随账号在 Web、macOS 和 Windows 客户端间同步。
4. 环境卡片展示标签、Web/SSH/数据库/Redis 数量和更新时间；在组织工作空间中，点击卡片 Tab 名称旁的编辑图标可设置仅当前账号可见的环境别称，按 `Enter` 或点击其他位置自动保存，按 `Esc` 取消，置空后恢复显示环境原名。别称会随账号在 Web、macOS 和 Windows 客户端间同步；卡片地址栏和环境详情始终显示组织共享的环境原名。进入详情后，知识库页签显示文档总数；服务维护入口分别显示服务数和已监控宿主机数。
5. 拖动卡片底部的排序把手，可调整同一组内的卡片顺序，也可把卡片放入其他环境组或“未分组”；刷新页面后顺序保持不变。收藏分组中的重复卡片不参与排序或拖放。
6. 打开环境后可编辑名称、环境组、标签和说明。
7. 删除环境会永久删除该环境的 Web 入口、Web 登录账号和日志配置，并关闭、清理对应 Web Profile；知识库只移除该环境标签，文档、正文、图片和编辑授权继续保留。SSH、数据库和 Redis 连接也只解除与该环境的关联；没有其他环境后进入“待分配”，不会删除连接或凭据。

环境删除会撤销该环境的直接授权，环境组或环境授权动态带来的访问范围也会随资源关系立即变化。环境或连接配置变更会使当前工作空间的活动运行资源失效；应避开正在执行 SSH、SFTP、日志、数据库或 Web 操作的时段。

### 7.3 环境详情工作区

环境详情当前包含：

- Web；
- SSH；
- 日志；
- 数据库；
- Redis；
- 知识库；
- 服务维护。

这些工作区保持统一尺寸。切换页签、菜单、路由或进入其他业务页面时，已经访问的工作区不被销毁；返回后继续此前操作。

### 7.4 知识库

知识库属于当前工作空间：个人空间只包含当前用户的文档，组织空间包含组织文档。左侧“知识库”展示全部内容；“环境详情 → 知识库”是同一批文档按环境标签生成的筛选视图。Web、macOS 与 Windows App 使用同一界面和中心数据。

#### 创建与分类

1. 从左侧“知识库”进入全局文档树，或进入“环境详情 → 知识库”查看当前环境内容。
2. 点击目录顶部“+”创建 Markdown 文档。输入框尾部固定显示 `.md`，只需输入文档名称；全局创建的节点默认不分配环境，环境内创建的节点自动携带当前环境标签并保存到该环境的专属目录。
3. 有文件夹编辑权时点击文件夹按钮创建任意层级目录。根级文件夹只有个人空间所有者或组织管理员可以创建。
4. 把可编辑的文档或文件夹拖到目标文件夹完成移动；拖到目录顶部空白区可移回当前视图根目录。环境视图中的根目录对应当前环境的专属存储目录。
5. 删除非空文件夹时，确认框会显示将要递归删除的文件夹和文档数量；文档专属图片随文档一并删除。

选中文件夹后，顶部的新建和导入操作默认以该文件夹为目标。点击目录树顶部的“知识库根目录”可取消当前选择并把新建目标恢复到根目录；点击目录树中文件节点之外的空白区域不会关闭当前文档或改变选择，文件夹的展开和折叠状态也不会因此改变。环境专属目录本身不会在环境视图重复展示，其直接子内容会作为根级内容显示；通过“关联文档”加入的其他位置文档仍会同时展示。

普通组织成员可以查看组织知识库全部文档、创建文档，并始终能够编辑、重命名、移动和删除自己创建的文档。没有编辑权的其他文档以只读方式打开。

#### 环境标签与关联文档

- 文件夹和文档都可以同时关联多个环境。选择可编辑节点后点击标签按钮增删直接环境标签；修改标签同时要求对应环境的访问权。
- 文件夹标签自动覆盖当前和以后新增的全部后代。移动节点不会清除直接标签，继承标签按新的父目录重新计算。
- 环境知识库只展示有效携带当前环境标签的节点；当只有子文档匹配时，未打标签的祖先文件夹会作为目录上下文显示。
- 在环境知识库点击“关联文档”，可以搜索并批量选择其他可编辑文档，为它们添加当前环境标签。只读文档以及已经直接或继承显示的文档不会进入候选列表。

#### 编辑、预览与自动保存

- 工具栏支持“编辑、分栏、预览”三种模式，桌面默认分栏；只读文档直接使用预览模式。
- 停止输入 1 秒后自动保存，也可以点击“保存”或按 `Cmd/Ctrl+S`。底部持续显示等待保存、保存中、已保存、失败或冲突状态。
- 同一文档被他人先保存时，当前保存不会静默覆盖。冲突条允许先复制本地正文，再加载远端版本。
- Markdown 支持标题、列表、任务标记、表格、引用、链接、代码块和图片；原始 HTML 不执行，危险链接不生成可点击地址。

#### 图片

- 可通过工具栏选择图片，也可直接粘贴或拖入编辑器。
- 支持 PNG、JPEG、GIF 和 WebP，单张不超过 30 MB；不支持 SVG。
- 图片以 Base64 存入元数据库并绑定当前文档，不依赖本机或外部文件路径。

#### 导入与导出

- 导入单个 `.md` 会在当前文件夹创建文档；Markdown 内嵌 Data URI 图片会转成独立 Base64 资源。在环境视图导入时，新节点自动携带当前环境标签。
- 导入 `.zip` 会恢复其中的 Markdown 目录结构，并把相对路径图片转为 Base64；导入目录结构需要当前文件夹编辑权。
- 同名文档或文件夹不会覆盖，系统自动追加 `(2)`、`(3)` 等序号。
- 目录顶部只提供一个导出菜单，可按当前选择导出文档或文件夹，也可导出整个工作空间知识库或当前环境知识库。
- 单篇文档导出为独立 `.md`，图片以内嵌 Data URI 保证单文件可查看；文件夹、工作空间知识库或环境筛选结果导出为 ZIP，保留目录结构并输出独立图片文件。

#### 组织编辑授权

组织管理员选择文件夹或文档，点击盾牌按钮，可以向普通成员或项目组授予编辑权。文件夹授权自动覆盖当前及以后新增的全部后代，文档授权只作用于当前文档。撤销直接授权后，成员仍可能因为上级文件夹、项目组或创建者身份继续拥有编辑权。

### 7.5 服务维护与 viron-monitor

“服务”是环境中的逻辑业务服务；同一服务可以在多台机器上拥有多个“部署节点”。每个部署节点引用当前环境已有的一条 SSH 连接，同一 SSH 连接也可以承载多个服务。删除服务或部署节点不会删除远程服务、SSH 连接或日志配置。

使用流程：

1. 进入“环境详情 → 服务维护”，点击“录入服务”，填写名称和说明。工作空间所有者或组织管理员可以拖动左侧手柄调整服务清单和 SSH 宿主机顺序，也可以从每行的更多菜单选择“上移”或“下移”；保存后的顺序由当前工作空间共享，只影响当前环境的服务维护页。
2. 在左侧选择需要持续采集的 SSH 宿主机，点击“一键安装监控服务”。Viron 会先经现有 SSH/跳板链路检查 Linux、`amd64/arm64`、systemd、安装包、目录和权限；目标 SSH 用户必须是 `root` 或具有免密 `sudo`，页面不接收 sudo 密码。
3. 确认预检信息后安装。进度弹窗依次显示目标预检、安装包校验、SSH 会话、临时目录、逐文件上传、安装并启动、重新连接、首次采集和中心入库；“详细日志”默认折叠，展开后只显示经过凭据过滤的远程输出。弹窗可以关闭，安装继续在服务端后台运行；返回该宿主机后点击“查看安装进度”可以恢复。安装失败时会保留失败步骤和日志，点击“重新安装”会从完整预检重新开始。
4. 默认程序目录为 `/opt/viron/monitor`，命令入口为 `/usr/local/bin/viron-monitor`，配置文件为 `/etc/viron-monitor/viron-monitor.env`，本地数据目录为 `/var/lib/viron-monitor`，systemd 单元为 `/etc/systemd/system/viron-monitor.service`。默认目录被非 Viron 内容占用时，页面要求改成 `/opt` 下的另一个安全绝对目录；具有有效安装清单的 Viron 安装可以原位更新，检测到没有清单的旧手工安装时拒绝自动覆盖。
5. 安装完成后 Viron 会自动重新登录 SSH、立即扫描并拉取首批指标。检测到已经安装的节点不再显示“一键安装监控服务”；由 Viron 托管安装的节点可使用“更新监控服务”。宿主机工作区用页签切换“监控”和“服务发现”，默认打开监控。服务发现页可按名称/标识搜索，并按 systemd、Docker、Kubernetes 和运行状态筛选，进入时默认选中第一个有候选的类型；选中 Kubernetes 后再用 context、namespace、资源类型和已发现的 kubeconfig 收窄，结果以可滚动列表展示。点击候选即可纳管：已选定服务时直接打开纳管对话框，否则先选择已有服务或录入新服务。也可以继续切换为手工登记。普通进程当前只登记关系，不提供可靠的通用启停。
6. `viron-monitor` 会检查 `$KUBECONFIG`、root 与普通用户的 `~/.kube/config`、`/etc/kubernetes/admin.conf`、`/etc/rancher/k3s/k3s.yaml`、`/etc/rancher/rke2/rke2.yaml` 和 `/home/*/.kube/config`，额外路径可通过 `VIRON_MONITOR_KUBECONFIG_PATHS` 指定。页面只显示路径、cluster、context、默认 namespace、连通状态和候选数，不上传证书、Token、私钥或 kubeconfig 原文。点击“选择扫描 context”并保存后，目标机才会在本地使用所选 context 连接 Kubernetes API，扫描 Deployment、StatefulSet、DaemonSet，并把 selector 匹配的 Kubernetes Service 名称附在候选元数据中。采集进程固定以 root 运行，因此不需要为 `viron-monitor` 用户另外修改 kubeconfig 属组、ACL 或复制凭据；页面显示“无法读取”时，应检查路径、文件内容、认证插件和 Kubernetes 连接本身。
7. 在部署节点卡片查看状态及可归属的 CPU、内存、运行时间和重启次数；Kubernetes 节点展示期望、就绪、可用、更新中和不可用副本数。每个服务的部署节点卡片下方平铺该服务全部部署节点的监控区域，并绘制 CPU、内存、运行时间和重启次数历史。没有可归属数据的节点仍保留自己的监控区域，并明确显示当前范围没有可绘制数据。在宿主机区查看 CPU 分项、内存与 Swap、负载、磁盘容量与 I/O、网络吞吐与错误、Linux PSI、温度和运行时间。CPU、内存和磁盘 I/O 图使用堆叠组成：所选时间范围贡献最大的固定 Top 5 保持稳定颜色，其他占用合并为“其他进程”；悬浮某个采样点时显示该时刻真实 Top 5 和总量。监控服务只上传 PID、进程名、可执行文件 basename、运行用户及资源数值，不上传完整命令行、启动参数或环境变量。趋势摘要展示当前值、平均、P95、峰值和前后区间变化；自动诊断会标记 CPU 饱和、I/O 等待、阻塞型高负载、内存压力、活跃换页、磁盘 I/O 压力及网络错误区间。服务和宿主机监控均可切换 1 小时、6 小时、24 小时、7 天和 30 天，采集缺口不会被折线跨接。首次打开默认选中并只读取最近 1 小时，更长历史只在主动切换时间范围后读取；多台宿主机分别在数据返回后立即显示，不互相等待。后台刷新期间已有图表保持可见。停留在服务维护页时，页面每 10 秒只读 Viron 中心数据库；需要立即采集时可点击“扫描并拉取”，普通 SSH 用户只通过受限本地 Unix Socket 请求一次固定 root 采集，不会获得 sudo 或任意 root 命令能力。
8. 工作空间所有者或组织管理员点击“告警设置”，可以为当前环境启用宿主机离线、CPU、内存、任一磁盘挂载点使用率、最高温度、磁盘挂载变化和部署节点停止/异常告警，并分别设置阈值。宿主机离线覆盖 SSH 拉取失败、目标机监控程序缺失、返回协议异常，以及采集样本持续未更新；同一工作空间中的重复 SSH 连接按物理 Agent 去重。规则连续两次检查满足异常条件后触发，连续两次恢复正常后解除；同一次异常持续期间不会每轮重复弹窗。磁盘以“设备 + 挂载路径”为稳定身份：首次启用或升级后以当前清单静默建立基线；新的身份连续两次出现时发送“新增磁盘”，既有身份连续两次缺失时发送“磁盘消失”，随后连续两次重新出现时发送“恢复挂载”。采集器过滤常见虚拟文件系统，设置中排除的临时或可移动磁盘不参与使用率和挂载变化判断。
9. 所有有权查看当前环境的用户都会收到全局站内弹窗和未读告警列表，不要求停留在服务维护页面。用户离线期间产生且仍处于活动状态的告警会在下次登录后提醒；一般资源告警恢复时只向已经收到异常提醒的用户显示一次恢复通知。磁盘新增是一次性事件，磁盘消失和恢复挂载分别通知；即使消失提醒尚未投递，恢复挂载仍保留一次待通知状态。macOS/Windows App 使用 Electron 系统原生通知，普通 Web 在 HTTPS 或 localhost 等允许通知的环境中、经用户授权后发送浏览器系统通知；未授权时仍保留站内提醒。点击站内或系统通知会直接进入对应环境的服务维护页并定位宿主机或服务。
10. 服务可以关联当前环境已有的一个或多个日志配置；点击关联日志会切换到日志工作区并定位该配置。启用中的服务可对 systemd、Docker、Podman 或 Supervisor 节点执行启动、停止和重启，执行前必须确认；Kubernetes 首版只扫描和纳管，不提供启停或重启，停用服务、普通进程或已移出环境的 SSH 连接也不能执行。
11. 工作空间所有者或组织管理员可以在服务标题或单个部署节点上打开“功能按钮”管理，设置按钮名称、图标和最多 64 KiB 的 Shell 正文。服务级按钮点击确认后在该服务的全部部署节点上执行，节点级按钮只在对应节点执行；同一服务级按钮按部署节点执行，即使多个节点引用同一 SSH 连接也分别执行。脚本由中心经已有 SSH/跳板链路写入远端 `/bin/sh -s` 的标准输入，以该连接的 SSH 登录用户和默认工作目录运行，不自动使用 `sudo`，正文不会出现在远端进程命令行。页面分别展示每个节点的退出码、耗时、stdout 和 stderr，输出过大时明确截断；审计只保存按钮、目标和执行结果摘要，不保存脚本正文或输出。服务停用、目标连接不可访问或已移出环境时拒绝或标记对应节点失败。
12. 点击“清理监控数据”并二次确认，只会删除当前目标 SSH 主机上的 `viron-monitor` 本地样本和缺口；Viron 中心已经入库的数据继续按中心保留策略保存。

安装脚本保留独立的 `viron-monitor` 用户和同名组作为本地访问控制边界，把指定 SSH 用户加入该组，并以 root 身份启动常驻服务和采集子进程；Viron 会关闭旧 SSH 连接池并重新登录，使新增组权限用于首次触发和拉取。只有首次安装或把旧的非 root 监控服务迁移为 root 服务时需要 root 登录或免密 `sudo`；之后的周期采集、“扫描并拉取”、context 选择和数据拉取都不需要 root 连接密码。已有节点的最近样本不是 root 采集，或缺少当前 `metricsVersion` 采集能力标识时，即使产品版本相同，页面也会显示“更新监控服务”；更新仍由用户确认，不会在后台静默改写 systemd。root 采集可以读取 kubeconfig、systemd、容器 socket 和 `/proc` 资源统计，安装前应由机器管理员把它作为高权限主机组件评估。需要离线手工安装时，仍可完整上传对应的 `dist/monitor/linux-amd64` 或 `dist/monitor/linux-arm64` 目录，并执行 `sudo ./install.sh --ssh-user <SSH 用户> [--install-dir /opt/viron/monitor]`；手工安装不会自动登记为 Viron 托管安装。

`viron-monitor` 默认每 30 秒在目标机采集一次。常驻主程序使用 SQLite/WAL 保存序列化样本；受控的 `viron-monitor-collector` 子进程嵌入固定 Telegraf `v1.39.2` 输入插件，并使用 Kubernetes 官方 `client-go v0.36.2` 解析已发现的 kubeconfig 和访问用户明确选择的 context。Docker 使用默认 socket 或 `DOCKER_HOST`；rootful Podman 自动识别 `/run/podman/podman.sock`，其他 Podman socket 通过逗号分隔的 `VIRON_MONITOR_PODMAN_ENDPOINTS` 配置；Supervisor 默认读取 `http://127.0.0.1:9001/RPC2`，也可通过 `VIRON_MONITOR_SUPERVISOR_URLS` 配置多个地址。

节点默认保留最近 30 天样本，同时继续受 256 MiB 缓冲上限保护。中心服务对每条新关联且尚无状态的 SSH 连接自动探测一次；识别到 Agent 或由 Viron 托管安装后按平台策略持续拉取，已经确认未安装或连接失败的非托管连接不再周期性重复扫描。同一工作空间内指向同一 Agent 的多条 SSH 连接共享中心游标、样本和最新快照，并只计为一台监控主机；同一物理机器分别出现在个人和组织空间时，两个空间仍独立保存和授权。中心也保留最近 30 天历史，长时间范围会降采样到约 480 个绘图点。

节点命令可用于排查：`viron-monitor status` 查看缓冲与游标，`viron-monitor collect` 或 `viron-monitor scan` 通过本地 Socket 请求 root 守护进程立即采集并返回新序列，`viron-monitor configure-kubernetes --selection-base64 <Base64 JSON>` 保存中心校验过的 context 选择，`viron-monitor pull --after <序列>` 只读指定序列后的数据，`viron-monitor clear` 清理本地样本和缺口。`collect`/`scan` 不直接打开采集器或以当前 SSH 用户执行采集；Socket 只接受固定采集动作。`ack --through` 仅为旧版中心兼容保留，不会删除数据。`configure-kubernetes` 的参数由 Viron 页面生成，日常操作不需要手工拼接。

服务、部署节点和日志关联仍由个人空间所有者或组织管理员配置。有权访问当前环境及对应 SSH 连接的成员可以查看监控、人工刷新、安装或更新监控服务、清理节点本地缓冲，以及执行固定的启动、停止和重启动作。

## 8. Web 入口与多账号浏览

### 8.1 创建 Web 入口和账号

1. 进入“环境详情 → Web”。
2. 点击入口列表末尾的“+”，填写入口名称、HTTP(S) 页面地址、说明和标签。
3. 选择入口，点击账号列表末尾的“+”。
4. 填写用户名、密码和备注。
5. 在普通 Web 中，选择账号后可显示密码，再执行复制；两项操作都会审计。桌面 App 不提供明文密码显示或复制。
6. 工作空间管理员可以直接拖动第一行 Web 入口 Tab 和第二行登录账号 Tab 调整顺序；顺序保存到中心服务，刷新、重启或切换客户端后保持不变。

编辑账号时密码留空表示保持原密码。删除账号、入口或环境会关闭对应账号页面，并清理相关本机 Profile；删除前应确认不再需要其中的登录态。

### 8.2 访问页面

1. 单击账号只进入“准备访问”状态，不立即建立连接，也不请求目标网站。
2. 双击页面空白处、点击“访问页面”，或在地址栏点击“新建空白标签页”，才创建实际 Web View。
3. 工具栏提供后退、前进、刷新、地址栏、新建页面、重新填充、重新登录和沉浸/聚焦。
4. 普通 Web 还可以在浏览器新标签页直接打开目标地址；该外部页面不受 Viron 的内置账号隔离和自动填充控制。

自动填充只处理入口原始 Origin 上能够可靠识别的普通登录表单。通过地址栏手工进入同一 Origin 的登录页后，可以点击钥匙按钮，让 Viron 在当前活动页重新识别并填充；不会向跨 Origin 页面填充密码。验证码、MFA、WebAuthn、跨域 SSO 或不确定表单需要手工完成。

### 8.3 账号隔离与多页面

- 服务端执行与 App 本机执行使用两套独立 Profile 存储：Full 浏览器/服务端转发按“Viron 实例 + 用户 + Web 登录账号”保存在中心服务，App 本机执行按“Endpoint + 用户 + Web 登录账号”保存在当前电脑。不同账号不共享 Cookie、缓存和 LocalStorage，同一账号在本机与服务端之间也不共享登录态。
- 同一账号的主页面、网站弹窗、子页面和手工新建页面共享该账号 Profile。
- 同一账号存在多个页面时，出现第三行页面 Tab，可切换、关闭、拖动排序和继续新建；每个账号最多保留 8 个页面。页面顺序只在当前账号浏览会话中保留，账号页面全部关闭后不恢复。
- 切到其他账号或工作区时，已访问账号保留；隐藏页面暂停画面流，切回后恢复。
- “重新填充”会在入口原始 Origin 的当前活动页重新识别登录表单，包括手工新建页和网站弹窗；跨 Origin 页面不会填充。
- “重新登录”只清除当前执行位置的账号 Cookie、缓存和本地存储后重新访问；切换执行位置后可能需要在另一套 Profile 重新登录。
- 网站上传使用文件选择器；下载由浏览器或系统保存对话框落盘。

删除账号、入口或环境时，中心服务会清理对应服务端 Profile；已经连接并同步到该 Endpoint 的 App 也会关闭、清理对应本机页面与 Profile。

桌面 App 中的目标网页原生右键菜单会按点击位置提供后退、前进、重新加载、复制、粘贴、全选和链接操作；“在新标签页中打开链接”会创建共享当前账号登录态的内部页面 Tab，并受单账号 8 页上限约束。选择“检查元素”会打开该账号页面的独立 DevTools。DevTools 能看到当前页面 DOM、网络、Cookie 和存储，只应对有权调试的网站使用；关闭页面时调试会话一并结束。普通 Web 当前不提供同等页面检查器。

## 9. 连接资源池

### 9.1 查看和筛选连接

资源池同时管理 SSH、MySQL/MariaDB 和 Redis：

- 按全部、待分配、已分配筛选；
- 按连接类型筛选；
- 按名称、主机、用户名、标签和来源路径搜索；
- 按层级连接组展示，可逐组或全部展开/折叠；
- 查看目标地址、连接方式、关联环境、来源、上次巡检和凭据保存状态；
- 编辑或删除连接；Redis 可在资源池直接复制，SSH 和数据库连接可在对应工作台的连接菜单复制。

“待分配”表示连接目前没有关联任何环境，但仍可从全局工作台使用。

### 9.2 新建连接

点击“新建连接”主按钮默认创建 SSH；使用右侧下拉可选数据库或 Redis。三类连接都可以设置连接名称、层级连接组和一个或多个关联环境，也可以在表单中直接新建环境、环境组或连接组。

#### SSH

- 主机、端口、用户名和标签；
- 密码、从当前工作空间选择一把 SSH 密钥，或使用 keyboard-interactive；
- 可引用一条已有 SSH 连接作为单级跳板机；
- 可启用多行登录脚本。

#### MySQL/MariaDB

- 引擎、主机、端口、用户名、密码和默认数据库；
- TCP 直连；
- 复用已有 SSH 连接的 SSH Tunnel；
- Navicat `ntunnel_mysql.php` HTTP Tunnel，可配置 HTTP Basic Auth 与 HTTPS 证书校验；
- TCP/SSH Tunnel 可启用数据库 SSL/TLS。

#### Redis

- Standalone 主机、端口、可选 ACL 用户名/密码和默认逻辑库；
- TCP 或复用已有 SSH 连接的 SSH Tunnel；
- 可启用 TLS、服务器名称、CA、客户端证书、客户端私钥和口令；
- 键名分隔符；
- 只读模式，开启后可信执行端拒绝写命令。

密码、私钥和证书使用 AES-256-GCM 加密保存，不返回资源池列表或普通 Renderer。编辑已有连接时，敏感字段留空表示保持原值。历史内嵌私钥连接继续可用；编辑时可以保持原状，也可以选择托管密钥完成迁移。

### 9.3 SSH 密钥

个人空间所有者和组织管理员可以从左侧“SSH 密钥”进入管理页：

- 导入 OpenSSH、PEM、PKCS#1 或 PKCS#8 私钥，可填写私钥口令；
- 生成 ED25519、RSA 3072 或 RSA 4096 密钥对；
- 查看算法、公钥指纹、维护人和引用连接数；
- 复制或导出公钥；私钥导出前必须再次确认风险；
- 重命名密钥；仍被连接引用的密钥不能删除。

SSH 连接只保存密钥 ID，私钥与口令由当前工作空间单独加密保管。同一密钥可以供多条连接使用。个人资源复制到组织时，关联密钥按指纹复用或创建组织副本，私钥使用目标实例主密钥重新加密。

普通组织成员看不到该菜单，调用密钥管理或导出接口会被拒绝；成员仍可使用已授权的 SSH 连接。桌面 App 本机直连时，组织密钥通过绑定设备和连接的一次性加密信封进入 App 主进程完成认证，不进入页面 Renderer，也不会显示在连接列表。

### 9.4 连接组与环境关联

连接组可按 SSH、数据库、Redis 分别建立任意层级，只用于整理连接，不影响环境授权。

批量关联环境：

1. 勾选一个或多个连接。
2. 点击“关联环境”。
3. 选择一个或多个目标环境并确认。

重要：批量关联会让所有选中连接使用同一组环境，并替换各连接原有的环境集合。关联弹窗只让用户选择新的目标集合，不提供旧/新差异预览；操作前应从资源池记录仍需保留的原关联。点击“移回待分配”会清空选中连接的全部环境关联。

删除连接会同时删除其加密凭据；删除环境只解除关联，不删除连接。

## 10. 导入、同步、复制与巡检

### 10.1 从 SecureCRT 或 Navicat 文件导入

进入“连接资源池 → 导入”：

1. 选择 SecureCRT 或 Navicat。
2. SecureCRT 支持 INI、Session 和配置目录 ZIP；如配置使用 Password V2，可填写配置口令。
3. Navicat 支持 15–17 的 NCX、XML 和 ZIP，并解析 TCP、SSH Tunnel、SSL/TLS、HTTP Tunnel 与 V2 密码。
4. 上传后先进入预览，分别查看 SSH 和数据库连接、新增项、已存在冲突和不可导入项。
5. 对冲突选择复用已有 SSH、保留为副本、覆盖已有连接或跳过。
6. 全部冲突处理完成后确认导入。

预览不会返回明文凭据。无法解密的 SecureCRT 密码仍可保留连接信息，并标记需要补录凭据。没有环境映射的新连接进入待分配队列。

### 10.2 脚本资源同步

进入“连接资源池 → 连接工具 → 连接同步”：

1. 新建同步源并选择“脚本同步”。
2. 填写 `/bin/sh` 脚本；标准输出必须是 `schemaVersion: 1` JSON，详细格式见[脚本资源同步](SCRIPT-SYNC.md)。
3. 选择同名资源策略：“直接忽略”保留 Viron 当前值，“无条件覆盖”使用脚本结果更新所有明确匹配项。
4. 可配置 Cron，也可点击“立即同步”。脚本通过独立 Runner 执行，当前个人空间或组织空间决定资源写入位置。
5. 同步校验和写入在单一事务中完成；任一资源、凭据或依赖无效时整批回滚。
6. 在“同步报告”中 review 每轮新增、覆盖、忽略和空间额外资源。报告不保存脚本原始输出或任何明文凭据。

脚本未返回但空间已有的资源不会删除或禁用。SSH、数据库和 Redis 连接在资源池的“来源”列显示对应同步源；其他资源只按名称及所属层级匹配，不绑定来源。

### 10.3 SecureCRT 连接同步

进入“连接资源池 → 连接工具 → 连接同步”：

1. 新建同步源，填写同步主机、SSH 端口、用户名和密码/私钥。
2. 每行填写一个远端 SecureCRT 会话目录。
3. 如有配置口令，填写 SecureCRT 配置口令。
4. 可配置 Cron 表达式启用定时同步，也可手工点击“立即同步”。
5. 首次同步后处理新增、更新和跨来源冲突。
6. 使用“目录映射”把来源路径前缀绑定到环境，使以后新增连接自动关联。

Viron 使用 SSH/SFTP 直接读取远端配置，不执行原同步脚本，也不运行 `sshpass`、`scp` 或 `rsync`。删除同步源只解除来源关系，已导入连接保留并转为手工维护。来源删除的连接只标记“来源已删除”，不会自动删除 Viron 连接。

### 10.4 个人资源复制到组织

只有处于组织空间的组织管理员可以使用“连接工具 → 连接复制”。来源固定为当前管理员自己的个人空间，目标固定为当前组织。

1. 选择个人环境组、环境、独立 SSH/数据库连接、Web 入口、Web 账号和日志配置。
2. 选择环境时默认带出其中的连接、Web 账号和日志，可手工取消不应进入组织的子资源。
3. 生成复制预览；系统自动补齐跳板机、数据库 SSH Tunnel 和日志 SSH 依赖。
4. 对组织中可能已存在的资源选择“新建独立副本”或“复用”。复制不会覆盖组织资源。
5. 可选复制完成后直接授权给项目或普通成员；默认只由组织管理员管理。
6. 确认提交。任何资源、依赖、凭据、复用或授权失败都会整批回滚。

同一连接关联多个环境时只复制一次并恢复全部关系。连接引用的托管 SSH 密钥按公钥指纹复用或复制到组织空间；其他凭据同样只在服务端内存中解密后用新随机 IV 重新加密。浏览器 Profile、Cookie、终端历史、SQL 历史、收藏和后台任务不复制。副本与个人原件后续互不联动。

当前复制目录覆盖 SSH 和数据库连接；Redis 可以在资源池中单独复制，但不在该组织批量复制向导的目录中。

### 10.5 连接巡检

进入“连接工具 → 连接巡检”：

1. 按 SSH、数据库或 Redis 筛选并多选，单批最多 500 个连接。
2. 开始巡检后最多 5 路并发执行。
3. SSH 执行真实认证，数据库执行 `SELECT 1`，Redis 完成连接、TLS/SSH Tunnel、AUTH 后执行 `PING`。
4. 页面展示成功/失败、耗时和错误摘要；结果回写资源池的“上次巡检”。

普通 Web 从中心服务网络执行；桌面 App 本机模式从当前电脑执行。巡检只验证连接，不执行目标数据写入。

## 11. SSH 工作台

### 11.1 打开终端

1. 从全局“SSH 工作台”，或“环境详情 → SSH”进入。
2. 左侧搜索连接名称、主机或标签。
3. 双击连接、按 `Enter` 或使用连接操作按钮建立终端。
4. 每个页签对应独立 SSH Shell；同一连接可以打开多个会话。
5. 主动关闭页签立即释放远端 Shell。异常断开时可点击重连。

支持密码、私钥/口令、keyboard-interactive、单级跳板机、UTF-8、256 色、真彩色、KeepAlive 和窗口 Resize。启用登录脚本时，交互式 Shell 建立后自动执行。

普通 Web 的目标连接从中心服务发起；桌面 App 本机模式从当前电脑发起。本机失败不会回退到中心服务。

### 11.2 分屏、布局和终端操作

- 单窗口、左右分屏、上下分屏和四宫格；
- 把终端页签拖到不同分屏区域；
- 拖动分隔条调整比例；
- 调整终端字体大小；
- 清屏、重连和沉浸；
- 环境级保存页签引用和布局，不保存正在运行的命令。

最多同时保留 20 个 SSH 会话。默认连续 30 分钟无实际输入或输出后断开，具体值由实例配置决定。短暂 Renderer 分离或页面切换时，执行端保留会话和最多 512 KiB 输出缓冲，可重新附着。

### 11.3 复制、粘贴、历史与收藏

- 普通 Web 和桌面 App 都会在文本选择完成后自动复制。桌面 App 使用系统剪贴板，并支持在已连接终端中右键直接粘贴；普通 Web 不提供右键粘贴，继续使用 xterm 的 `Ctrl/Cmd+V`。
- 最近 50 条命令按 Viron 用户和 SSH 连接保存在当前浏览器站点或桌面客户端本地。
- 明显包含密码、令牌或密钥赋值的命令不保存，连续重复命令不重复追加。
- 输入时出现历史建议，前缀匹配优先；方向键或鼠标选择，`Enter`/`Tab` 只回填、不执行。
- 历史面板可删除本地记录、开关输入辅助或收藏命令。
- 收藏保存在服务端，不随浏览器缓存清理丢失；双击或按 `Enter` 回填，同样不会自动执行。

### 11.4 ZMODEM 文件传输

- 在远端执行 `rz`，终端出现本地文件选择器，可多选上传。
- 在远端执行 `sz <文件>`，浏览器或 App 接收并保存文件。
- 传输期间终端以原始字节处理，不经过 UTF-8 文本转换。

远端主机需要安装并允许使用兼容的 `rz`/`sz` 工具。

## 12. SFTP 文件管理与跨主机传输

SFTP 集成在 SSH 工作台右侧抽屉中，不设独立主导航。

### 12.1 双栏文件管理

1. 点击 SSH 工具栏的“SFTP”。每次打开时，左栏会一次性沿用最近操作的 SSH 会话和已识别的当前绝对路径；路径不可访问时回退根目录。打开后终端继续执行 `cd` 不会强制改变 SFTP 目录。
2. 左右栏分别选择 SSH 主机；从环境进入时优先推荐当前环境连接，也可选当前工作空间内其他有权连接。手工切换主机会从根目录开始。
3. 双击目录进入，使用面包屑返回；双击路径区域可手工输入路径。
4. 单击只选择一项；macOS 按住 `Command`、Windows/Linux 按住 `Ctrl` 可以增减独立选中项，按住 `Shift` 可以从锚点连续选择当前可见范围。
5. 每栏可以筛选文件、显示隐藏文件、刷新；“操作”菜单提供上传、下载、新建目录、重命名、删除和 `chmod`。

左右栏独立保存主机、目录和选中项。关闭抽屉不关闭 SSH 终端，也不中断后台传输。

### 12.2 主机间复制

1. 在来源栏选择一个或多个文件、目录。
2. 点击中间“传到右侧”或“传到左侧”，也可以把选中项拖到另一栏；放在栏内空白位置时使用当前目录，放在目录行时进入该目录。
3. Viron 在开始前递归预检整个批次。没有冲突时直接创建后台传输，不显示确认框。
4. 同名目录直接合并；遇到同名文件或文件/目录类型不一致时才显示冲突框。逐项选择“跳过”或“覆盖”，也可以取消整个尚未开始的批次；启用“应用全部”会把当前选择用于本批次剩余冲突。
5. 开始后查看文件数、字节、速度、进度、跳过和失败原因。

“跳过”只保留当前同名文件并继续处理其他内容；“覆盖”替换当前同名文件。类型不一致时，“覆盖”会完整删除并替换目标文件或目录，“跳过”则完整保留目标。符号链接、根目录、同一路径和把目录复制到自身子目录会被拒绝。

Finder 或资源管理器中的多个文件、目录可以直接拖入任一远程栏，并使用相同的预检和冲突决策。macOS 与 Windows 桌面 App 可以把 SFTP 选中项拖回 Finder 或资源管理器；远程内容会先准备到系统临时目录，准备期间应保持拖动。普通 Web 完整支持拖入上传；受浏览器原生拖出能力限制，拖出下载只保证单个文件可用，批量文件或目录应使用桌面 App。

每个执行实例最多同时运行 3 个传输任务，支持取消和重试失败/取消任务，最多保留最近 100 个已结束任务。当前不支持断点续传；服务或 App 重启会中断活动任务。

## 13. 环境日志

### 13.1 新建日志配置

1. 进入“环境详情 → 日志”。
2. 点击配置列表“+”。
3. 选择当前环境关联且有权使用的 SSH 连接。
4. 输入 1–10 个绝对文件路径，例如 `/var/log/my-app/application.log`。
5. 输入显示名称；留空时使用文件名。

路径不能包含通配符、Shell 命令、额外参数、NUL 或换行。Viron 固定执行受控的 `tail -n <行数> -F -- <路径...>`。连接启用 SSH 登录脚本时，系统先在交互式 Shell 执行脚本，再从脚本进入的环境启动 `tail`。

### 13.2 查看和过滤

1. 单击配置选中，双击或按 `Enter` 开始查看。
2. 启动前或查看时设置 1–5000 行上限；默认 200。远端对每个文件分别读取最近指定行数，合并到达浏览器后，当前配置的屏幕输出再只保留最近指定行数。
3. 最多同时保持 3 路日志流；切换配置或页面不会停止其他后台流。
4. 可折叠配置列表并拖动宽度，独立停止、重连、清屏和开关自动滚动。当前选中日志流处于活动状态时，可按 `Ctrl+C` 快速停止并保留当前屏幕内容；焦点在输入控件中或已经选择文本时不会拦截复制。停止或连接异常后，可按 `Enter` 或点击“重新连接”恢复跟踪；输入控件、按钮和配置弹窗中的 `Enter` 保持原用途。
5. 输入固定字符串关键字，可选择区分大小写。
6. 选择上文、下文或上下文，并设置 0–200 行范围；上下文按当前合并输出窗口的到达顺序计算，不跨越已经被窗口淘汰的内容。
7. 可关闭语义高亮；默认高亮 critical/fatal、error、warning、info、debug、trace、时间戳、IP、请求标识、耗时和 HTTP 状态。
8. 下载“当前屏幕”；启用过滤时下载过滤结果，否则下载当前窗口。

多文件按远端 `tail` 到达顺序展示，并保留 `tail` 输出的文件来源标题，不按日志时间重新排序。断线期间不承诺无损补读；重新连接会按当时设置的行数重新取得各文件尾部。当前不提供历史日志保存、时间范围过滤或跨文件时间排序，日志正文也不写入元数据库或审计详情。

## 14. 数据库工作台

Viron 0.1.6 支持 MySQL 和 MariaDB。普通 Web 由中心服务连接数据库；桌面 App 本机模式从当前电脑连接，并支持 TCP、SSL/TLS、SSH Tunnel 和 Navicat HTTP Tunnel。

### 14.1 连接与统一导航树

1. 从全局“数据库工作台”或“环境详情 → 数据库”进入。
2. 左侧统一导航树包含连接组、连接、数据库、对象分类和具体对象。
3. 单击连接只选中；双击或按 `Enter` 才建立连接。
4. 主动“关闭连接”会清空该连接的数据库树、对象选择和全部页签；空闲回收或异常断开保留编辑内容，并显示重新连接入口。
5. 可隐藏导航窗格、拖动宽度；右侧信息窗格独立显示属性和 DDL/预览，也可隐藏或调整宽度。

连接操作包括新建、编辑、复制、删除、开关连接、刷新、星标、颜色、连接组、共享、配置文件、新建数据库、新建查询、命令列和运行 SQL 文件。打开主要连接或任何配置文件时，需先关闭连接才能切换、编辑、复制、删除或更改活动配置。

收藏区位于导航树顶部：

- 收藏数据库后可自动连接、展开并定位数据库；
- 收藏数据表后可自动连接、定位并直接打开数据页；
- 可以只显示已标星连接或包含收藏对象的连接。

### 14.2 数据库对象

对象树按“表、视图、函数、事件、查询、备份”展示。存储过程和函数统一归入“函数”；触发器不作为顶级分类，但可由表设计、DDL、备份恢复和迁移处理。

常用操作：

- 双击或按 `Enter` 打开对象；
- 查看常规属性、`SHOW CREATE` 和完整 DDL；
- 新建、设计、删除、复制、粘贴和重命名表、视图、函数/存储过程和事件；
- 对函数/存储过程生成运行 SQL；
- 对表执行清空、截断、复制结构/数据、导入、导出、数据生成和数据字典；
- 对表执行分析、检查、优化、修复和行数统计；
- 设置表、视图、函数/存储过程权限；
- 建立对象组，把对象加入组或从组排除；
- 在组织空间共享连接或其数据库对象对应的连接资源；
- 以详细列表或 ER 图表查看对象；
- 在数据库中跨分类查找对象。

右键数据库、分类或对象时先选中目标。菜单根据连接状态、对象选择、任务状态和权限启用或置灰相应动作。

### 14.3 新建和设计表

新建表进入可视化设计器，包含：

- 字段；
- 索引；
- 外键；
- 触发器；
- 检查约束；
- 表选项；
- 注释；
- SQL 预览。

设计器提供添加、插入、删除、专注和保存。保存前校验名称、字段引用、生成列、自动递增、索引、约束和触发器配置；首次保存询问表名，成功后刷新对象树并打开新表数据页。

已有表也进入同一设计器，读取字段、索引、外键、触发器、检查、高级选项和注释，保存时生成并执行受控结构差异。读取期间会提示数据库或网络慢响应，完整结构未就绪前不能保存；等待超过 45 秒后停止转圈并显示可重试错误。视图、函数、存储过程和事件继续使用完整 DDL 编辑。

### 14.4 SQL 查询与命令列

点击“新建查询”打开 Monaco 多页签 SQL 编辑器。支持：

- MySQL 高亮、格式化和上下文补全；
- 内置和用户自建代码段，可搜索、预览、插入、编辑和删除；
- 数据库、表、视图、字段、函数、存储过程和别名字段补全；
- 执行选择内容、当前语句或全部脚本；
- “遇到错误时继续”，逐句保留失败结果并继续后续语句；
- `EXPLAIN` 当前语句；
- 取消正在执行的查询；
- 结果上下/左右布局和查询专注模式；
- 显示执行时间、影响行数、警告与错误；
- SQL 收藏、查询列表、执行历史和重新打开；
- 最多同时执行 10 个查询。

“命令列界面”提供数据库命令式交互，但仍通过 Viron 的受控数据库执行路径，不是在本机启动外部 `mysql` 客户端。

### 14.5 表数据

打开表进入 Tabulator 数据网格：

- 服务端分页、排序、筛选；
- 调整列宽和顺序、显隐列、复制单元格或行；
- 网格/表单视图；
- 存在主键或唯一键时直接编辑，批量新增、修改、删除；
- 提交或回滚暂存修改；
- 没有唯一键时禁止直接编辑并说明原因；
- CSV、XLSX 导入；
- CSV、XLSX、SQL 导出；
- 大导出进入后台任务；
- 数据加载期间可以停止，停止后的迟到响应不会覆盖当前结果。

表配置文件按用户、连接、数据库和表保存在 Viron 元数据库，不写入业务库。它可以保存筛选、排序、列顺序、列宽、隐藏列、分页大小和网格/表单模式，并支持加载、保存、另存为、重命名和删除。

### 14.6 数据库用户与对象权限

顶部“用户”工作区支持：

- 查看数据库用户及认证插件、密码过期策略、资源限制和 SSL 条件；
- 新建、编辑和删除数据库用户；
- 修改认证插件时同时设置密码；
- 打开权限管理员维护授权；
- 从表、视图、函数/存储过程右键菜单直接进入对象权限设置。

实际可执行范围取决于当前数据库账号对 `mysql` 系统表和 `GRANT` 等语句的权限。

### 14.7 查询、备份与本机文件

“查询”节点展示当前数据库的 SQL 收藏，支持新建、设计、复制、删除、重命名和导出。桌面 App 还可以使用外部编辑器打开、从外部文件打开，并在 Finder 中显示对应查询文件。

“备份”节点和“工具 → 数据库任务”展示任务状态与进度。备份范围是当前连接中选定的数据库，不是整个 Viron 实例：

- 新建完整或仅结构 SQL 备份；
- 备份表、数据、视图、存储过程、函数、触发器和事件；
- 从 SQL 文件恢复；
- 取消运行中的任务；
- 删除、复制、重命名、还原和提取 SQL；
- 桌面 App 可在 Finder 中定位本机备份。

服务端备份保存到 `DATA_DIR/backups/database`；桌面本机任务保存在 App 用户数据目录。HTTP Tunnel 是请求级连接，严格长事务和大批量恢复优先使用 TCP 或 SSH Tunnel。

### 14.8 数据传输、数据同步与结构同步

这些功能从顶部“工具”菜单进入，源和目标均为当前用户有权使用的 Viron 数据库连接。

#### 数据传输

- 选择源/目标连接、数据库和表；
- 仅结构、仅数据或结构+数据；
- 可包含视图、存储过程、函数、触发器和事件；
- 可选择覆盖同名对象；
- 分批写入并显示对象、行数、进度和失败详情；
- 是一次性传输，不提供定时或双向持续同步。

数据传输按对象和批次写入，不保证整次任务原子回滚；失败后应根据任务明细检查目标数据库，再决定清理或重试。

#### 数据同步

- 先按相同主键比较源表和目标表；
- 分别选择是否插入目标缺失记录、更新不同记录、删除目标多余记录；
- 每张表使用独立事务；
- 没有兼容主键或列的表不能按该方式自动同步。

每张表独立提交意味着后续表失败时，之前成功表的修改仍然保留。

#### 结构同步

- 比较表列、主键、索引、外键、检查约束、字符集/表选项、视图、函数/存储过程、触发器和事件；
- 选择要应用的差异；
- 执行前预览目标 SQL；
- 删除、替换和删除目标多余对象必须显式选择；
- 分区、表达式索引等无法安全生成差异 SQL 的对象标记为“需处理”，不会自动执行。

结构同步可能执行破坏性 DDL。应用前应审阅 SQL、显式确认删除/替换项，并使用目标数据库自身能力完成可恢复备份。

## 15. Redis 工作台

### 15.1 连接和逻辑库

1. 从全局“Redis 工作台”或“环境详情 → Redis”进入。
2. 左侧按连接组查看连接，搜索并选择连接。
3. 工作区显示连接地址、TCP/SSH Tunnel、TLS 和只读状态。
4. 切换逻辑库后重新读取键空间摘要和键列表。

当前只支持 Redis Standalone。Sentinel、Cluster、Valkey 完整兼容矩阵和拓扑修改不属于 0.1.6 已交付范围。

### 15.2 键空间浏览

- 只使用安全的 `SCAN`，不调用 `KEYS`；
- 可填写 glob，例如 `user:*`；
- 可按 string、hash、list、set、zset、stream 筛选；
- `COUNT` 提示值可选 100、200、500、1000；
- 自动续传游标，直到扫描完成或保留 10,000 个键；
- 可按连接配置的分隔符使用列表或一级分组树；
- 显示已载入数、当前库键数、设置过期数、类型、TTL 和键名大小；
- 游标扫描不是一致性快照，不显示虚假完成百分比。

### 15.3 键和值维护

选择键后查看 TTL、键名大小、内存占用、逻辑库和值预览。键和值保留原始 Base64，可按 UTF-8、JSON、Hex 或 Base64 查看与输入，非 UTF-8 数据不会被错误转换。

支持：

- 新建 String、Hash、List、Set、Sorted Set、Stream；
- String `GET/SET KEEPTTL`；
- Hash `HSET/HDEL`；
- List `LPUSH/RPUSH/LPOP/RPOP`，最多预览 500 项；
- Set `SADD/SREM`；
- Sorted Set `ZADD/ZREM`；
- Stream `XADD/XDEL`，最多预览 500 条；
- `COPY`、`RENAME`、`UNLINK`；
- 设置相对 TTL 或改为 `PERSIST` 永不过期。

只读连接禁用结构化写入，可信执行端也会再次拒绝写命令。Redis 使用真实的最后写入生效语义，不承诺通用版本 CAS。

### 15.4 受控命令

命令工作台使用 Monaco，支持高亮、基础补全、选中/全文执行、最近结果和本地收藏。多行按顺序执行，最多 20 行，不保证原子性。

安全策略会拒绝未知、高危、脚本、管理、订阅和无界命令，包括 `KEYS`、`FLUSH*`、`CONFIG`、`ACL`、`EVAL`、`SCRIPT`、`DEBUG` 和 `MONITOR`。集合读取、Slow Log、多键操作和删除还有独立数量上限；拒绝尝试同样进入审计。

命令工作台当前只允许下列白名单，未列出的命令默认拒绝：

- 读取：`DBSIZE`、`EXISTS`、`GET`、`HEXISTS`、`HGET`、`HLEN`、`HMGET`、`HSCAN`、`INFO`、`LLEN`、`LPOS`、`LRANGE`、`MGET`、`PING`、`PTTL`、`SCAN`、`SCARD`、`SISMEMBER`、`SMISMEMBER`、`SSCAN`、`STRLEN`、`TIME`、`TTL`、`TYPE`、`XLEN`、`XRANGE`、`XREVRANGE`、`ZCARD`、`ZMSCORE`、`ZRANGE`、`ZRANGEBYSCORE`、`ZRANK`、`ZREVRANGE`、`ZREVRANGEBYSCORE`、`ZREVRANK`、`ZSCAN`、`ZSCORE`；
- 受限子命令：`MEMORY USAGE/STATS/DOCTOR/MALLOC-STATS`、`OBJECT ENCODING/FREQ/IDLETIME/REFCOUNT`、`SLOWLOG GET/LEN`；
- 写入：`COPY`、`DEL`、`EXPIRE`、`EXPIREAT`、`HDEL`、`HINCRBY`、`HINCRBYFLOAT`、`HSET`、`LINSERT`、`LPOP`、`LPUSH`、`LREM`、`LSET`、`MSET`、`PERSIST`、`PEXPIRE`、`PEXPIREAT`、`RENAME`、`RENAMENX`、`RPOP`、`RPUSH`、`SADD`、`SET`、`SREM`、`UNLINK`、`XADD`、`XDEL`、`ZADD`、`ZINCRBY`、`ZREM`。

只读连接只允许上述读取命令。范围限制包括：`LRANGE`/按索引的 `ZRANGE`/`ZREVRANGE` 最多 1000 项；`XRANGE`/`XREVRANGE` 必须指定 1–1000 的 `COUNT`；`MGET`/`EXISTS`/`DEL`/`UNLINK` 最多 100 个键；`HMGET`/`SMISMEMBER`/`ZMSCORE` 最多 100 个成员；`MSET` 最多 100 对；各类 `SCAN COUNT` 为 1–1000；按分数的 Sorted Set 范围查询必须带 `LIMIT` 且最多 1000 项；`LPOP`/`RPOP` 最多 1000 项；`SLOWLOG GET` 为 1–1000 条。

单命令最多 256 个参数，文本参数最多 256 KiB，Base64 参数最多 512 KiB，单响应上限 2 MiB。默认连接和命令超时为 10 秒，连接设置允许 1–120 秒。

### 15.5 运行诊断

“运行诊断”提供当前连接节点的一次采样：

- Redis 版本、模式和运行时间；
- 内存；
- 已连接客户端；
- 当前逻辑库键数与过期数；
- 分类展开的 `INFO`；
- 最近 32 条 `SLOWLOG GET`，最大允许读取 1000 条。

Slow Log 是 Redis 服务端执行耗时，不是端到端网络延迟。诊断只代表当前 Standalone 节点和本次采样，不是持续实时监控。

## 16. 操作审计、终端录像与 SQL 历史

进入“操作审计”：

### 16.1 操作事件

默认保留并查看近 30 天记录，展示操作者、摘要、动作编码、资源类型、来源 IP、操作来源、时间和最多三项非敏感详情摘要。操作来源分为“人工操作”“MCP 操作”“系统操作”和“历史未知”：新记录由可信执行链路直接写入来源，无法可靠判断来源的旧记录不会误标成人工。页面可按用户、来源和关键字组合过滤；关键字匹配摘要、动作编码和资源类型，不搜索完整详情。结果分批加载，但近 30 天的可查询总量不受固定条数限制。审计覆盖账号、组织、授权、环境、连接、导入同步、凭据显示/复制、SSH/SFTP、日志、数据库、Redis、迁移等敏感操作。

Redis 审计记录命令名、参数数量、执行位置、耗时和响应字节，不保存完整值或响应；日志正文不进入审计详情。

### 16.2 终端录像

- 与操作事件共用近 30 天保留期、用户过滤和关键字过滤；关键字匹配连接名称、主机和状态等可见描述。
- SSH 会话生成 asciinema 格式录像；
- 普通 Web 的录像来自服务端；桌面 App 同时展示本机录像；
- 可以下载录像；
- 非录制中的录像可以手工删除。

### 16.3 SQL 历史

- 与操作事件共用近 30 天保留期、用户过滤和关键字过滤；关键字匹配连接名称、数据库和状态，不搜索 SQL 正文。
查看连接、数据库、SQL、状态、执行时间、行数和错误。数据库工作台的“工具 → 执行历史”还可以按上下文继续使用历史记录。

操作事件、终端录像与 SQL 历史默认统一保留 30 天，平台管理员可在“设置 → 运行策略”调整为 1–3650 天；同一页面还可以把宿主机后台采集频率设为 10–3600 秒。保存后两项策略都对当前进程立即生效并持久化。`AUDIT_RETENTION_DAYS` 和 `VIRON_MONITOR_PULL_INTERVAL_SECONDS` 只提供实例首次配置或尚无页面保存值时的默认值；超过期限的审计数据由服务启动和周期清理删除。

## 17. 客户端下载与更新

### 17.1 Web 手工下载

登录浏览器客户端后点击左侧“下载客户端”：

1. 页面优先说明桌面客户端的 Web 入口优势：目标页面由本机 Chromium 原生加载，通常比普通 Web 的远程画面流响应更快，并可通过右键打开 Chromium DevTools 检查目标元素。
2. 普通 Web 的目标页面运行在服务端 Chromium 中，通过网络持续传输画面；外层浏览器开发者工具只能检查 Viron 页面外壳，当前不能检查目标网站 DOM。
3. 桌面 App 提供 Viron Agent 本机模型配置、流式聊天、SSH/数据库多步只读诊断、SSH 写命令和数据库写 SQL 确认执行、三档审批策略和对话/工作台双执行位置；普通 Web 不支持。
4. 页面在浏览器本地检测 macOS/Windows 与可用的 CPU 架构信息；找到精确匹配或 Universal 安装包时，在原有列表位置标记“推荐此版本”，不改变安装包顺序。
5. Safari 等无法可靠提供 CPU 架构的浏览器只提示已识别的操作系统，并要求用户手工确认 Apple Silicon、Intel/AMD 或 ARM 架构，不通过其他指纹信息强行推断。
6. 页面列出服务端 `DATA_DIR/installers` 根目录中版本与当前服务一致、平台和架构可识别的非空 macOS `.dmg` 和 Windows `.exe`；该清单也是 App 自动更新的唯一安装包来源。
7. 根据操作系统、CPU 架构、版本、文件名和大小选择；同一平台和架构存在多项时只展示最近更新的一项。
8. 下载前确认服务来源、系统和架构。

其他版本、未知架构、空文件、嵌套目录和其他扩展名不会公开。目录内容变化后刷新页面即可生效，不需要重启服务。

### 17.2 登录前更新检查与安装

管理员把当前版本安装包放入 `DATA_DIR/installers/` 后，App 启动或切换 Endpoint 会查询 `/api/v1/version`。Web 页面可见的 macOS `arm64/x64`、Windows `x86/x64/arm64` 包都会进入自动更新；精确架构不存在时可使用同平台 Universal 包。服务端版本更高且当前平台存在匹配包时提示用户选择下载并安装或稍后处理；发现更高版本但缺少匹配包时明确提示不可用，不再显示“当前已经是最新版本”。这是自动检查、用户确认安装，不是无人值守强制更新。

确认更新后，App 会下载并校验安装包。macOS 在窗口仍打开时完成系统授权（仅当需要写入受保护目录时），然后替换当前正在运行的那份 App；从 DMG 直接打开时会安装到 `/Applications/Viron.app`。Windows 覆盖当前安装目录。下载完成后不要立刻再次点击 Dock 或快捷方式；若更新尚未完成，再次打开会提示等待并自动启动新版本。macOS 自签名内部包首次打开可能被 Gatekeeper 拦截，需要在 Finder 右键“打开”或在“系统设置 → 隐私与安全性”批准；Windows 未签名包可能触发 SmartScreen。安装前应确认安装包确实来自受信任的 Viron 服务。

## 18. 平台管理员部署与维护

本节给出 0.1.6 的最小可执行操作。更完整的构建、开发和验证命令见根目录 [README](../README.md)。

### 18.1 Docker Compose 部署

要求 Docker 24+ 和 Docker Compose v2。

```bash
cp .env.example .env
```

至少修改 `ADMIN_PASSWORD`。常用配置：

| 配置 | 作用 | 默认/建议 |
| --- | --- | --- |
| `HOST` | 宿主机绑定地址 | `127.0.0.1` 仅本机；对外服务使用 `0.0.0.0` |
| `PORT` | 宿主机和容器服务端口 | `8080` |
| `DATA_DIR` | 宿主机数据目录 | `./data` |
| `DATABASE_DRIVER` | Viron 元数据库 | `sqlite`，也可为 `mysql` |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | 首次启动管理员 | 只在尚无管理员时生效 |
| `ALLOW_WEAK_PASSWORDS` | 是否允许弱密码 | 生产保持 `false` |
| `SESSION_TTL_HOURS` | 单次登录 Session 固定有效期 | `45` 天（`1080` 小时） |
| `COOKIE_SECURE` | Cookie 是否只经 HTTPS | 直接 HTTP 为 `false`；HTTPS 反代后为 `true` |
| `CONNECTION_IDLE_MINUTES` | 无数据活动断开时间 | `30` |
| `USER_CONNECTION_LIMIT` | 单用户活动连接上限 | `30` |
| `AUDIT_RETENTION_DAYS` | 录像与 SQL 历史保留 | `30` |
| `VIRON_MONITOR_PULL_INTERVAL_SECONDS` | 尚无页面策略时的宿主机后台采集频率 | `60` 秒 |
| `WEB_VIEW_TOTAL_LIMIT` | 服务实例 Chromium 总量 | `8` |

启动其中一个版本：

```bash
# Lite：仅供桌面客户端，服务端仍可转发 SSH/SFTP/日志/数据库/Redis
docker compose -f docker-compose.lite.yml up -d --build

# Full：同时提供浏览器客户端和桌面客户端
docker compose -f docker-compose.full.yml up -d --build
```

检查服务：

```bash
docker compose -f docker-compose.full.yml ps
curl http://127.0.0.1:8080/healthz
curl http://127.0.0.1:8080/readyz
curl http://127.0.0.1:8080/api/v1/version
```

Lite 部署把命令中的 Compose 文件改为 `docker-compose.lite.yml`。两个文件都会启动非 root `viron` 主服务和不发布端口、没有 Viron 数据挂载的 `script-runner`；主服务健康检查会等待 Runner 的 Unix Socket 就绪。成功时 `/healthz` 返回 HTTP 200、`status: "ok"`、`product: "viron"` 和 `productVersion: "0.1.6"`；版本接口也应返回服务端 `0.1.6`、API 协议范围和各平台安装包状态。只有端口可访问但版本或产品不符，不能视为 0.1.6 验证通过。`/healthz` 只表示进程存活与产品身份，不接触元数据库；容器 HEALTHCHECK 打的是 `/readyz`，它会真实探测元数据库，正常返回 HTTP 200 和 `status: "ok"`，元数据库不可用时返回 HTTP 503 和 `error: "DATABASE_UNAVAILABLE"`，容器随之判为 unhealthy。

### 18.2 使用 MySQL/MariaDB 作为元数据库

先创建空数据库和具备建表、索引、读写权限的账号，再配置：

```dotenv
DATABASE_DRIVER=mysql
DATABASE_HOST=127.0.0.1
DATABASE_PORT=3306
DATABASE_NAME=viron
DATABASE_USERNAME=viron
DATABASE_PASSWORD=replace-with-strong-password
DATABASE_POOL_SIZE=10
```

应用会幂等创建当前版本表结构。这里的 `127.0.0.1`、`localhost` 和 `::1` 是 Viron 容器版的特殊配置语义：服务启动时会把它们改写为 `host.docker.internal`，两个 Compose 文件同时配置 `host-gateway`；并非标准容器回环地址会天然指向宿主机。远程地址、域名和 Compose 服务名保持原样。

已有 SQLite 源码实例迁移前必须停止服务、保留 `DATA_DIR/envman.db`，配置好 MySQL 后执行：

```bash
./scripts/dev-service.sh stop
npm run database:migrate:mysql
./scripts/dev-service.sh start
```

容器实例先修改 `.env` 中的 MySQL 配置，再按部署版本执行：

```bash
# Full；Lite 把两处 Compose 文件替换为 docker-compose.lite.yml
docker compose -f docker-compose.full.yml stop viron
docker compose -f docker-compose.full.yml run --rm viron \
  node dist/server/cli/migrate-sqlite-to-mysql.js
docker compose -f docker-compose.full.yml up -d viron
```

目标 MySQL/MariaDB 中的 Viron 平台表必须为空；这里不是指用户通过 Viron 管理的业务数据库。迁移在单一事务中复制并校验行数与外键；成功后 SQLite 文件作为人工回退副本保留，运行中的 MySQL 模式不再写它。

### 18.3 主密钥和数据目录

首次启动自动生成 `DATA_DIR/master-key`，权限为 `0600`。已有加密数据但主密钥缺失、不可读或不匹配时，Viron 拒绝启动。外部托管可使用 `VIRON_MASTER_KEY` 或 `VIRON_MASTER_KEY_FILE`。

主要持久化内容：

```text
DATA_DIR/envman.db
DATA_DIR/master-key
DATA_DIR/recordings/
DATA_DIR/web-profiles/
DATA_DIR/web-downloads/
DATA_DIR/backups/database/
DATA_DIR/exports/
DATA_DIR/uploads/
DATA_DIR/installers/
DATA_DIR/restore-pending/
DATA_DIR/migration-history/
```

不得只备份数据库而丢失主密钥。基础设施备份应覆盖完整 `DATA_DIR`；MySQL/MariaDB 元数据库还应使用数据库服务自己的备份和时间点恢复。直接复制目录前应停止 Viron，或使用能够保证数据库文件与同批目录一致性的文件系统/存储快照；不要在线逐文件复制 SQLite 与正在写入的录像、备份目录后把它当作一致性恢复点。

旧 `ENVMAN_*` 环境变量不兼容，检测到后启动失败并提示对应 `VIRON_*` 名称。Cookie、浏览器存储键和 `envman.db` 文件名属于持久化兼容标识，不代表仍支持旧品牌配置。

### 18.4 提供客户端安装包

在具备 Docker Buildx 的 macOS 构建机上，可以一次生成完整发布矩阵：

```bash
./scripts/package-release.sh

./scripts/package-release.sh --refresh-docker-cache 0.1.6
```

不传参数时使用 `package.json` 当前版本；传入新版本时会永久更新仓库版本、Compose 镜像标签和版本化文档。输出包括 macOS `arm64/x64`、Windows `x86/x64/arm64` 五个客户端安装包，以及 `linux/amd64`、`linux/arm64` 两个服务离线包；每个服务包都包含 Lite、Full 与 Script Runner 三个镜像。发布完成后应通过 `shasum -a 256 -c release/SHA256SUMS` 校验全部七个产物。

Docker 镜像构建按架构和目标把 BuildKit `mode=max` 缓存保存在 `.tmp/docker-build-cache/release/`。缓存目录不存在时自动执行完整构建并写入缓存；普通源码变更会复用独立的 Chromium/字体运行时层、Node 下载缓存和 Go 编译缓存。`--refresh-docker-cache` 只在本轮忽略既有层缓存并用新结果刷新持久缓存，适用于升级基础镜像或系统依赖，不应作为日常发布参数。

Compose 使用 `.tmp/docker-build-cache/compose/` 下的对应目标缓存。需要显式刷新时执行 `docker compose -f docker-compose.full.yml build --no-cache`，Lite 使用对应 Compose 文件。两个入口都支持以下可选环境变量：

```dotenv
VIRON_DOCKER_CACHE_DIR=/absolute/path/to/docker-build-cache
VIRON_DOCKER_REGISTRY_MIRROR=docker.io
VIRON_APT_MIRROR=http://mirrors.aliyun.com/debian
VIRON_APT_SECURITY_MIRROR=http://mirrors.aliyun.com/debian-security
```

默认缓存位于仓库的忽略目录，不会进入 Git 或 Docker build context，但会占用额外磁盘空间；删除该目录后下一次构建会自动重建。Node 与 Go 基础镜像默认通过 Docker 官方 `docker.io` 解析，避免依赖第三方代理；受限网络可用上述变量切换到其他兼容镜像。APT 默认使用阿里云 Debian 镜像，APT 包仍通过 Debian Release 签名校验，覆盖镜像源时必须提供完整的 Debian 与 Debian Security 根地址。

Web 手工下载与 App 登录前自动更新使用同一套发布清单。把 `.dmg` 或 `.exe` 直接放入 `DATA_DIR/installers/`，文件名使用：

```text
Viron-<version>-<platform>-<architecture>-...
```

只发布与当前服务端 `package.json` 版本一致、平台和架构可识别、位于目录根层且非空的普通文件；同一平台和架构存在多项时稳定选择最近更新的一项。源码目录默认是 `./data/installers/`，Compose 使用宿主机的 `DATA_DIR/installers/`，并通过既有数据目录挂载映射到容器内 `/data/installers/`。目录变化在下次 Web 清单或版本请求时生效，无需单独配置环境变量或重启服务。

Lite 没有 Web 下载页，但与 Full 使用相同的 `DATA_DIR/installers/` 自动更新来源。第一次安装桌面 App 时，需要由管理员通过受控文件分发、内部软件下载门户或其他可信渠道提供安装包；已有 App 连接 Lite Endpoint 后，可使用上述登录前版本检查和安装能力。Windows 包在对应真实 Windows 架构完成运行验收前只应作为测试产物分发。

### 18.5 重置平台密码

本地源码实例：

```bash
npm run admin:reset -- admin 'new-password'
```

Full 容器：

```bash
docker compose -f docker-compose.full.yml exec viron \
  node dist/server/cli/reset-admin-password.js admin 'new-password'
```

Lite 使用对应 Compose 文件。重置后该用户现有会话全部失效。初始化完成后修改 `.env` 的 `ADMIN_PASSWORD` 不会覆盖数据库中的密码，必须通过页面或 CLI 修改。

### 18.6 跨实例迁移

平台管理员进入“设置 → 数据迁移”：

1. 确认源、目标均运行经过验证的兼容版本；0.1.6 手册默认按 0.1.6 到 0.1.6 迁移。
2. 设置至少 12 个字符的迁移密码并确认。
3. 点击“生成并下载”，得到包含平台元数据库快照、终端录像和数据库备份的加密迁移 ZIP。
4. 在目标实例选择迁移 ZIP，输入迁移密码。
5. 点击“校验并暂存导入”。
6. 重启 Viron 服务后才应用迁移包；重启前目标仍使用原数据。

导入会检查格式、数据库完整性、外键、密码和重放。应用时采用替换而不是合并：SQLite 文件或 MySQL/MariaDB 中的全部 Viron 平台表由来源快照替换；迁移包中存在 `recordings/` 或 `backups/` 时，目标同名目录会先删除再复制来源内容。目标实例用自己的主密钥重新加密凭据。忘记迁移密码后无法使用对应迁移包。

系统会在 `DATA_DIR` 自动保存恢复前的可移植元数据库副本 `envman-pre-restore-<timestamp>.db`，但不会自动保存被替换的旧 `recordings/` 和 `backups/`。导入前必须另做完整、一致的目标 `DATA_DIR` 和外部 MySQL/MariaDB 备份；需要整体回退时使用该备份，而不是只依赖恢复前数据库副本。

平台元数据库快照包含用户、组织、资源配置、授权、审计事件和其他中心元数据。迁移包不包含 Web Profile/Cookie、Web 下载、上传暂存、客户端安装包、既有导出 ZIP 或各浏览器/App 的本地状态。

迁移包用于实例搬迁，不能替代完整 `DATA_DIR` 和元数据库基础设施备份。

## 19. 安全与操作注意事项

- 生产环境使用 HTTPS 反向代理，并设置 `COOKIE_SECURE=true`。
- 共享电脑不要使用浏览器“记住密码”；操作完成后退出登录。
- 不要删除或覆盖 `master-key`；密钥和加密数据必须作为同一备份集。
- 桌面 App 的明文 Web、SSH、数据库、Redis 凭据只在主进程可信执行层使用，不跨 preload。
- 普通组织成员通过桌面 App 本机直连使用组织 SSH 密钥时，私钥会在本机主进程内存中短暂出现；本阶段不阻止能完全控制自己电脑的成员提取进程内秘密，后续以远程签名或受控 SSH Agent 收口。
- App 本机执行失败不会自动改用中心服务；服务端执行失败也不会自动改用本机。
- 删除环境不会删除连接；删除连接会删除凭据。执行前看清确认框对象。
- 批量“关联环境”会替换选中连接的原环境集合，不是追加。
- 数据库没有唯一键时不允许直接编辑；结构同步的“需处理”项不会自动执行。
- Redis 拒绝未知、高危、脚本、管理和无界命令；不要尝试通过命令工作台绕过结构化操作限制。
- SFTP、数据库同步、备份恢复等长任务可能部分完成；开始前确认目标、覆盖策略和备份。
- 普通 Web 与桌面本机执行看到的是不同网络位置；同一目标在一种模式可达、另一种模式不可达属于预期差异。

## 20. 当前边界

0.1.6 当前不包含：

- SSO、LDAP/OIDC、MFA、WebAuthn、审批流和跨组织共享；
- 关闭自主注册、注册审批和邮件找回密码；
- 通用 SSH 本地、远程、动态端口转发和 SSH Agent 转发；
- PostgreSQL、Oracle、SQL Server 等非 MySQL/MariaDB 数据库；
- 数据库定时同步、双向实时同步；
- Redis Sentinel、Cluster、Pub/Sub、Monitor、服务器配置/ACL/拓扑管理和 Redis 备份恢复；
- 日志历史保存、时间范围过滤和跨文件按日志时间排序；
- 普通 Web 的页面检查器；
- 环境组服务汇总；
- 手机端终端分屏和数据库编辑；
- 多实例高可用和平台数据定时自动备份；
- 内置 Viron Agent 的日志、Redis、知识库、服务维护和 Web 页面工具，以及远程脚本文件创建与脚本执行、数据库批处理任务、Redis 写命令和 Web 页面操作。

桌面和平板是主要操作端；手机只建议查看基础信息。功能候选和后续边界以 [ROADMAP](./ROADMAP.md) 为准，不应把尚未交付能力当作当前可用入口。

## 21. 常见问题

### 为什么选择账号后没有立刻打开网站？

这是按需连接设计。选择入口和账号只显示待访问状态，双击页面空白处、点击“访问页面”或“新建空白标签页”后才创建执行资源并请求目标网站。

### 为什么连接在环境详情里看不到？

确认当前工作空间、资源授权和连接的环境关联。资源池中的“待分配”连接仍可从全局工作台使用，但不会出现在某个环境的连接列表中。

### 为什么桌面 App 能连上，而浏览器不能，或相反？

浏览器模式从 Viron 服务端发起目标连接；App 本机模式从当前电脑发起。检查“设置 → 连接与执行”的实际执行位置、两端网络、DNS、防火墙和本地网络权限。

### 为什么无法建立新连接？

点击左侧“当前连接”检查用户额度和空闲会话。达到上限时先关闭不再需要的 Web、SSH、日志、SFTP 或数据库连接。

### 为什么日志配置不能启动？

检查 SSH 连接权限和可达性、路径是否为绝对路径、远端账号是否有读权限。启用 SSH 登录脚本时，也要确认脚本执行完成后仍处于能够访问目标路径的交互环境。

### 为什么数据库表不能直接编辑？

表必须存在主键或唯一键，Viron 才能可靠定位需要更新或删除的行。没有唯一键时只能查询、导出或先修改表结构。

### 为什么 Redis 命令被拒绝？

只读连接拒绝全部写命令；高危、脚本、管理、订阅、未知和无界命令在所有连接中都被策略拒绝。优先使用键详情中的结构化操作或改用明确允许的有界命令。

### 为什么平台迁移导入后没有变化？

导入操作只校验并暂存迁移包。必须重启 Viron 服务才会应用；重启前页面顶部会显示待重启提示。
