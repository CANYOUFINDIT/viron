# Viron Agent 设计方案

状态：Pi Agent 内核、持久历史会话、Viron MCP 紧凑工具网关、SSH/数据库专用工具、统一审批策略、双执行位置，以及 SSH 写命令和数据库写 SQL 的确认执行已接入

本文描述 Viron 内置 Viron Agent 的目标形态、权限边界、开源底座选型、架构分层、工具能力和分阶段实施路径。对话界面中的助手身份显示为“小 V”；设置、配置、入口、错误提示和其他功能页面统一使用“Viron Agent”。桌面 App 当前使用 Pi Agent 负责持久多轮对话和 ReAct/tool loop，并通过 Viron MCP 紧凑网关调用当前业务目录中已注册的能力；SSH 和数据库另有可见工作台专用工具。用户可以独立配置审批策略和执行位置：执行结果可以显示在 Agent 对话中，也可以直接落到当前绑定的 SSH 终端或数据库工作台。尚未注册为 MCP 业务操作、未完成领域安全策略或没有工作台适配器的能力仍不开放给 Agent。

## 0. 第一版已确认边界

第一版只做 Viron App 端 Agent，不接入普通 Web 客户端。

- **开源底座**：使用 `@earendil-works/pi-agent-core` 的稳定 `Agent` 和 `@earendil-works/pi-ai` 处理持久多轮对话、模型流式输出、ReAct/tool loop 与工具结果回填；不嵌入完整 coding-agent harness。模型服务支持 OpenAI-compatible API 和 Anthropic Messages API。
- **模型配置**：每个用户在 App 本机依次配置协议类型、`endpoint` 和 `apiKey`；App 从对应协议的模型列表接口自动获取模型并由用户选择，不提供平台级统一 Key。
- **配置存储**：模型配置按“当前设备 + Viron 服务地址 + Viron 用户”隔离，保存在 App 本机数据目录；`apiKey` 使用 App 本机安全存储保护，不上传远端 Viron 服务。
- **模型调用位置**：App 后台主程序直接调用用户配置的模型服务；远端 Viron 服务不接触用户模型 API Key。
- **历史会话**：会话按“当前设备 + Viron Endpoint + Viron 用户”隔离，不绑定工作空间。完整 Chatbox 和快捷输入共用当前会话，并支持新建、切换、重命名和删除历史会话；切换工作空间保留历史文本，只终止旧工作空间中的活动执行。
- **全局入口**：设置页提供“悬浮按钮”“快捷输入”和“关闭”三种互斥状态；尚未保存过入口偏好的设备默认关闭，已经保存的选择保持不变。悬浮按钮打开完整 Chatbox；快捷输入只在 Viron 前台内部响应用户可修改的快捷键，macOS 默认 `Option+Space`，Windows 默认 `Ctrl+Shift+A`。快捷输入发送后保持打开以继续多轮对话，右下角流式回复气泡可以展开，也可用「隐藏回复」暂时收起以免遮挡工作台；关闭状态隐藏并禁用所有入口，但保留模型配置、快捷键和历史会话。
- **瞬时现场提示**：界面不展示场景卡片、附件按钮或“加入当前现场”。用户发送消息时，App 才自动采集当前页面以及可见 SSH/数据库工作台的受限摘要，作为本轮优先提示；它不持久化、不构成权限，也不限制 Pi 通过 Viron 工具搜索其他已授权资源。
- **工具范围**：Pi 可以通过 Viron MCP 紧凑网关发现并调用当前业务目录中已注册的操作；当前 SSH/数据库工作台另提供命令、脚本和 SQL 专用工具。直接操作工作台只调用工作台显式注册的强类型适配器，不模拟鼠标坐标或在未知页面中盲操作。
- **MCP 工具共用**：通用 Viron 业务工具的紧凑网关调用链、操作目录和业务 Schema 已由内置 Agent 与外部 MCP 共用；当前 Pi 适配层仍单独维护网关参数 Schema 与风险映射，后续必须并入共享网关定义并补齐跨入口一致性测试。当前可见工作台专用工具只承担页签绑定、可见执行和结果呈现，仍复用对应领域的安全策略与底层 Runtime。
- **审批策略**：设置提供“请求批准”“帮我批准”“完全访问权限”三档。“请求批准”让每个执行动作只在对话卡片中确认一次，不再打开第二个模态确认框；“帮我批准”自动执行可证明为低风险的只读动作，其他动作仍询问；“完全访问权限”自动执行 Viron 已实现且启用的动作。所有档位都不能绕过当前用户权限、工具白名单、资源绑定、执行模式、影响预览和审计，也不会创建尚未实现的写工具。
- **执行位置**：设置提供“在对话中显示”和“直接操作工作台”，与审批策略相互独立。前者复用受控后台执行通道并在 Agent 卡片显示结果；后者把动作发送到当前绑定且可见的工作台。SSH 会在终端中写入单行命令并发送回车，命令与原始回显保留在终端；数据库会在当前 SQL 页签执行并把结果保留在结果网格。选择“直接操作工作台”且当前轮次绑定了可见 SSH/数据库现场时，Pi 通过 `viron_read` / `viron_risk` 触发的同连接 SSH 命令或 SQL（含写命令和写 SQL）会改走工作台适配器，不再使用受控后台通道。目标不是当前可见现场的其他已授权资源仍可通过 MCP 搜索和调用。两种位置都只把脱敏、截断后的工具结果回送模型。
- **当前执行边界**：本机 SSH 单行命令仍可只生成和填入；多行 Shell 脚本只允许安全填入，不自动回车、写入远程文件或执行。可证明为只读的单行 SSH 命令和单条 `SELECT` / `EXPLAIN SELECT` 按当前审批策略执行。无法证明为只读的单行 SSH 命令和单条受控写 SQL（`INSERT`/`UPDATE`/`DELETE`/`REPLACE` 及受控 Schema 变更）可通过 `confirm-write` 在一次确认后执行，审批卡展示风险原因、目标对象，以及 UPDATE/DELETE 的预计影响行数。账号安全、文件输出和服务管理 SQL 仍被拒绝。SSH 工作台执行要求目标终端当前可见、已连接、处于普通缓冲区和空闲 Shell 提示符、没有待输入内容；取消发送 `Ctrl+C`。数据库工作台执行要求绑定的本机数据库连接已连接且没有其他查询运行；取消复用现有查询取消路径。单次 Pi 执行最多 64 次工具调用、总时限 20 分钟；工作空间、用户、Endpoint、执行模式或目标现场变化时，活动执行立即失效。
- **持久化边界**：本机历史文件只保存经过长度限制和常见凭据脱敏的用户/助手文本，以及助手消息的本轮耗时与 token 用量摘要，最多保留 80 个会话、每个会话 240 条消息；不保存 Pi 内部 tool call、工具结果、完整终端输出、完整查询结果、现场摘要或凭据。
- **当前交付边界**：已交付 App 本机模型配置、Pi 多轮 Agent、历史会话管理、三种互斥入口状态、三档审批策略、两种执行位置、Viron MCP 紧凑网关、发送时瞬时现场提示、本机 SSH 单行命令与 Shell 脚本填入、SQL 填入、跨 SSH/数据库多步只读诊断，以及 SSH 写命令和数据库写 SQL 的影响预览与确认执行。远程脚本文件创建、脚本自动执行、数据库批处理任务、Redis/Web 工作台写入仍不开放。未进入 MCP 业务目录或尚未完成领域安全工具、影响预览和审计的操作仍不开放。
- **术语约定**：用户可见页面统一称为“App 界面层”，本机安全存储、模型调用和工具执行所在的 App 后台部分称为“App 后台主程序”，现有服务器称为“远端 Viron 服务”。

## 1. 目标

Viron Agent 的目标不是只提供一个普通聊天入口，而是在 Viron App 内成为可审计、可授权、可确认的连接操控层。当前提供完整 Chatbox、快捷输入和关闭三种互斥入口状态，能力聚焦 SSH 终端和数据库工作台；长期目标是在用户明确授权的范围内读取当前环境的 Web 页面、SSH 终端、日志、数据库和 Redis 信息，并在更高阶段直接操作用户当前打开或明确选择的连接现场。

最终产品口径：

- 用户要求编写脚本时，Agent 可以读取当前 SSH 终端上下文，生成脚本内容，在当前终端中以可见方式写入脚本、填入执行命令，并在用户确认后执行。
- 用户要求排查问题时，Agent 可以串联 Web 页面现象、SSH 终端状态、日志片段、数据库查询和 Redis 数据，形成可执行排查步骤。
- 用户要求处理数据库数据时，Agent 可以生成查询 SQL、执行受限查询、预览影响范围，并在用户确认后执行数据修正、迁移或清理。
- 用户要求维护 Redis 时，Agent 可以生成命令、读取 key 状态、预览变更风险，并在用户确认后执行受策略允许的操作。
- Agent 操作的是 Viron 已经建立的连接能力，不新增一套绕过 Viron 权限、凭据和审计的执行通道。

首期重点：

- 让 Agent 看懂 Viron App 当前 SSH 终端和数据库工作台现场，包括终端输出、当前输入、数据库结构、当前 SQL 编辑器内容和查询结果摘要。
- 让 Agent 生成排查建议、SSH 命令、Shell 脚本和 SQL，并默认只填入对应工作台。
- 在用户确认后执行数据库低风险读操作，并为后续 SSH 执行、数据库写入、审批、审计和高危拦截建立基础。

长期目标：

- 支持围绕一个环境进行多资源联合排查，例如从 Web 报错定位到日志、SSH 服务状态、数据库数据和 Redis 缓存。
- 支持对当前打开的 SSH 终端、数据库工作台、Redis 工作台和 Web 账号页面进行上下文感知的直接辅助。
- 支持受控的 Web 页面操作、SSH 命令执行、数据库变更和 Redis 维护。
- 支持可复用的运维 Runbook，但所有执行仍受 Viron 权限、工具策略、审批和审计约束。

## 1.1 连接操控口径

Agent 的“直接操控”必须绑定到 Viron 中已经存在的连接现场，而不是让模型构造任意目标。

| 连接现场 | Agent 可以读取 | Agent 可以生成 | 后续可确认执行 |
| --- | --- | --- | --- |
| 当前 SSH 终端 | 最近输出、当前输入、连接元数据、工作目录线索 | Shell 命令、脚本、排查步骤、文件写入命令 | 填入当前终端、创建脚本文件、运行脚本、执行诊断命令 |
| 日志流 | 日志配置、最近行、过滤条件、高亮命中 | 关键字、排查解释、下一步命令或 SQL | 启动已有日志配置、调整过滤条件 |
| 数据库工作台 | schema、对象、SQL 编辑器内容、结果预览 | 查询 SQL、EXPLAIN、数据处理 SQL、迁移步骤 | 执行查询、事务化数据修正、导出或导入任务 |
| Redis 工作台 | INFO、SCAN 结果、key 类型、值预览、TTL | Redis 命令、key 维护步骤、缓存排查流程 | 执行策略允许的读写命令 |
| Web 账号页面 | URL、标题、可见文本、受控 DOM 摘要、截图 | 点击/输入/导航建议、表单填写计划 | 点击、输入、提交前确认、重新登录流程辅助 |

首期可以先交付“读取 + 生成 + 填入当前工作台”，后续再开放“确认后直接执行”。两者都属于同一套连接操控模型，只是风险等级不同。

## 1.2 与 Viron MCP 的工具共用

目标关系不是两套实现之间的事后对齐，而是“通用能力共用、工作台呈现薄适配”。当前核心调用链已经共用，但 Pi 协议适配层仍有两处需要收口：

- `src/shared/mcp-tools.ts` 与 `src/shared/mcp-business-operations.ts` 已经是通用网关调用、业务操作目录、业务 Schema hash、权限/风险分级和 Operation 分派的代码事实来源。桌面主进程通过 `createVironMcpCompactGateway` 创建与远程/本机 MCP 相同的 11 个紧凑工具名称、标题、说明和调用回调，再交给 `DesktopAgentRuntime` 转换为 Pi `AgentTool`；操作搜索、单项业务 Schema 和实际调用不再维护 Agent 私有目录。
- `DesktopAgentRuntime` 当前仍通过 `gatewaySchemas()` 重写 11 个紧凑工具的 Pi 参数 Schema，并通过 `gatewayRisk()`维护网关模式到审批风险的映射。后续应由共享紧凑网关定义直接输出 Pi 可转换的 JSON Schema 与风险元数据，删除这两个 Agent 私有映射；完成前，工具共用状态定义为“核心调用链已共用，协议适配层待收口”。
- `ssh_propose_command`、`ssh_propose_script` 和 `database_propose_sql` 属于内置 Agent 的当前工作台专用工具。它们需要读取瞬时现场、绑定当前可见页签并把命令、SQL 和原始结果留在工作台，因此不直接暴露为外部 MCP 工具；但执行时必须复用 Viron 现有 SSH/数据库 Runtime、只读判定、审批策略、取消、脱敏、结果上限和审计。
- 后续 Web、日志、Redis、知识库和服务维护的普通业务调用必须先进入共享 MCP 目录，内置 Agent 自动获得同一能力。只有需要当前页面/页签可见交互的部分才能增加薄适配器，并且不得复制业务 Schema、风险表、权限判断或连接实现。
- 纯 UI 控制不进入 MCP，包括 Agent 入口开关、Chatbox 展开/关闭、历史会话管理、悬浮按钮位置和界面动效。外部 MCP 也不获得任意 Renderer、IPC、坐标点击或 CDP 透传能力。
- 每个新增共享操作都需要覆盖内置 Agent、远程 MCP 与本机 MCP 一致性测试：相同输入必须使用相同 Schema hash、工作空间绑定、权限和风险分类，并得到等价的受限结果、错误、审计与生命周期行为；“直接操作工作台”只允许改变结果呈现位置，不允许改变授权结论。该跨入口门禁尚未完整建立，属于工具共用收口的完成条件。

## 2. 非目标

以下能力不进入首期边界：

- 不让模型直接获得凭据、密钥、Cookie、设备私钥或连接明文配置。
- 不暴露任意 Shell、任意 SQL 连接、任意 Redis client、任意 CDP method 或任意 JavaScript 执行接口。
- 不因为用户能看到资源列表就批量读取全部资源；Pi 只能按任务通过 Viron 搜索和版本化工具逐项读取当前用户有权访问的资源。
- 不自动执行写入、删除、权限变更、服务重启、批量修改或生产页面提交。
- 不把目标网页、日志、数据库内容或 Redis 值长期保存为普通应用日志。
- 不承诺自动处理验证码、MFA、WebAuthn、复杂 SSO 或跨站安全限制。

## 3. 设计原则

1. **模型不碰凭据**：模型只能调用 Viron 提供的结构化工具，不能拿到明文密码、私钥、连接串、Cookie 或设备密钥。
2. **工具不绕权限**：每次工具调用都重新使用当前用户、工作空间、资源版本和执行模式做权限复核。
3. **读取先于执行**：首期以只读和建议为主；执行能力按风险逐步开放。
4. **默认最小上下文**：每次发送只自动采集当前窗口的瞬时优先提示；其他资源由 Pi 按任务通过 Viron 工具按需搜索和读取。所有进入模型的内容都经过权限复核、脱敏、截断和大小限制。
5. **执行必须可解释**：Agent 执行动作前需要展示目标、参数、影响范围、风险级别和可取消方式。
6. **审计覆盖成功和拒绝**：执行、拒绝、高危拦截、用户批准和用户取消都应进入审计。
7. **本机直连不弱化边界**：Viron App 本机执行仍由 App 后台主程序完成，App 界面层和模型不持有本机通用能力。

## 3.1 开源 Agent 与库选型

Viron 不从 0 实现模型调用、工具调用协议，也不自行维护易提前终止的多阶段循环。当前采用“两层结构”：

- **Agent 内核**：Pi `Agent` 负责多轮历史、流式消息、连续 ReAct/tool loop、工具结果回填、取消和同一循环内的审批等待。
- **Viron 宿主层**：Viron 负责工具目录、权限复核、审批策略、审计、执行位置和工作台适配器。

Viron 不采用完整外部 Agent 平台接管执行流程。SSH、数据库、权限、确认和审计仍由 Viron 自己控制。

| 候选库 | 适配结论 | 原因 |
| --- | --- | --- |
| Pi (`earendil-works/pi`) | 当前采用 | 稳定 `Agent` 提供可嵌入的 TypeScript 多轮工具循环，支持 OpenAI-compatible 与 Anthropic 协议；审批可以在工具 Promise 内等待并在同一 loop 中继续，适合由 Viron 承担权限和执行宿主 |
| yClaw | 外部设计参考 | 一个独立的 Agent runtime 参考实现；适合参考 session-scoped query engine、tool primitive、permission runtime、structured transcript 和上下文管理 |
| OpenCode | 外部开源优先参考 | 开源 Codex-like coding agent，TypeScript 实现，支持 Ollama、LM Studio、llama.cpp 和多供应商模型；适合参考 provider、session、tool 和终端 agent 交互设计 |
| Qwen Code | 外部开源第二参考 | 面向开源模型和 Qwen 生态的 terminal coding agent，适合参考本地模型和 OpenAI-compatible 兼容方式 |
| Vercel AI SDK | 已替换 | 早期版本用于模型流式调用和分阶段工具循环；当前由 Pi 统一承担多轮 Agent runtime，避免 Viron 自行维护续跑阶段和过早终止逻辑 |
| Cline、Goose、aider | 参考交互和工具权限 | 这些项目支持本地或 OpenAI-compatible 模型，Agent 体验成熟；但默认围绕代码仓库、编辑器或本地 shell，不适合直接整包嵌入 Viron |
| LangChain / LangGraph JS | 后续复杂 Runbook 再评估 | 生态成熟，但抽象较重；第一版只需要 Chatbox、工具调用和 SSH/数据库小闭环，不需要先引入图状态机 |
| Mastra | 暂不采用 | 是完整 TypeScript Agent 框架，适合独立 AI 应用；对 Viron 第一版来说会把工作流、部署和工具边界引入过多框架约束 |
| OpenAI Agents JS | 暂不采用 | 适合 OpenAI Agents 体系，但第一版需要同时支持用户自配 OpenAI-compatible 和 Anthropic Endpoint，Viron 仍需模型供应商中立 |
| LlamaIndexTS | 暂不采用 | 更偏数据/RAG 框架；Viron 第一版核心是操作 SSH 与数据库连接现场，不是先做知识库检索 |
| OpenHands、SWE-agent 等代码 Agent | 不作为嵌入底座 | 这些项目主要面向代码仓库、开发终端或自动软件工程流程，不能直接复用为 Viron 内嵌 SSH/数据库连接操控层 |

当前工程策略是：Pi 负责模型调用、流式响应、多轮历史和连续工具循环；Viron 自己负责本机模型配置、安全存储、MCP 紧凑工具网关、SSH/数据库瞬时现场采集、工作台操作、权限复核、确认和审计。Pi 的完整 coding-agent harness 不进入 Viron，避免引入文件系统或通用 Shell 权限模型。

### 3.2 yClaw 可复用设计点

yClaw 不作为 Viron 运行时依赖，也不直接复制其实现。它只作为外部设计参考，重点复用以下思想：

- **Session-scoped query engine**：每个 Agent 会话有明确的 session runtime、单轮输入、历史 transcript、运行期 transcript、工具调用和恢复计划。
- **Query loop**：在同一个模型循环内处理 assistant tool calls、权限判定、工具执行、tool result message 和最终回复，避免把 Agent 逻辑拆散到界面事件里。
- **Runtime-native tool primitive**：工具有稳定名称、schema、runtime description、risk level、permission requirement、provider metadata、执行实现和结构化结果。
- **Permission runtime**：按 `allow / ask / deny` 语义在每次工具调用前决策；用户选择 remember 后写入工具级 matcher，而不是只按命令字符串做临时审批。
- **Context engineering**：通过 ContextManager 组装系统上下文、用户上下文、可用工具、memory、recovery plan 和 transcript，并做预算控制。
- **Structured transcript**：持久化结构化 transcript；流式事件只服务界面展示和回放，不作为运行时事实来源。
- **Interaction card**：用户确认、工具权限提示和工具进度用结构化交互卡承载，避免把关键授权埋在普通聊天文本中。

Viron 的差异：

- yClaw 面向代码仓库、文件和本地命令；Viron 第一版面向 App 当前 SSH 终端和数据库工作台。
- yClaw 是 Java/Spring Web runtime；Viron 第一版运行在 App 后台主程序和 App 界面层。
- yClaw 的 Bash/File 工具不能直接迁入 Viron；Viron 必须重新实现 SSH/数据库专用工具。
- yClaw 的 permission runtime 可以作为设计模板，但权限对象要换成 Viron 的连接、工作空间、当前会话和数据风险级别。

## 4. 总体架构

Viron Agent 由四层组成。

### 4.1 Agent Orchestrator

Agent Orchestrator 负责对话、计划、模型调用、工具调用编排、步骤限制、取消和审批等待。它只面向抽象工具，不直接连接 Web、SSH、数据库、日志或 Redis。

职责：

- 管理 Agent 会话、消息、上下文引用和工具调用状态。
- 构造模型输入，并在发送前执行上下文裁剪与脱敏。
- 解析模型工具调用请求，交给 Tool Gateway 做权限和策略检查。
- 控制最大步骤数、最大 token、最大工具调用次数和总耗时。
- 在需要用户确认时暂停，并把确认结果写回执行流。

### 4.2 Tool Gateway

Tool Gateway 是模型与 Viron 现有运行能力之间的唯一入口。它把现有 Web、SSH、日志、数据库和 Redis 能力包装为版本化、强类型、可审计的工具。

职责：

- 校验工具名称、参数 schema、资源归属、用户权限、工作空间和执行模式。
- 统一执行只读、建议、低风险写入、高危写入的风险分级。
- 根据风险决定直接执行、要求确认、二次确认或拒绝。
- 记录工具调用请求、批准人、执行位置、结果摘要和脱敏后的错误。

### 4.3 Execution Runtime

Execution Runtime 复用 Viron 已有执行端。第一版只启用 App 本机执行：

- App 后台主程序读取本机 AI 配置并调用用户配置的模型 Endpoint。
- App 后台主程序复用现有本机 SSH 和数据库运行层。
- App 界面层负责展示 Agent 面板、历史会话、确认动作，并把生成内容填入当前 SSH 终端或 SQL 编辑器。
- 远端 Viron 服务继续负责账号、权限、连接配置和一次性凭据信封，不保存也不接触用户模型 API Key。

Agent 不新增第二套连接实现。它只通过 Tool Gateway 调用现有运行层，避免出现两套权限、凭据、审计和生命周期模型。

### 4.4 全局 Viron Agent 入口

全局 Viron Agent 入口属于 App 界面层。它不挂在某个环境详情页内部，而是由 App 全局布局承载，并在设置中保持互斥：

- 默认使用右下角悬浮按钮，用户可以拖动按钮调整位置；位置在当前设备持久化。
- 按钮拖动到窗口任一边缘附近并释放时，自动吸附到最近边缘并半隐藏，减少对工作台的遮挡；用户也可以通过聊天窗内的收缩按钮主动贴边。
- 点击半隐藏的按钮或边缘展开控件后解除贴边收缩，并保持完整展开；只有再次拖到边缘或主动收缩时才重新贴边。
- 点击按钮后，聊天窗在按钮附近朝可用空间展开并悬浮在当前页面上方；标题栏可以打开历史会话列表或新建会话。启动 App 或首次打开 Agent 时进入新对话，不自动展示上次内容；用户可从历史会话手动切换并恢复该会话文本。尚未使用的新对话保持唯一：重新打开 App 或再次新建时复用这条空会话，不会在历史里堆叠多条“新对话”。删除历史会话后窗口和列表保持打开，便于连续删除。
- 切换为快捷输入后不再显示悬浮按钮；用户在 Viron 前台内部按下可配置快捷键后，窗口底部居中显示带背景折射、半透明染色和内缘高光的圆角液态玻璃输入条。Enter 发送，Esc 或再次按快捷键收起；发送后输入条保持打开，当前执行结束后可以直接继续下一轮。快捷输入在输入条上方以互不粘连的独立圆角按钮陈列最近 3 个会话名称，名称超过 14 个字符时以省略号收缩，鼠标悬停可看全文；尾部用 `...` 展开其余历史，最右侧加号新建会话；展开的列表仍可切换、重命名和删除。删除后输入条和会话列表保持打开。
- 快捷输入的助手回复在右下角最多保留三条气泡。多轮时默认叠成画中画卡片，最外面只展示最新一轮；点击后方露出的历史轮次标题栏会平铺成标题列表，再点击某一轮才展开该轮详情。平铺后可用「叠起历史」、发送新一轮或点工作台空白叠回最新一轮。气泡堆叠上方提供「隐藏回复」，可暂时收起全部回复以免遮挡工作台；再次打开输入条后可用「显示回复」恢复，发送新一轮或手动切换历史会话也会重新显示。平铺或展开后显示完整 Markdown、SSH 只填入动作和数据库填入或逐次确认的只读动作。启动后不自动铺上一次对话；手动切换到历史会话后，从本机历史恢复该会话最近的回复气泡，并仍默认叠起历史。
- 快捷输入默认快捷键在 macOS 为 `Option+Space`，在 Windows 为 `Ctrl+Shift+A`。Windows 不允许保存会触发系统窗口菜单的 `Alt+Space`；入口模式与快捷键都保存在当前设备。
- 切换为关闭后不显示悬浮按钮、快捷输入条或回复气泡，快捷键不响应；模型配置、快捷键配置、对话和上下文状态不删除，重新切回任一入口后继续使用。
- 桌面本机 Web 页面由原生视图承载时，使用两个同步的透明子窗口把同一个 Agent 悬浮按钮置于原生视图上方：大尺寸视觉层永久穿透鼠标并完整绘制光晕，紧凑交互层固定置于视觉层上方，只覆盖可见按钮与边缘控件、保持视觉透明并始终接收首次点击；按钮样式、位置、贴边和拖动行为与其他页面一致。普通工作台的 Chatbox 和快捷输入仍在主窗口内悬浮，以保留毛玻璃和可聚焦输入。只有当前可见的本机 Web 页面需要越过原生视图时，才把同一套对话层放到覆盖内容区的透明子窗口中；Web 页面保持完整尺寸，不收缩、不重排，也不丢失登录状态。
- 普通工作台中的 Agent 界面不挤压、不重排当前页面布局；本机 Web 页面在对话层可见时也不让出显示区域。
- 发送消息时自动采集当前页面引用；在可见 SSH 或数据库工作台中，同时采集受限、脱敏的现场摘要。本轮结束后不把这些摘要写入历史会话。

界面职责：

- 展示和管理按设备、Endpoint、用户隔离的历史会话，不把会话绑定到工作空间。
- 用户发送时静默采集当前终端、数据库连接、SQL 编辑器内容、查询结果摘要或页面引用；不展示场景卡片、附件按钮或手工加入现场入口。
- 展示 Agent 计划、工具调用、审批卡片、执行结果和审计摘要。
- 支持把生成的 SSH 命令、Shell 脚本或 SQL 填入对应工作台。
- 支持停止 Agent、撤销未执行计划和清空上下文。

## 5. 上下文模型

Agent 的持久历史只保存用户和助手文本。资源现场作为本轮瞬时提示或 Pi 运行期工具结果存在，不写入历史会话文件；每次执行仍依赖可重新授权的资源引用。

### 5.1 瞬时现场提示

发送时采集的内部提示可以包含：

- `environment`：当前环境基础信息、资源数量、标签和状态。
- `web_page`：当前账号页面的 URL、标题、可见文本摘要、可访问性树摘要、必要截图。
- `ssh_terminal`：当前 SSH 会话最近输出、当前输入框内容和连接元数据摘要。
- `log_stream`：当前日志配置、文件路径摘要、最近日志行、过滤条件和高亮命中。
- `database`：连接元数据、数据库列表、schema 摘要、表结构、查询结果预览。
- `redis`：连接元数据、逻辑库、INFO 摘要、SCAN 结果、key 类型和值预览。

每条提示必须包含上下文来源、更新时间、数据范围和脱敏状态。提示不在界面显示为卡片，切换页面或工作空间后直接失效；Pi 如需其他资源，必须通过 Viron 工具重新搜索和授权读取。

### 5.2 脱敏规则

默认脱敏：

- 密码、私钥、token、Cookie、Authorization header、连接串中的 secret。
- 常见 access key、secret key、session id、JWT、数据库密码、Redis 密码。
- Web 表单密码框、隐藏字段和疑似密钥字段。
- 日志与查询结果中的高置信密钥和凭据片段。

脱敏不是安全边界的唯一依赖。即使脱敏失败，工具层仍不得让模型获得凭据或跨权限资源。

### 5.3 截断与大小限制

首期建议默认限制：

- 单次 Web 可见文本不超过 20,000 字符。
- 单个 SSH 终端上下文不超过最近 500 行。
- 单个日志上下文不超过最近 1,000 行。
- 单个 SQL 查询结果不超过 100 行或 1 MiB。
- 单个 Redis 值预览不超过 64 KiB。
- 单次模型请求的瞬时现场提示默认不超过 4 条。

超过限制时只发送摘要、采样和用户明确选择的片段。

工具分为读取、建议、确认执行和高危执行四类。

### 6.1 通用工具

| --- | --- | --- |
| `viron_context` | 已交付 | 读取当前用户、工作空间、执行模式和紧凑能力上下文 |
| `viron_domains_list` | 已交付 | 列出当前 MCP 业务目录的领域 |
| `viron_operations_search` | 已交付 | 按领域、关键词和风险模式搜索版本化业务操作 |
| `viron_operation_schema` | 已交付 | 只在搜索摘要不足时读取具体操作 schema |

### 6.2 Web 工具

| 工具 | 阶段 | 风险 | 说明 |
| --- | --- | --- | --- |
| `web.snapshot` | 首期 | 读取 | 读取当前页面 URL、标题、可见文本、可访问性树摘要和截图 |
| `web.find_text` | 首期 | 读取 | 在当前页面摘要或受控 DOM 中搜索文本 |
| `web.propose_action` | 首期 | 建议 | 生成点击、输入或导航建议，但不执行 |
| `web.click` | 后续 | 确认执行 | 点击当前页面中的受控元素 |
| `web.fill` | 后续 | 确认执行 | 向当前页面的受控输入框填入内容 |
| `web.submit` | 后续 | 高危执行 | 提交表单或触发生产操作，默认要求二次确认 |

Web 工具只能操作当前用户已授权的账号页面和受控目标。不得暴露完整 CDP、任意 JavaScript、其他账号 Profile、Cookie 或浏览器内部目标列表。

### 6.3 SSH 工具

| 工具 | 阶段 | 风险 | 说明 |
| --- | --- | --- | --- |
| `ssh.read_terminal` | 首期 | 读取 | 读取当前 SSH 会话最近输出 |
| `ssh.inspect_state` | 首期 | 读取 | 读取当前会话、连接元数据、终端尺寸、输入框内容和可推断工作目录 |
| `ssh.propose_command` | 首期 | 建议 | 生成命令并解释作用和风险 |
| `ssh.insert_command` | 首期 | 建议 | 把命令填入当前终端输入框，不执行 |
| `ssh.propose_script` | 阶段 2 | 建议 | 结构化生成完整多行脚本、解释器和风险说明 |
| `ssh.insert_script` | 阶段 2 | 建议 | 仅在当前本机终端启用 bracketed-paste 时安全填入，不自动回车或执行 |
| `ssh.write_script_file` | 后续 | 确认执行 | 以受控写文件方式在远程主机创建脚本文件 |
| `ssh.run_command` | 阶段 3 | 确认执行 | 通过 `ssh_propose_command` 的 `confirm-write` 在受控通道或当前终端运行单行写命令 |
| `ssh.run_script` | 后续 | 确认执行 | 运行 Agent 创建或用户确认的脚本 |
| `ssh.run_high_risk_command` | 后续 | 高危执行 | 删除、重启、权限变更等命令，默认二次确认或拒绝 |

SSH 命令执行有两种模式：

- **当前终端填入模式**：Agent 把命令或脚本写入用户当前打开的终端输入区，保持可见、可编辑，默认不自动按 Enter。适合用户希望接管现场的脚本编写和单次命令辅助。
- **受控执行通道模式**：Agent 使用绑定同一 SSH 连接的受控执行通道运行命令，输出回到 Agent 面板并进入审计。适合多步骤诊断和 Runbook。

当前脚本建议必须展示脚本全文、解释器和风险说明。安全填入只使用当前交互终端已启用的 bracketed-paste 机制，填入前清空当前命令行，不发送回车，且不新增主进程脚本执行或远程写文件接口。后续如开放创建脚本文件或执行脚本，必须另外展示目标路径、运行用户、执行目录、环境变量假设和影响范围，并在每次执行前重新确认。

### 6.4 日志工具

| 工具 | 阶段 | 风险 | 说明 |
| --- | --- | --- | --- |
| `logs.snapshot` | 首期 | 读取 | 读取当前日志流最近行 |
| `logs.search` | 首期 | 读取 | 在当前日志窗口或指定日志流中搜索关键字 |
| `logs.explain_error` | 首期 | 读取 | 根据日志片段解释可能原因 |
| `logs.start_tail` | 后续 | 确认执行 | 基于已有日志配置启动受控 tail |

日志工具只使用已有日志配置和受控 `tail` 能力，不把用户输入拼接为任意远端 shell 命令。

### 6.5 数据库工具

| 工具 | 阶段 | 风险 | 说明 |
| --- | --- | --- | --- |
| `database.describe_schema` | 首期 | 读取 | 读取库、表、列、索引和对象摘要 |
| `database.read_editor` | 首期 | 读取 | 读取当前 SQL 编辑器内容和选中 SQL |
| `database.select` | 首期 | 读取 | 执行受限 SELECT，强制行数和响应大小限制 |
| `database.explain_sql` | 首期 | 读取 | 执行或生成 EXPLAIN |
| `database.propose_sql` | 首期 | 建议 | 生成 SQL，默认填入 SQL 编辑器 |
| `database.insert_sql` | 首期 | 建议 | 把生成的 SQL 填入当前数据库工作台，不执行 |
| `database.preview_change` | 阶段 3 | 确认执行 | 通过 COUNT/结构分析预览 UPDATE/DELETE 影响行数和目标对象 |
| `database.execute_change` | 阶段 3 | 确认执行 | 通过 `database_propose_sql` 的 `confirm-write` 执行单条受控 INSERT/UPDATE/DELETE/DDL |
| `database.process_data` | 后续 | 确认执行 | 执行一组用户确认的数据处理步骤 |
| `database.execute_high_risk_change` | 后续 | 高危执行 | DROP/TRUNCATE/批量更新等，默认二次确认或拒绝 |

数据库能力分为 SQL 生成、查询辅助和数据处理三类。生成 SQL 可以直接填入当前工作台；执行查询至少需要明确目标连接和数据库；数据处理必须展示目标连接、数据库、SQL、预计影响对象、事务策略、回滚可能性和审计摘要。首期不允许 Agent 自动执行写 SQL。

数据处理的最低要求：

- 先用只读查询确认目标数据范围。
- 对 `UPDATE`、`DELETE`、`INSERT ... SELECT`、DDL 和跨表处理展示影响预览。
- 支持事务时默认放入事务，并在执行前说明能否回滚。
- 对缺少 `WHERE` 的变更、全表更新、全表删除、结构删除和权限变更默认按高危处理。
- 执行后返回影响行数、结果摘要和下一步校验 SQL，不返回完整敏感数据。

### 6.6 Redis 工具

| 工具 | 阶段 | 风险 | 说明 |
| --- | --- | --- | --- |
| `redis.info` | 首期 | 读取 | 读取受限 INFO 摘要 |
| `redis.scan` | 首期 | 读取 | 使用 SCAN 浏览 key，限制数量和速率 |
| `redis.get_value` | 首期 | 读取 | 读取单 key 的类型和值预览 |
| `redis.propose_command` | 首期 | 建议 | 生成 Redis 命令和风险解释 |
| `redis.run_command` | 后续 | 确认执行 | 执行当前策略允许的命令 |
| `redis.run_high_risk_command` | 后续 | 高危执行 | FLUSH、CONFIG、SCRIPT、批量删除等默认拒绝或二次确认 |

Redis 工具复用现有命令策略。未知、高危、脚本、管理、订阅、无界读取和无法分类命令默认拒绝。

## 7. 权限与审批

使用四级风险模型，并让风险等级、审批策略、执行位置保持正交。

| 级别 | 名称 | 处理方式 | 示例 |
| --- | --- | --- | --- |
| L0 | 只读上下文 | 用户加入上下文后可读取 | 当前页面摘要、终端输出、日志片段 |
| L1 | 建议与填入 | 可直接生成，但不执行 | 填入 SSH 命令、填入 SQL |
| L2 | 低风险执行 | 按审批策略确认或自动执行 | `SELECT`、`INFO`、受限 `SCAN` |
| L3 | 高风险执行 | 二次确认、影响预览，必要时默认拒绝 | `DROP TABLE`、`rm -rf`、`FLUSHDB`、生产表单提交 |

需要用户批准时，只使用对话中的结构化审批卡，不再追加第二个模态确认框。审批卡必须显示：

- 执行动作和工具名称。
- 目标资源、执行位置和当前工作空间。
- 完整参数或可读摘要。
- 风险级别和风险原因。
- 预计影响范围。
- 是否进入审计。
- 确认、取消和填入但不执行三个路径；点击确认即完成本次授权并开始执行。

审批策略：

- `always` / 请求批准：L2、L3 动作都要求一次内联确认。
- `risk-only` / 帮我批准：L2 低风险动作自动批准，L3 仍要求内联确认和影响预览。
- `never` / 完全访问权限：已实现且已启用的动作自动批准；不绕过工具可用性、Viron 权限、资源与工作空间绑定、风险策略、影响预览或审计。

执行位置：

- `conversation` / 在对话中显示：通过受控后台运行层执行，结果显示在 Agent 卡片。
- `workbench` / 直接操作工作台：通过当前可见工作台注册的领域适配器执行，原始命令、SQL 和结果留在工作台；模型只接收脱敏、截断后的结构化结果。
- 当前适配器覆盖 SSH 和数据库。Redis、知识库与服务维护只定义统一领域契约，不在安全工具完成前接受执行请求。

组织工作空间可以增加管理员配置：是否允许 Agent 使用写工具、是否允许高危工具、是否需要组织管理员批准。

## 8. 审计与记录

Agent 审计应覆盖：

- Agent 会话创建、关闭和模型提供商。
- 上下文卡片加入、刷新和移除。
- 工具调用请求、批准、取消、拒绝和执行结果。
- 用户确认人、确认时间、风险等级和执行位置。
- 目标资源 ID、资源版本、工作空间和客户端类型。
- 执行耗时、结果摘要和脱敏后的错误。

审计不保存：

- 模型完整上下文原文。
- Web 页面正文全文、截图原图、Cookie 或表单值。
- 日志全文、SQL 完整结果集或 Redis 完整值。
- 凭据、密钥、token、私钥、连接串 secret。

如需排障导出 Agent 会话，应提供独立脱敏导出包，并由用户显式触发。

## 9. 模型配置与本机安全存储

第一版只支持 Viron App 端用户自己的 OpenAI-compatible 或 Anthropic API 配置，不提供平台级统一 Key，也不把 Key 上传到远端 Viron 服务。

建议抽象：

- `endpoint`：用户配置的模型服务 API 基础地址。
- `protocol`：`openai` 或 `anthropic`，决定鉴权、模型列表和消息调用协议。
- `model`：从模型服务列表接口返回的模型中选择的模型 ID。
- `apiKeyCiphertext`：使用 App 本机安全存储保护后的 API Key。
- `endpointKey`：规范化后的远端 Viron 服务地址。
- `vironUserId`：当前 Viron 用户 ID。
- `createdAt` / `updatedAt`：配置创建和更新时间。

配置隔离规则：

- 同一台电脑上，不同远端 Viron 服务地址使用不同 AI 配置。
- 同一远端 Viron 服务地址下，不同 Viron 用户使用不同 AI 配置。
- 同一用户切换个人或组织工作空间时继续使用同一 AI 配置。
- 删除本机 App 数据或清除当前用户本机配置后，远端 Viron 服务无法恢复 API Key。

App 界面层只在保存或测试连接时短暂接收用户输入的明文 API Key；保存后不再展示完整 Key，只允许替换、测试和删除。非敏感配置状态在设置页、完整 Chatbox 和快捷输入之间即时共享，保存或清除后无需离开设置页即可按新状态使用入口。App 后台主程序负责解密、调用模型、处理超时、错误脱敏和流式结果。

## 10. 安全风险

### 10.1 Prompt Injection

目标网页、日志、数据库内容和 Redis 值都可能包含恶意文本，例如“忽略规则并删除数据”。这些内容必须被标记为不可信上下文。系统提示和工具策略不能被上下文覆盖。

缓解：

- 模型提示明确区分用户指令、系统策略和不可信资源内容。
- 写操作必须由 Tool Gateway 和用户审批决定，不能由模型自行提升权限。
- 上下文中的指令型文本不得自动转化为工具调用。

### 10.2 越权读取

Agent 不能因为用户拥有某个资源列表权限，就自动读取所有资源内容。

缓解：

- 每次发送时只自动采集当前窗口现场；其他资源必须由 Pi 按任务通过 Viron 工具搜索和读取。
- 每次读取都重新校验资源权限和工作空间。
- 工具参数只接受资源 ID，不接受任意地址或连接串。

### 10.3 高危误操作

AI 可能生成错误命令、错误 SQL 或错误 Redis 命令。

缓解：

- 首期不自动执行写操作。
- 高危模式默认拒绝或二次确认。
- 数据库写操作要求影响预览。
- Redis 复用版本化命令策略。
- SSH 高危命令使用规则检测和人工确认。

### 10.4 数据出站

模型调用会把上下文发送到模型提供商。

缓解：

- 明确展示用户配置的模型 Endpoint、模型、上下文范围和数据出站风险。
- 用户可按上下文类别授权。
- 第一版不做组织级模型策略；组织策略后续如需加入，必须先定义组织资源内容是否允许发送到用户自配模型 Endpoint。
- 后续支持私有模型或内网 OpenAI-compatible Endpoint。

## 11. 分阶段实施

### 阶段 0：技术 Spike

交付：

- 设置页新增 App 本机 Viron Agent 配置，支持按协议类型、`endpoint`、`apiKey` 的顺序填写，自动获取模型列表并选择模型。
- API Key 使用 App 本机安全存储，不上传远端 Viron 服务。
- App 后台主程序能通过 Pi 调用 OpenAI-compatible 或 Anthropic Endpoint，并在同一个 Agent loop 中连续处理工具调用和结果。
- App 全局布局提供右下角悬浮按钮、可收起的完整 Chatbox，以及互斥的快捷输入和回复气泡入口。
- 完整 Chatbox 与快捷输入支持发送消息、展示流式回复、停止当前请求，并复用同一持久历史会话和工具动作。
- 使用 Pi faux provider 验证多轮历史、工具调用、工具结果回填、审批等待和继续生成。

不交付：

- 不读取真实 SSH 终端内容。
- 不读取真实数据库 schema、SQL 编辑器或查询结果。
- 不执行命令、SQL、Redis 命令或 Web 操作。
- 不做平台级模型 Key 或远端 Viron 服务模型调用。

验收：

- 未配置模型时，聊天窗明确提示需要先配置。
- 保存配置后能重新打开 App 并读取非敏感配置。
- API Key 不出现在远端请求、普通日志和设置页回显中。
- 流式聊天可完成一轮真实模型回复。
- mock 工具调用能返回结构化结果并继续生成最终回复。

### 阶段 1A：SSH 只读 Copilot

已交付：

- 用户在当前 SSH 工作台发送消息时，App 自动采集当前 SSH 现场作为本轮瞬时提示。App 后台主程序按当前用户、工作空间和会话重新校验，再读取该 SSH 会话的最近输出。
- 输出在进入 Agent 上下文前移除终端控制字符，按最近 120 行和 3 KiB 双重限制截断，并脱敏常见口令、Token、Authorization、URL 密码、JWT、Access Key 和私钥块。
- Agent 通过结构化 `ssh_propose_command` 工具返回一条单行命令、用途说明和绑定的 SSH 上下文引用。
- 用户点击“填入终端”后，只替换当前聚焦终端的输入内容，不发送回车；会话、路由、连接状态或执行方式不匹配时拒绝填入。
- 单行命令和 Shell 脚本填入仍只支持 App 本机直连 SSH 会话；阶段 2 已把同等的显式现场读取和 L2 只读诊断扩展到 App 服务端转发会话，普通 Web 不开放 Agent。

验收：

- Agent 不能绕过 Viron 工具和权限读取资源；瞬时 SSH 提示只指向发送时可见会话。
- Agent 不能获得凭据和连接明文。
- SSH 单行命令只能填入当前提示符，不自动执行；多行脚本必须使用阶段 2 的独立结构化脚本建议和安全填入入口。
- 上下文大小限制和脱敏规则生效。

### 阶段 1B：数据库只读 Copilot

已交付：

- 数据库 schema 读取、当前 SQL 编辑器内容读取、SQL 生成和填入 SQL 编辑器。
- 用户确认后的数据库 `SELECT` 和 `EXPLAIN` 只读执行。
- 数据库上下文截断、结果预览脱敏和本机 Viron Agent 操作记录；记录按 Endpoint 与用户隔离，默认保留 30 天并可在设置中手工清除。
- 每次执行 `SELECT` 或 `EXPLAIN SELECT` 都展示目标连接、数据库和完整 SQL，并要求用户单独确认；不记住执行授权。

验收：

- Agent 不能绕过 Viron 工具和权限读取数据库连接、schema、编辑器或查询结果。
- 数据库写操作不能被工具执行。
- SQL 填入和只读执行分别显示目标连接、数据库和语句范围。

### 阶段 2：策略化读操作和双执行位置

已交付：

- 设置按当前设备、Endpoint 与用户保存三档审批策略和两种执行位置；旧配置迁移为“请求批准 + 在对话中显示”。设置变更立即终止正在运行的 Agent 会话，防止旧策略继续生效。
- 需要批准时，SSH/数据库 L2 卡片展示完整命令或 SQL、目标和诊断进度；用户点击“确认并执行”后立即开始执行，不再弹出第二个确认窗口。低风险自动批准时仍展示同一执行状态卡，并允许取消。
- 可证明为只读的单行 SSH 诊断命令按当前策略执行；App 后台在执行时重新校验当前用户、Endpoint、工作空间、执行模式、SSH 会话和命令策略。服务端同时重新校验当前用户、工作空间、连接权限和 App 执行实例。服务端转发的现场读取和后台执行请求继续使用设备签名保护。
- “在对话中显示”继续使用绑定当前交互会话底层连接的独立受控通道。“直接操作工作台”要求当前 SSH 终端可见、已连接、位于空闲 Shell 提示符且没有待输入内容，再原子写入命令并发送回车；命令和原始输出在终端回显，捕获下一次 Shell 提示符后把脱敏结果回送 Agent。取消或超时发送 `Ctrl+C`。Pi 若改走 MCP `viron_ssh_command_request` / `viron_ssh_commands_read_batch` 且目标就是当前可见 SSH 连接，Viron 会改写为同一条工作台执行路径，而不是另开后台通道。
- 数据库 `SELECT` 和 `EXPLAIN SELECT` 与 SSH 共用同一个可暂停恢复的 Agent loop。“直接操作工作台”把 SQL 写入绑定页签并复用现有查询/取消链路，完整结果留在结果网格，最多 100 行受限结果回送模型。对当前可见数据库连接，MCP `viron_database_query_read_start` / `viron_database_queries_read_batch` 同样改走工作台查询页签。
- Pi Agent 提供连续多轮 ReAct/tool loop；单次执行使用 64 次工具调用和 20 分钟安全上限，总时限包含模型生成、等待用户确认和工具执行。达到限制后不再开放新的工具执行，Agent 必须基于已有结果收口。
- 会话历史按设备、Endpoint 与用户隔离并跨工作空间保留；用户停止、关闭相关 SSH 或数据库连接、禁用 Agent、退出登录、切换工作空间或执行模式时，只终止当前活动执行。数据库查询取消会销毁当前受控查询连接。
- Pi 通过 Viron MCP 紧凑网关获得 `viron_context`、领域/操作搜索、schema、读写/高危/安全执行、Operation 状态、用途补充和取消工具；Viron 在工具 Promise 内完成审批等待，批准后由同一个 Pi loop 继续，不重启模型阶段。
- 确认、完成、拒绝和取消写入按 Endpoint 与用户隔离的本机 Viron Agent 操作记录；服务端转发 SSH 另写中心执行摘要。两侧记录均不保存命令输出或查询结果。
- 结构化 `ssh_propose_script` 返回完整多行 Shell 脚本、`sh`/`bash` 解释器和风险说明；完整 Chatbox 与快捷输入都显示脚本卡片。用户只能把脚本安全填入绑定的当前本机 SSH 终端；终端必须处于 Shell 提示符、普通缓冲区并启用 bracketed-paste。填入不发送回车，不创建远程文件，也不进入执行审批或多步诊断预算；操作记录只保存解释器和行数，不保存脚本正文。
- Chatbox 和快捷输入提供历史会话新建、切换、重命名和删除；历史文件只保存经过长度限制和常见凭据脱敏的用户/助手文本，不保存 Pi 工具消息、现场提示和工具结果。

待交付：

- 远程脚本文件创建与脚本自动执行。

验收：

- 未确认的 SSH 诊断请求不会落到执行端，写命令或无法证明为只读的命令会在 App 后台和服务端策略边界拒绝。
- 后台 SSH 诊断取消或超时后关闭独立执行通道；工作台 SSH 诊断取消或超时向当前终端发送 `Ctrl+C`。
- SSH 诊断结果不会把常见敏感值写入普通日志或本机操作记录。
- 账号安全、文件输出、多语句和具有锁副作用的查询不能进入多步执行循环。受控单条写 SQL 必须经过 `confirm-write`、影响预览和当前审批策略。
- 工具审批与工作台请求绑定原始工具调用、当前用户、Endpoint、工作空间、资源、执行模式和截止时间，旧响应不能在现场变化后重放。

### 阶段 3：确认后写操作

已交付：

- 数据库写 SQL 影响预览和确认执行。`database_propose_sql` 的 `confirm-write` 接受单条受控 DML 或 Schema 变更；审批卡展示风险级别、目标对象，以及可解析 UPDATE/DELETE 的预计影响行数。执行后返回受影响行数。账号安全、文件输出和服务管理 SQL 仍拒绝。
- SSH 写命令确认执行。`ssh_propose_command` 的 `confirm-write` 接受无法证明为只读的单行命令；审批卡展示高风险原因。对话通道走受控执行通道，工作台通道写入当前可见终端。多行脚本仍只能安全填入。

待交付：

- 数据库数据处理任务的预览、事务化执行和执行后校验。
- Redis 写命令策略、确认和审计。
- Web 受控点击、输入和提交。
- 远程脚本文件创建与脚本自动执行。

验收：

- 高危命令默认拒绝或二次确认。
- 组织策略可以禁用写工具。
- 执行失败时保留真实错误并脱敏。

### 阶段 4：Runbook 自动化

交付：

- 用户保存排查模板。
- 短时授权的多步骤任务。
- 运行中暂停、恢复、取消。
- 人工接管和结果报告。

验收：

- Runbook 只能使用授权工具集合。
- 超过时间、步骤、输出或风险限制时自动暂停。
- 任何写操作仍需明确确认。

- `src/client/components/AgentHostBridge.vue`：主窗口向对话层同步当前路由、会话和工作台现场，并执行填入、跳转设置和工作台动作。

- `src/shared/keyboard-shortcuts.ts` 与桌面状态：入口快捷键、平台默认值和设备级入口模式。

首期应优先复用已有运行层：

- SSH 输出复用现有 SSH session buffer 和输入填入能力；脚本生成先落到当前终端可见输入和用户手工执行闭环。
- 数据库读取复用 database workbench 查询和 schema 能力；SQL 生成先落到当前 SQL 编辑器填入和用户手工执行闭环。

实现当前连接操控时，App 界面层需要向 Agent 明确传递“当前活动连接现场”引用，而不是让 Agent 自行猜测：

- 当前环境 ID、工作区类型和工作空间 ID；这些只绑定本次执行，不进入会话主键。
- 当前激活的 SSH 会话或数据库连接。
- 当前编辑器内容、选中文本、终端输入内容和结果页摘要。
- 当前执行模式：第一版固定为 App 本机直连。

## 13. 已确认决策

- 功能品牌统一为“Viron Agent”；只有完整 Chatbox、快捷输入和回复气泡中的对话助手身份显示为“小 V”。设置、配置、入口、错误提示、下载介绍和其他功能页面均使用“Viron Agent”；代码类型、IPC 名称和架构语境继续使用 `Agent`，避免产品命名影响稳定接口。
- 本机安全存储不可用时拒绝保存需要 API Key 的 Agent 配置。
- 数据库 `SELECT` / `EXPLAIN SELECT` 是否确认由统一审批策略决定；“请求批准”每次只在内联卡片确认一次，“帮我批准”和“完全访问权限”可自动批准当前已实现的只读工具。
- Agent 本机操作记录默认保留 30 天，按设备、Endpoint 与用户隔离，允许用户手工清除。
- Agent 历史会话按设备、Endpoint 与用户隔离，不绑定工作空间；切换工作空间保留对话，只让旧工作空间中的活动执行失效。
- Viron Agent 入口只允许“悬浮按钮”“快捷输入”或“关闭”三选一，不提供同时开启；尚未保存过入口偏好的设备默认关闭，已保存的入口选择不被覆盖。
- 快捷输入不提供尾部关闭按钮；用户点击输入条外部（包括桌面原生 Web 页面）时自动收起。收起和再次唤起不会清空未发送草稿；提交发送后只清空输入内容，输入条保持打开以继续当前会话。
- 不显示场景卡片、附件按钮或“加入当前现场”。当前页面、SSH 和数据库状态仅在发送时自动采集为本轮瞬时优先提示。

## 14. 最小可行版本

最小可行版本建议只做以下闭环：

1. 用户在 Viron App 中选择协议类型，填写模型 Endpoint 和 API Key，再从自动获取的列表中选择模型。
2. 用户保留右下角悬浮按钮打开完整 Chatbox，对话助手身份显示为“小 V”；在设置中切换为快捷输入后通过平台默认或自定义快捷键唤起底部输入条，或选择关闭以隐藏所有 Viron Agent 入口。
3. 用户从完整 Chatbox 或快捷输入选择当前历史会话并发送消息；App 在发送时自动采集当前 SSH 终端、数据库工作台或页面引用作为瞬时提示。
4. App 后台主程序通过 Pi 调用用户配置的模型服务，并在同一多轮 loop 中调用 Viron 紧凑工具或 SSH/数据库专用工具。
5. Agent 基于上下文解释问题并生成 SSH 命令、Shell 脚本或 SQL。
6. 用户可以只填入当前工作台，也可以按审批策略执行只读 SSH 命令或数据库 `SELECT` / `EXPLAIN`。
7. 执行位置可以选择 Agent 对话或当前工作台；工作台模式下命令、SQL 和原始结果保留在对应终端或结果网格。
8. 所有上下文读取、填入和执行动作进入对应审计；历史会话只保存脱敏后的用户/助手文本。

这个版本不会修改任何目标系统；自动批准仅覆盖当前可证明为只读的已实现工具。它已经验证模型配置、上下文、脱敏、工具网关、策略审批、双执行位置、审计和 UI 主流程，为后续写操作的影响预览与 L3 安全实现打基础。
