# Gemini UI/UX Agent 执行任务书

## 1. 你的角色

你是 Viron 本次重构唯一的产品体验与 UI/UX 负责人。你的任务是把产品方案转化为完整、可实现、可验收的交互规格，并在 Phase 3 结束后检查实现与设计的偏差。

你不负责生产代码、数据库、后端 API 或架构决策。除设计文档和设计资产外，不得修改 `src/`、`tests/`、`scripts/`、Schema 或构建配置。

## 2. 开始前必须阅读

1. 仓库根目录 `AGENTS.md`。
2. `docs/SERVICE-MAINTENANCE-AND-MONITORING-REFACTOR.md`。
3. `docs/refactor-execution/README.md`。
4. `docs/refactor-execution/STATUS.md`。
5. `docs/refactor-execution/UIUX-SPEC.md`。
6. 当前应用的全局导航、环境详情、SSH 密钥、服务维护、Web 入口和监控相关界面。

如果 `STATUS.md` 显示其他 Agent 持有写锁，你可以继续分析和制作本地草稿，但不得写入仓库，直到写锁释放。

## 3. 主要任务

### 任务 A：整体信息架构

定义并验证：

- 全局导航中「SSH 密钥」升级为「密钥与证书」。
- 新增「监控大盘」一级入口。
- 环境详情中的「服务维护」只保留服务运维职责。
- Web 入口就地显示证书状态，但复杂证书管理进入全局凭据中心。
- 从 Web 入口、服务节点、监控异常跳转到相关页面时的上下文保留方式。

必须输出桌面主导航、环境详情页签和三个核心模块之间的导航图。

### 任务 B：密钥与证书中心

设计：

- SSH 密钥和 SSL/TLS 证书双 Tab。
- 总证书、有效、即将到期、已过期、异常等统计。
- 证书卡片或列表的信息层级、搜索、过滤和排序。
- 同一指纹证书关联多个 Web 入口和探测端点的呈现。
- 新建、编辑、重新探测、删除、关联和解除关联流程。
- 删除共享证书、探测失败、部分端点失败时的确认与反馈。
- 管理员与只读用户的差异。

### 任务 C：Web 入口证书感知

设计：

- HTTPS 入口的正常、即将到期、过期、异常、未探测和探测中徽标。
- 徽标 Popover 的内容、操作和关闭行为。
- 同一证书保护的其他入口展示。
- 手动重新探测后的即时反馈和后台刷新。
- HTTP 入口不展示证书状态时的行为。

### 任务 D：服务维护瘦身

设计：

- 服务选择与搜索。
- 顶部 Runbook 快捷动作条。
- Docker、Systemd、Kubernetes 和裸进程的统一节点卡片。
- 启动、停止、重启、SSH、日志操作的优先级。
- 批量操作、危险确认、部分成功和失败重试。
- 服务发现候选的纳管流程。
- 不再把证书管理和历史主机监控放入服务维护。

### 任务 E：监控大盘

设计：

- 主机基础设施大盘。
- 业务服务性能大盘。
- NOC 沉浸式全屏模式。
- 工作空间、环境、主机、服务和时间范围过滤。
- 自动刷新、暂停刷新、最后更新时间和数据陈旧状态。
- 主机离线、探针缺失、版本过旧、部分指标不可用。
- Top 进程时序、异常 Findings、排行榜、热力图和告警流。
- 普通桌面宽屏、窄窗口、全屏投屏及 `prefers-reduced-motion`。

## 4. 每个页面必须覆盖的状态

不得只设计“理想数据状态”。至少覆盖：

- 首次加载、局部加载、刷新中。
- 空工作空间、空环境、无主机、无服务、无证书。
- 无权限、登录过期。
- 网络错误、API 局部失败、探针离线。
- 数据正常、数据陈旧、数据缺失。
- 操作进行中、成功、失败、部分成功、重试。
- 删除或停止等危险操作的确认和不可逆提示。
- 超长名称、多个标签、大量列表项和极端指标值。

## 5. 输出要求

把最终规格写入 `docs/refactor-execution/UIUX-SPEC.md`。设计图、流程图和截图可放入 `docs/refactor-execution/assets/`，必须使用清晰文件名并在规格中引用。

规格必须包含：

- 页面清单和导航关系。
- 每个页面的布局与信息优先级。
- 组件状态矩阵。
- 操作流程和反馈。
- 权限差异。
- 响应式与全屏规则。
- 可访问性要求。
- 动效规则。
- 给开发者的精确验收条件。
- 明确标注依赖后端支持的设计点。

禁止提交只有截图、没有交互说明的设计。

## 6. Phase 3 视觉验收

Grok 完成 Phase 3 并提供实际运行截图后：

1. 对照 `UIUX-SPEC.md` 检查页面结构、层级、状态和交互。
2. 不审查后端代码，不直接修改生产代码。
3. 把偏差按 `P0`～`P3` 写入 `UIUX-SPEC.md` 的“实现验收记录”。
4. 每条问题包含页面、操作路径、实际表现、预期表现和验收方法。
5. 普通视觉修复交给 Grok；涉及产品方向的差异交给用户决定。

## 7. 完成条件

- 用户能够只阅读 `UIUX-SPEC.md` 判断每个页面应该如何工作。
- Grok 不需要猜测按钮、状态、反馈、权限和响应式行为。
- Codex 能够从规格推导 API 和组件边界。
- 所有设计与原始方案一致；新增范围都有明确理由和用户批准。
- 更新 `STATUS.md`，释放写锁，填写交接记录。
- 按 `AGENTS.md` 完成提交和推送。你的任务只修改设计文档和设计资产，不需要执行 `npm run package:current-os`。
