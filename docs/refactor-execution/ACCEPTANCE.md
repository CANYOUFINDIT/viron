# 重构验收矩阵

> Gate 1 由 Codex 根据最终技术合同补充。本文件中的必选项不得在无用户批准的情况下删除。

## 1. 通用完成定义

每个实现阶段必须满足：

- [ ] 只修改技术合同允许的范围。
- [ ] UI/UX 行为符合已批准规格。
- [ ] 没有未说明的 Schema 或 API 变化。
- [ ] 新逻辑包含行为测试，不只依赖源码字符串断言。
- [ ] `npm run typecheck` 通过。
- [ ] 相关定向测试通过。
- [ ] `npm test` 通过。
- [ ] `npm run build` 通过。
- [ ] 需要时完成桌面用户流和启动验证。
- [ ] 没有敏感信息、私有数据和 `release/` 进入提交。
- [ ] 改动已提交到 `dev` 并推送 `origin/dev`。
- [ ] `npm run package:current-os` 成功。
- [ ] `STATUS.md` 已记录提交、测试、打包、风险和交接。

## 2. Phase 0 验收

### 现状审计

- [ ] 原始方案的每项需求都有实现状态和代码证据。
- [ ] 未跟踪监控组件的归属、完成度和处置建议明确。
- [ ] SQLite/MySQL、TLS、监控、服务维护和测试现状完整。
- [ ] 开放问题均有决策人和阻断阶段。

### UI/UX

- [ ] 全局 IA 和跨模块路径完整。
- [ ] 三个核心模块都有详细设计。
- [ ] 加载、空态、错误、权限、离线、陈旧和部分成功状态完整。
- [ ] 桌面宽屏、窄窗口和 NOC 全屏规则完整。
- [ ] 每个依赖后端的交互都有数据要求或降级方案。
- [ ] 用户已批准设计方向。

## 3. Gate 1 技术合同验收

- [ ] 证书资产与端点模型已明确。
- [ ] 旧 TLS 数据迁移、兼容、回滚和幂等策略明确。
- [ ] 指纹归并受工作空间边界约束。
- [ ] API 请求、响应、权限、限制和错误码明确。
- [ ] 服务维护轻量 Payload 明确。
- [ ] 监控时序降采样、点数和刷新限制明确。
- [ ] 客户端组件拆分和复用边界明确。
- [ ] 未跟踪监控组件处置明确。
- [ ] 每阶段允许修改和禁止修改范围明确。
- [ ] `TECH-CONTRACT.md` 状态为 `FROZEN`。

## 4. Phase 1 凭据与证书验收

- [ ] 全局入口显示「密钥与证书」。
- [ ] SSH 密钥原有导入、生成、导出、指纹和关联统计没有回归。
- [ ] SSL/TLS 证书统计、筛选、列表/卡片和详情可用。
- [ ] 相同 SHA-256 指纹在同一工作空间正确归并。
- [ ] 不同工作空间不会归并或泄漏资产存在性。
- [ ] 多 Web 入口和多探测端点关系正确。
- [ ] Web 入口显示正常、即将到期、过期、异常、未探测和探测中状态。
- [ ] 重新探测会更新所有关联入口。
- [ ] 删除、解绑和证书轮换不会损坏 Web 入口。
- [ ] TLS 探测具备权限、输入限制、超时和注入/SSRF 防护。
- [ ] SQLite 和 MySQL 行为一致。
- [ ] 旧数据迁移测试通过且重复执行安全。

## 5. Phase 2 服务维护验收

- [ ] 服务维护不再包含证书管理 UI 和证书专属 Payload。
- [ ] 服务维护不再承载历史主机监控大盘。
- [ ] 服务选择、Runbook 和部署节点矩阵可用。
- [ ] Docker、Systemd、Kubernetes 和裸进程状态正确。
- [ ] 启动、停止、重启、SSH 和日志操作权限正确。
- [ ] 危险操作有确认和明确后果说明。
- [ ] 防止重复提交和刷新竞态。
- [ ] 批量操作支持部分成功、失败详情和重试。
- [ ] 服务发现和纳管没有回归。
- [ ] 首页 Payload 不携带不必要的历史时序数据。
- [ ] 关键操作写入审计或遵守现有审计合同。

## 6. Phase 3 监控大盘验收

- [ ] 全局导航和路由可按权限访问。
- [ ] 主机基础设施视图展示主机状态、关键指标和探针状态。
- [ ] 服务性能视图提供服务聚合和异常节点排名。
- [ ] NOC 模式可以进入、退出并适配目标分辨率。
- [ ] 环境、主机、服务和时间范围过滤正确。
- [ ] 自动刷新、暂停和最后更新时间正确。
- [ ] 离线、陈旧、缺失和局部失败数据不会被显示为健康。
- [ ] 时序接口实施降采样和最大点数限制。
- [ ] 页面不存在明显 N+1 请求和无限并发。
- [ ] 卸载页面或退出全屏会清理定时器、监听器和未完成请求。
- [ ] `prefers-reduced-motion` 生效。
- [ ] Gemini 的 P0/P1/P2 实现验收问题全部关闭。

## 7. 最终发布验收

- [ ] 原始方案中所有范围均为已实现或经用户批准延期。
- [ ] Gate 2、3、4 均为 `PASSED`。
- [ ] `npm run verify:full-regression` 通过。
- [ ] `npm run package:current-os` 通过。
- [ ] 桌面 App 能启动并完成核心路径冒烟测试。
- [ ] Git 工作区没有意外文件。
- [ ] 所有提交均位于 `dev` 并已推送 `origin/dev`。
- [ ] 未合并或推送 `main`。
- [ ] 已知限制和延期项已记录。
