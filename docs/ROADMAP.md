# Viron 后续能力路线图

本文只记录尚未交付且值得长期跟踪的产品方向，不代表开发排期或承诺。当前已实现能力以 [README](../README.md) 和 [TECHNICAL-DESIGN](../TECHNICAL-DESIGN.md) 为准。

## 当前未交付总览

以下条目是当前代码与长期设计核对后的待办索引，具体边界以对应章节为准：

- Redis：Sentinel/Cluster 可执行拓扑、大规模键空间、Streams/Pub/Sub、运行诊断、导入导出、跨连接复制和扩展模块。
- 用户与接入：资源移交、注册与账号恢复增强、细粒度组织角色，以及通用联邦登录和外部系统初始化。
- 服务维护：TLS 证书观察与到期告警、端口/HTTP 健康检查、历史保留与容量分析、Kubernetes 受控运维动作、环境组汇总和独立脚本库。
- 自动化：跨环境 SSH 脚本主动执行、批量执行、调度、历史、取消、重试和审计。
- Web：普通 Web 服务端画面流的受控页面检查器。
- 桌面 App：个人本机审计、组织可靠上报队列、失权与清理收口、远程签名或受控 SSH Agent，以及 macOS/Windows 正式签名和目标机验收。
- Viron Agent：Web、日志、Redis、知识库和服务维护的强类型安全工具，远程脚本文件与脚本执行，数据库批处理任务，Redis/Web 写操作，以及受限 Runbook。
- MCP：补齐新增业务目录、日志与 Web 运行语义、真实目标写入和完整生命周期回收验收。
- 日志：时间/级别过滤、多文件稳定来源与时间排序、脱敏历史保留。

环境页签和只读数据预取、单个默认 Web 账号的有界预热、服务维护主机离线告警、磁盘变化通知、Agent 统一审批与双执行位置，以及 MCP 精简网关已经交付，不再作为待办重复记录。

## Redis 后续增强

Redis Standalone 核心工作台已经交付，当前连接模型、Web/App 执行边界、资源上限和已验证范围以 [TECHNICAL-DESIGN](../TECHNICAL-DESIGN.md) 为准。本节只记录尚未交付的拓扑、诊断、数据流和高级模块能力。

后续实现继续以 MIT 许可的 [Another Redis Desktop Manager](https://github.com/qishibo/AnotherRedisDesktopManager)（ARDM）作为底层行为参考，以 [Redis Insight](https://redis.io/insight/)、[Medis](https://github.com/luin/medis) 和 [Redis Commander](https://github.com/joeferner/redis-commander) 补充功能覆盖；UI、交互和应用架构仍全部使用 Viron 自身体系，不复用 ARDM 的界面实现。未完成独立安全和真实版本验收的入口不得提前显示为可用。

### ARDM 底层实现参考与复用边界

重点研究 ARDM 的 `ioredis` 连接封装、Standalone/Sentinel/Cluster、ACL、TLS、SSH Tunnel、Cluster NAT 映射、命令与二进制响应处理、键扫描和类型操作、Pub/Sub、Monitor、Slow Log、内存分析、导入导出和值格式解析实现。经过许可证、依赖、安全和正确性审查的独立底层逻辑可以选择性移植或按相同行为重写。

ARDM 的 Vue 2、Element UI、页面组件、布局、样式、全局事件总线和 Electron Renderer 架构不属于复用范围。Viron 继续使用 Vue 3、Element Plus、Fastify、共享前端和受控桌面主进程，并同时支持普通 Web、本机直连和服务端转发；不得把 ARDM 作为 iframe、子应用、独立窗口或第二套 Electron Runtime 嵌入 Viron。

| ARDM 能力 | Viron 中的归属与接入方式 |
| --- | --- |
| `ioredis` 单机、Sentinel、Cluster、ACL、TLS 连接行为 | 在 Viron 共享 Redis 运行层重新封装；普通 Web 由服务端执行，App 本机直连由主进程执行，两端复用连接选项、命令策略和结果模型 |
| SSH Tunnel 与 Cluster NAT 映射 | 复用 Viron 现有 SSH 连接、跳板机、凭据信封和生命周期管理，只参考 ARDM 的拓扑发现与映射行为，不复制其 Renderer 文件读取和临时凭据模型 |
| 键扫描、类型命令、CLI 执行、Slow Log、Monitor、内存分析、导入导出与值解析 | 学习其底层调用、分页、二进制处理和错误语义，在 Viron Redis 运行层中选择性移植或重写；UI 只消费 Viron 自己的结构化结果模型 |
| 连接表单、标签页、深色界面和快捷操作 | 使用 Viron 共享 Vue 3/Element Plus 组件、设计令牌、工程网格、表面层级、图标、间距、字体和浅/深色主题重新设计；Web、macOS、Windows 的共享界面同步适配 |
| 命令表、参数拆分、格式解析等独立逻辑 | 只有通过许可证、依赖、安全、二进制正确性和 Redis 版本测试后才可选择性移植；移植的 ARDM 代码或实质性改写必须保留 MIT 版权与许可声明并进入第三方软件清单 |

每个实施阶段开始前固定经过审查的 ARDM tag 或 commit，记录参考或移植的上游文件、Viron 归属模块和行为差异；运行时不得从 GitHub 加载代码、组件或资源。后续同步 ARDM 更新必须经过独立的差异、安全、许可证和回归评审，不能自动追随上游 `master`。

ARDM 只作为参考实现，不能把其安全行为当作 Viron 的默认设计。明确禁止复制关闭 TLS 证书/主机名验证、Renderer 直接读取私钥或持有 Redis 明文凭据、仅靠静态写命令表实现只读模式、未经脱敏展示 `MONITOR` 原始参数，以及让自定义值查看器执行本机脚本或任意系统命令等行为。若 ARDM 行为与本路线图的权限、审计、资源限制或真实 Redis 语义冲突，以 Viron 边界和独立验收结果为准。

### 拓扑与兼容性

- Sentinel 和 Cluster 成为可执行连接模式，而不只是静态拓扑图。Sentinel 使用 service/master name 发现当前主节点并在外部故障转移后重新发现，Sentinel 与数据节点可以分别配置 ACL 和 TLS；Cluster 从 seed 节点发现拓扑、处理 `MOVED`/`ASK` 和槽位刷新，并遵循只能使用逻辑库 `0`、跨槽命令受限等真实语义。
- Sentinel/Cluster 工作区展示节点、角色、槽位和健康状态，但不主动执行故障转移、主从切换、槽位迁移、节点增删、复制配置或持久化配置修改。
- Redis、Valkey 及其他兼容实现分别维护最低版本、已验证版本、RESP2/RESP3、命令和扩展能力矩阵；未经真实验证不能仅因能够连接就标记为完全兼容。TLS、SSH Tunnel、ACL 和错误阶段仍需要扩充真实环境矩阵。

### 大规模键空间与 Cluster 浏览

- 大键空间改用虚拟列表、可暂停/取消的持续扫描和可配置结果缓存；`COUNT` 仍明确为提示值。逐键内存和近似空闲时长按需读取，且 `OBJECT IDLETIME` 只在淘汰策略和权限允许时标记为近似采样。
- 第二阶段扫描 Cluster 时为每个 primary 维护独立游标和限流，拓扑变化后使当前结果失效并要求重新扫描。类型/TTL 分布、大 Key、热 Key 和内存分析必须显示节点覆盖率、已处理数量和采样方法，不能根据当前页面推断全库结论。

### 数据编辑强化

- 增加批量删除/调整 TTL、绝对过期时间、逐项冲突预览，以及基于 `WATCH`/`MULTI`/`EXEC`、原子 CAS 或等价机制的可检测并发编辑；无法可靠 CAS 的操作继续明确采用最后写入生效，不能承诺 Redis 不具备的通用键版本检测。
- 大 Key 删除优先使用服务端支持的 `UNLINK` 并说明异步释放语义。Cluster 内 `RENAME` 仅允许同槽键；跨槽场景拒绝重命名，不把非原子的复制后删除伪装成 `RENAME`。`COPY` 和其他版本相关命令按能力矩阵开放。
- Hash、Set 和 Sorted Set 使用对应的增量扫描，List 和 Stream 按范围分页；大值和大集合先展示大小与截断预览，由用户显式请求后再分段加载，不能一次性把完整内容读入浏览器或服务进程内存。
- MessagePack、Pickle、Protobuf 和自定义查看器列为第三阶段候选；自定义查看器不得直接执行来自浏览器的本机脚本或任意系统命令。RedisJSON/TimeSeries 等扩展键类型使用专用编辑器，Search 使用独立索引/查询工作区；能力通过命令、类型和兼容矩阵探测，权限不足时显示“无法确认”，不能误判为“未安装”。

### 命令工作台强化

- 增加多页签、服务端持久历史/收藏、原始/结构化结果切换，以及版本、子命令和扩展模块感知的高级补全。事务、Pipeline、Lua/Functions 不因编辑器增强而自动开放；若以后设计，必须明确结果对应关系、超时、资源限制和逐条授权，不能通过文本拼接假装为原子操作。
- 每次执行使用受控连接和响应大小上限；超时或用户停止时可以关闭当前专用连接，但若服务端命令已经开始执行，界面必须如实提示“结果不再等待”而不能宣称远端操作已取消。
- 所有结构化操作和工作台命令都经过同一份版本化命令策略；服务端执行器与 App 主进程复用同一实现。策略至少区分安全读取、数据写入、服务管理、阻塞/高负载和无法分类，解析到子命令及影响行为；批量命令逐条检查，未知、无法分类，以及未被当前能力矩阵和策略明确识别并授权的扩展命令默认拒绝。第三阶段的结构化模块操作只开放自身明确需要的命令，不自动向命令工作台放开全部模块命令。
- 只读连接只允许无服务端或会话副作用的安全读取，执行端一律拒绝写入、订阅状态变更和管理操作，不能只隐藏按钮或只依赖 Redis ACL；可控部署仍应以最小权限 ACL 作为纵深保护。第一阶段一律阻止 `KEYS`、`FLUSHDB`、`FLUSHALL`、`SHUTDOWN`、`CONFIG SET`、ACL/Module/Debug、持久化/复制/迁移、客户端控制和任意脚本等高风险命令，无界集合读取也必须先通过大小检查和影响确认；拒绝尝试同样进入审计。

### Streams 与 Pub/Sub

- 第二阶段的 Stream 工作区在第一阶段 entry 操作之上展示消费者组、消费者和 Pending 状态，支持按 ID 范围增量读取与自动刷新，也可以把用户输入的时间转换为 Stream ID 的毫秒部分作为范围边界，但必须说明这不等同于按消息字段中的业务时间查询；ACK、Claim、删除消息和消费者组变更必须作为明确写操作审计。
- Pub/Sub 工作区支持订阅频道或模式、实时查看有限消息缓冲以及手工发布消息。订阅数、消息大小、刷新速率和会话空闲时间必须有限制，页面关闭、连接失权或执行方式切换时立即退订。
- Stream 与 Pub/Sub 的实时内容默认只存在于活动会话，不进入普通应用日志；是否允许保存或导出必须由用户显式触发并遵守脱敏规则。

### 高级运行诊断

- 增加相邻 INFO 样本计算的吞吐和命中率、命令统计、客户端列表以及内存/大 Key 分析；Cluster 聚合必须保留逐节点数据、阈值、样本与覆盖率，不能把累计计数或历史快照显示成实时指标。
- 热 Key 分为两种不同证据：LFU 策略允许时按需读取近似 `OBJECT FREQ`，或通过限时命令流统计当前窗口；两者分别展示前提、窗口、覆盖率和误差，不能混称为精确全库热度。
- `MONITOR` 会直接增加 Redis 端负载且可能暴露敏感数据，只能在第二阶段由具有独立高危权限的用户显式启动。界面在启动前提示负载和数据风险，设置严格最大时长与事件上限；达到上限立即断开，默认只返回命令名和统计摘要，原始参数未经可靠脱敏不得传给浏览器或写入普通服务日志。
- 首期诊断以读取和定位问题为主，不提供修改 `CONFIG`、ACL、持久化、复制、Sentinel 或 Cluster 拓扑的运维入口。

### 导入、导出与跨连接迁移

- 第二阶段提供版本化导出包，至少记录引擎与版本、逻辑库、导出时间、键和成员的无损二进制编码、类型载荷、绝对到期时间、格式版本及逐项校验和；导出文件不得包含连接密码、TLS 私钥或其他连接凭据。首个格式覆盖六种核心类型的键数据和 Stream entries，不承诺消费者组或 PEL 保真。
- 多键导出不是一致性快照，界面必须说明键可能在导出期间修改或过期。导入使用绝对到期时间，已经到期的键跳过并报告，不能因导入耗时无意延长原 TTL。
- 导入先解析并预览新增、覆盖、跳过、不兼容和失败数量，再由用户选择跳过或覆盖策略；“仅新增/跳过”在实际写入时使用原子的不覆盖条件或等价 CAS，“覆盖”则明确提示可能覆盖预览后的并发修改并记录用户选择，不能把预览结果描述成写入锁。竞态、驱逐、ACL 或其他运行时差异按项失败；过程设置单键、总大小、并发和执行时间上限，部分失败提供可重试明细。
- 跨连接复制复用同一预览和冲突模型，源与目标都必须是当前用户有权访问的 Redis 连接；目标写入成功前不删除源键，也不提供暗含删除的“移动”。同一 Cluster 内的原子多键操作遵守同槽限制；跨独立连接复制不以槽位不同为由提前阻止，但必须检查目标版本、类型和运行限制。
- 首期不管理服务器文件系统中的 RDB/AOF，不执行服务器备份恢复、定时同步或持续数据复制；这些能力需要先定义存储位置、一致性、恢复验证和资源消耗边界。

### 权限、审计与执行边界

- 普通 Web 由中心服务发起目标连接；桌面 App 默认本机直连并可以按本路线图既有全局模式选择服务端转发。两种执行方式共用同一连接配置、命令策略和工作台语义，SSH Tunnel 也由实际执行端建立；本机失败时不静默回退到服务端，中心断线和已建立会话沿用本路线图“本机 Session、状态与中心断线”的统一规则。
- App Renderer 只提交 Redis 连接 ID、结构化数据动作或命令文本；主进程按当前 Session、工作空间和资源版本重新授权并取得一次性凭据信封，Redis 密码、TLS 私钥和 SSH Tunnel 凭据不得跨 preload。
- App 本机直连期间中心断线时，已经建立的 Redis 会话可以继续，但不能新建连接、重新取得凭据、修改中心配置或切换执行方式；每个后续操作必须先成功写入个人本机审计或组织加密待上报队列，写入失败或队列已满时停止对应操作。中心恢复后先重新校验登录、权限、设备和连接版本，再允许新连接或补传组织审计。
- 连接配置变更、测试、命令执行或拒绝、键增删改、TTL 调整、批量操作、导入导出、发布消息和诊断会话均进入审计。审计保存命令名、必要参数摘要、键名或模式、执行位置、耗时和结果，不保存完整值、命令响应、订阅消息或凭据；个人/组织审计归属和中心断线队列沿用本路线图的统一审计规则。
- 所有路径设置连接数、命令超时、响应大小、扫描速率、批量数量、活动订阅和后台任务上限。工作空间切换、授权撤销、连接变更、设备撤销、退出登录或执行方式切换时关闭受影响的 Redis 会话和任务。
- 实施前必须把扫描批大小、总保留结果、逐键元数据速率、连接/订阅/任务并发、响应和值大小等默认值与硬上限写入技术设计。真实 Redis 验收覆盖空库、百万级键空间、大 Key、二进制键和值、扫描期间增删/过期、取消后停止新请求、ACL、TLS、SSH Tunnel、超时、断线重连、命令策略绕过、跨用户隔离和审计脱敏；Sentinel、Cluster、Valkey 与扩展能力在宣布支持前分别完成真实版本和拓扑验收。

### 后续分阶段范围

1. **生产拓扑、诊断与数据流**：支持经 Sentinel 自动发现主节点和经 Cluster 槽位路由执行数据操作，同时提供只读拓扑；增加 Streams 消费者组、Pub/Sub、版本化导入导出、跨连接复制、命令/客户端统计、内存与大 Key 分析，以及受高危权限和时间上限控制的命令流监控。仍不提供人工故障转移、迁槽或拓扑修改。
2. **扩展模块与高级能力**：RedisJSON、TimeSeries 等扩展键类型编辑器，Search 索引/查询工作区，Bloom 等扩展能力，MessagePack 等安全值查看器，以及版本、子命令和模块感知的补全与分析。拓扑变更、任意脚本、服务器备份恢复或其他高风险管理能力不属于当前承诺，需独立设计和安全验收后再决定是否开放。

## 用户体系后续增强

多用户、个人/组织工作空间、组织管理员与成员、项目成员、资源授权、账号停用、现有实例迁移，以及组织管理员将自己的个人连接、环境或环境组复制为组织独立副本并完成项目/成员授权已经交付，当前行为以 [TECHNICAL-DESIGN](../TECHNICAL-DESIGN.md) 为准。后续仍可扩展：

- 组织删除、个人或组织资源移交，以及离职用户资源接管流程。
- 注册审批、邮件找回密码和更细的注册防滥用策略。
- 自定义部门用户组、项目管理员和受限的继续授权能力。
- 通用联邦登录、外部身份即时创建和接入方组织 / 项目初始化；OIDC、SCIM、LDAP、MFA、WebAuthn 与企业身份目录同步在该基础上继续评估。
- 跨组织资源共享，以及已经独立复制的个人/组织副本之间可审计的选择性同步。

## 通用联邦登录与外部系统接入

目标是让已在可信外部系统登录的用户通过外部系统后端进入 Viron，无需再次输入 Viron 密码。Viron 只提供通用集成客户端、外部身份、组织 / 项目初始化和一次性登录票据能力，不包含接入方专用路由、固定组织名或业务角色判断。

### Viron 通用后端

- 增加每个接入系统独立的集成客户端与可轮换凭据；Viron 只保存高熵密钥哈希，支持平台管理员创建、列表、轮换、启停和审计。第一版可以先提供 CLI 和平台管理员接口，不要求先完成独立管理页面。
- 增加外部身份映射、接入方资源外部键绑定和短时单次登录票据；联邦创建账号禁止本地密码登录并固定不是平台管理员。
- 提供通用 `session-launches` 和 POST 票据消费接口，在一个事务内完成账号即时创建、组织/项目幂等初始化、组织角色与项目成员同步、票据签发和目标工作空间选择。
- 为项目成员关系记录人工或集成来源，联邦撤销不能删除仍有人工来源的成员关系；外部绑定有效时阻止直接删除组织或项目，并提供平台管理员绑定、解绑和完整性检查能力。
- 客户端策略限制可创建的组织外部键、项目数量、最高组织角色和内部回跳路径；客户端停用、外部身份停用或授权撤销时关闭关联运行时并撤销关联 Session，同时保护组织至少保留一名实际可登录的有效管理员。
- SQLite 与 MySQL 使用等价约束、大小写语义和行为；覆盖并发首次初始化、同名人工资源冲突、绑定资源删除、最后一名有效组织管理员、平台救援、密钥轮换、票据重放、回跳注入、速率限制和审计脱敏测试。

### 外部系统参考接入

- 接入方后端配置 Viron Endpoint、独立 `clientId` / `clientSecret`、目标组织外部键和默认项目外部键；密钥只存在于服务端环境变量或密钥管理系统，不返回前端。
- 接入方后端根据自己的认证上下文和业务规则映射 Viron 组织管理员或普通成员，并调用 Viron 通用接口；Viron 不识别接入方内部角色字段。
- 接入方管理员首次进入时允许初始化目标组织和默认项目，后续管理员加入同一组织；普通用户在初始化后成为组织普通成员并加入默认项目，初始化前得到明确提示。
- 接入方前端只提供独立入口，并使用 Viron 返回的消费地址和一次性票据自动提交临时顶层 POST 表单；票据不得进入 URL 或浏览器持久存储，也不得向 Viron 传递接入方 Session、第三方 Token、Cookie 或客户端密钥。

### 后续平台管理与标准化

- 在 Viron 平台设置中增加集成客户端管理、密钥到期提醒、最后使用时间、失败统计、客户端审计和关联 Session 撤销。
- 接入方数量增加后评估 OIDC、SCIM、mTLS 或 `private_key_jwt`，复用既有外部身份、资源绑定、成员同步和审计模型，不因引入标准协议绕过 Viron 权限边界。

## 环境 TLS 证书维护

目标是让运维在现有环境里看见「哪张证、在哪台机器上、何时过期」，并在到期前收到与主机离线同一管道的告警。证书是服务维护中的观察对象，不是第八个环境页签，也不是 SSH 密钥那样的工作空间私钥库。

当前连接表单里的数据库/Redis 客户端 TLS 材料、Viron Endpoint 自身的 HTTPS 证书，都不属于本节。

### 产品形态

- 入口在环境「服务维护」：左栏在服务清单、主机清单之外增加「证书」分组。不新增环境顶栏页签，不进入连接资源池、连接巡检或 SSH 密钥页。
- 用户看见的主列表是**逻辑证书**（同一环境内按叶子证书 SHA-256 指纹聚合）。每张证展开后列出出示它的 TLS 端点（SSH 主机、连接目标、端口、SNI）。尚未探测成功的端点以独立行出现，不假装成一张证。
- 顶栏 `attentionItems` 增加即将过期、已过期、待关联主机；无异常时不占位。全局监控告警中心复用现有未读、站内通知和桌面系统通知，点击进入该环境服务维护并聚焦对应证书。
- Web 入口不承载维护工作台。`https://` Origin 只作为自动发现来源，并在入口列表提供只读徽章；点徽章跳到服务维护中的那张证。`http://` 入口不生成端点、不显示徽章。

### 对象模型

主存储对象是环境内的 **TLS 端点**，不是私钥、也不是独立的证书文件库。

- 端点字段：所属环境、可选 SSH 连接、连接主机、端口（默认 443）、SNI（默认等于连接主机）、来源（`web_entry` / `manual`）、是否启用观察、可选服务/部署绑定（第一期可空）、排序和时间戳。
- 端点身份：已绑定 SSH 时为 `environment_id + ssh_connection_id + host + port + sni`；未绑定为 `environment_id + host + port + sni`。未绑定的相同 Origin 只保留一条，避免两个 Web 入口共用地址时重复建端点。绑定后允许另一台 SSH 主机再登记相同 host/port/SNI（例如两台机器都在 `127.0.0.1:443` 出示同一域名）。
- Web 入口与端点是多对多：多个 `https` 入口可以指向同一 Origin 端点；删除入口只取消关联，仅当端点来源为自动、无手工改动且无其他入口引用时删除端点。管理员把自动端点改成手工后，删除入口不再级联删除。
- 探测快照只保存公钥侧结构化结果：subject CN、SAN、issuer、serial、签名算法、`notBefore`/`notAfter`、叶子 SHA-256 指纹、是否自签、SNI/主机名是否匹配、链是否完整、剩余天数、探测状态、探测时间和脱敏错误。不保存私钥、完整 PEM、中间证书原文或连接凭据。
- 指纹变化视为换证：端点保留，旧逻辑证书上的到期告警恢复，新指纹作为新的逻辑证书展示。不能把换证显示成磁盘那样的「新增事件」。

每个环境最多 50 个 TLS 端点。主机名/SNI 最长 253 字符，端口 1–65535。主机只允许 DNS 名、IPv4 或 IPv6；SNI 只允许 DNS 名。写入前拒绝空白、控制字符和 Shell 元字符。

### Web 入口联动

- 创建或更新 `https` Web 入口时，用 `normalizeWebAddress` 得到的 Origin 登记端点：`host` 为 hostname，`port` 为 URL 端口或 443，`sni` 为 hostname。
- 若当前环境恰好有一条 SSH 连接的 `host` 与 Origin hostname 大小写不敏感完全相同，则自动绑定该 SSH 连接；0 条或多条都不猜测，端点保持「待关联主机」，由管理员选择。Viron 中心不做 DNS 解析来凑主机。
- 自动绑定之后，管理员仍可改 SSH 连接、把连接目标改成 `127.0.0.1` 并保留原 SNI，以覆盖「公网域名、本机 443」的源站场景。已手工改过的端点，Web 入口 URL 变更不再覆盖主机/端口/SNI。
- Web 入口列表只读徽章来自该入口已关联端点的最近探测：正常、即将过期、已过期、主机名不匹配、待关联、尚未探测。徽章不发起 Chromium 握手，也不把浏览器看到的 CDN/代理证书当成源站库存。
- 证书详情列出关联的 Web 入口名称，可跳回对应入口；不在 Web 浏览区展开证书链或换证操作。

浏览器执行端（服务端 Chromium 或 App 本机 `WebContentsView`）看到的叶子证书若在后续阶段采集，必须作为独立的「浏览侧」字段，不能与源站探测快照合并。第一期不采集浏览侧证书。

### 探测与执行位置

- 探测始终由中心服务经现有 SSH/单级跳板执行，与服务维护扫描、监控拉取、脚本按钮相同；不跟随桌面 App 的本机直连/服务端转发，也不从用户浏览器或 App Renderer 对目标做 TLS 握手。
- 未绑定 SSH 的端点不探测、不产生到期告警，只出现在「待关联主机」。
- 远端命令模板固定。中心把已校验的 host、port、SNI 作为独立参数传入，使用与日志路径相同的 POSIX 单引号转义，禁止字符串拼接进任意 Shell。在绑定主机上对 `host:port` 发起 TLS handshake 并指定 SNI，把叶子证书 PEM 收回中心后用运行时 `X509Certificate` 解析。SSH 命令超时 10 秒，输出上限 64 KiB。
- 目标机没有可用的固定探测工具时，状态为 `probe_unavailable`，界面说明需要 OpenSSL 或后续 `viron-monitor` 辅助命令；禁止静默改由中心机器直连目标 443。自签、私有 CA 或链不完整不算探测失败：仍保存叶子字段，并分别标记 `isSelfSigned`、`hostnameMatch`、`chainComplete`。
- 第一期不依赖 `viron-monitor` 已安装。周期探测挂在中心后台拉取器旁路，与监控 collect 分账：每个 SSH 连接串行探测到期端点，每轮每连接最多 10 个，全局仍按现有监控拉取的小批量并发。健康证书默认 1 小时一次；剩余天数 ≤ 告警阈值或上次失败时 15 分钟一次；任何端点两次探测间隔不短于 5 分钟。
- 有环境与对应 SSH 权限的成员可以手动「重新探测」，同一端点 1 分钟内只能成功排队一次。关闭页面不中断已开始的探测。

### 告警

环境告警设置增加证书规则，从属于现有总开关，可单独关闭：

- `tls_expiring`：剩余天数 ≤ 阈值（7 / 14 / 30，默认 14）。
- `tls_expired`：`notAfter` 早于当前时间。
- `tls_hostname_mismatch`：SNI 或连接主机与 CN/SAN 不匹配（含通配符规则）。默认开启。

状态机与主机指标相同：连续两次异常创建活动告警，连续两次正常恢复，活动期间去重。自签和链不完整第一期只展示，不告警。探测失败不使用到期规则冒充；连续探测失败只更新端点状态，第一期不新增等价于主机离线的证书告警，以免 OpenSSL 缺失刷屏。

告警 `targetType` 扩展为证书端点；导航 query 为 `tab=maintenance` 与证书/端点 ID。通知文案只含环境、连接名、CN/SAN 摘要和剩余天数，不含 PEM 或指纹以外的证书正文。每个用户的未读和提醒状态沿用监控告警现有隔离。

### 权限、审计与界面

- 工作空间所有者或组织管理员：登记/编辑/删除手工端点、绑定或改绑 SSH、调整自动端点、开关观察、配置证书告警。普通成员不可改配置。
- 有权访问环境和对应 SSH 连接的成员：查看清单、快照、关联 Web 入口，以及手动重新探测。每个写接口和探测接口都重新校验环境和 SSH 权限。
- 审计记录端点增删改、绑定、告警设置、手动探测和拒绝尝试。保存主机、端口、SNI、指纹、剩余天数、结果，不保存 PEM、私钥或完整证书正文。
- 服务维护 10 秒只读刷新带上证书摘要。沉浸导航的服务维护叶子可显示即将过期数；环境总览卡片第一期不增加证书计数。
- 桌面 App 与普通 Web 使用同一中心数据和操作语义。App 额外走现有监控告警的系统通知，不在本机执行探测。

### 明确不做

- 不新增环境页签、工作空间证书私钥库、CA、ACME/Let’s Encrypt 客户端或证书签发。
- 不把目标 HTTPS 私钥、完整证书链原文收入元数据库、凭据信封、审计、MCP 或界面。
- 不与数据库/Redis 客户端证书、Viron Endpoint 证书、kubeconfig 客户端证书混用。
- 不在 Web 账号、Profile、自动填充或画面流路径里插入换证、重载或证书链工作台。
- 第一期不做端口/HTTP 健康检查、nginx/Caddy/certbot/Kubernetes Secret 扫描、服务绑定换证、上传并重载。
- 第一期 MCP 只在能力落地后把证书清单和快照按 `read` 加入现有紧凑网关业务目录；换证不得先做成 Agent 私有写工具。

### 分阶段范围

1. **观察与告警**：手工端点、Web 入口 Origin 自动登记、SSH 唯一主机名匹配、中心经 SSH 的 TLS 探测、按指纹聚合的证书清单、到期/过期/主机名不匹配告警、Web 入口只读徽章和跳转。
2. **主机发现与健康检查共用**：从常见反代/证书路径和 Kubernetes TLS Secret **元数据**发现端点（只读路径、名称、到期，不拉私钥）；端点可绑定已纳管服务；端口/HTTP 健康检查复用同一端点登记。浏览侧证书若采集，必须与源站快照分列。
3. **更换与重载**：经 SFTP 把用户选择的证书材料一次性落到已知路径并触发已绑定服务的重载或既有脚本按钮；材料只短暂存在于中心授权过程与本次 SSH/SFTP，用完释放，不入库。ACME/certbot 需要独立安全设计后再决定是否开放。

实施前要把端点上限、探测间隔、命令超时、输出上限和告警阈值写入技术设计。真实验收至少覆盖：无 Web 入口的手工 443、Web 入口自动登记、待关联主机、唯一 SSH 主机名匹配、本机 `127.0.0.1` + 公网 SNI、自签、主机名不匹配、换证指纹变化、过期恢复、OpenSSL 缺失、SSH 失权、普通成员只读、审计无 PEM，以及告警点击聚焦。未完成上述验收前，入口不得显示为已交付。

## SSH 脚本与调度执行

服务维护已经提供直接绑定服务或部署节点的功能按钮。这里规划的是独立于服务按钮的跨环境可复用脚本库与调度能力：用户录入脚本、关联环境并指定 SSH 主机，再主动执行或按定时任务触发。脚本实际运行在所指定的远端 SSH 主机上，不等同于现有用于生成资源目录的隔离脚本同步，也不等同于建立 SSH 会话时自动执行的登录脚本。

当前只确认以下产品需求：

- 用户可以创建、查看、编辑和删除多个脚本。
- 脚本可以关联环境，并为独立执行指定对应的 SSH 连接；也可以绑定到服务维护中的部署、启动、停止、重启、回滚或自定义动作。
- 用户可以对一个或多个指定 SSH 连接主动触发脚本，也可以从服务维护页选择一个、多个或全部部署节点执行已绑定的脚本。
- 用户可以为脚本配置定时任务，由系统自动触发执行。
- 用户可以查看每次执行的状态、时间和结果，失败时得到可操作的错误信息。

具体方案留到实施前再完成需求对齐和安全设计，包括工作空间归属和共享权限、解释器与运行目录、参数和环境变量、定时表达式与时区、批量节点的串行/并行/分批策略、并发和重复触发、超时/取消/重试/回滚、输出与历史保留、审计与脱敏、凭据或权限变化后的处理，以及手动和定时任务由服务端还是桌面 App 发起。相关边界未确认前，不把该能力标记为已交付。

## 普通 Web 的页面检查器

桌面 App 的本机 Web 页面已经通过当前 `WebContentsView` 的原生右键菜单提供导航、编辑、复制粘贴、链接在同账号新标签页打开和独立 Chromium DevTools。普通 Web 当前接收的是服务端 Chromium 的画面流，外层浏览器开发者工具只能检查 Viron 页面外壳，尚不能检查目标网站 DOM。普通 Web 的首期目标是提供受控的元素检查器，不把完整 Chrome DevTools 或原始 CDP 暴露给浏览器客户端。

### 交互与首期范围

- 用户在目标网页画面右键后选择“检查元素”，Viron 打开与当前账号页面并列的检查面板并定位到点击元素；账号、弹窗页面或活动页切换后，检查目标必须明确跟随当前选择，不能继续显示其他页面的数据。
- 首期提供按需 DOM 树、元素属性、盒模型、计算样式、页面内高亮和复制 CSS 选择器。Console、Network、Sources、Application、任意 JavaScript 执行和完整 DevTools 前端不在首期范围内。
- 检查面板只在当前工作区保存展开状态和已选节点引用；刷新、导航或 DOM 重建后节点引用失效时重新选择，不持久化网页正文、DOM 快照或样式结果。

### 服务端实现

- `WebAccountViewManager` 为当前 `credentialId + pageId + executionScope` 创建独立于画面流的检查会话。开始检查前沿用现有 Web 凭据访问校验，并签发短时、单次使用的检查票据；WebSocket 只能绑定票据对应的用户、账号、执行实例和页面。
- 服务端通过受控 CDP 命令读取命中节点、父子节点、属性、盒模型和计算样式，并使用 Overlay 域把选中高亮绘制进现有画面流。浏览器客户端只发送选择坐标、节点展开/收起和关闭检查等结构化动作，不能提交任意 CDP method、表达式、目标 ID 或脚本。
- DOM 与样式按用户动作增量读取，不发送整页持续快照；限制单次节点数量、树深、属性长度、样式数量和消息大小。同一账号页面只保留一个检查会话，避免检查器绕过现有连接数、空闲回收和输出速率约束。

### 隔离、审计与生命周期

- 检查会话只能访问当前用户已有权使用的账号页面，不开放 Chromium 远程调试监听端口，也不允许枚举其他 Browser Context、账号、页面或服务端目标。App 选择服务端转发时复用同一检查路径和执行实例隔离。
- 记录检查器打开、目标页面、选择元素和关闭等元数据，不把 DOM、样式、Cookie、页面正文或表单值写入审计和应用日志；错误摘要继续脱敏。
- 页面关闭、导航到新文档、账号重新登录、视图休眠、权限失效、执行方式切换、WebSocket 断开或服务停止时立即释放检查 CDP 会话和节点引用。释放检查器不得停止同页面的画面流，停止画面流也不得留下可继续读取页面的检查通道。

### 验收边界

- 覆盖普通 Web 与 App 服务端转发、主页面与 HTTP(S) 弹窗、同账号多页面、双账号并排、刷新/导航/关闭及重新登录。
- 验证跨用户、跨账号、跨执行实例和过期票据均被拒绝；检查消息不能调用未列入白名单的 CDP 能力，也不能读取其他 Profile、Cookie 或服务器文件。
- 真实 Chromium 验证元素定位、高亮、DOM 增量展开、计算样式和盒模型准确，检查器关闭后页面交互、画面流、上传下载和登录态不受影响。

## 桌面 App、本机执行与服务端转发

目标是先交付 macOS 桌面 App，并保持普通 Web 客户端继续可用。两类客户端共享同一中心 Viron 服务中的用户、组织、权限、环境和连接配置，但根据客户端能力采用不同的连接执行方式。

第一阶段中心数据层已交付。第二阶段本机 Web 已收口：API 协议 v2 支持设备 RSA 持有证明和 60 秒一次性 AES-GCM 凭据信封；macOS App 使用 App 数据目录中的安装级随机密钥保护每个 Endpoint/用户的私钥，并让 Chromium 使用无钥匙串后端，运行时不请求系统钥匙串授权；按 Endpoint、用户和账号创建独立持久 Chromium Profile，在本机缓存每个账号最后访问的同源完整地址，并支持本机直连、单/双账号视角、导航、刷新、同账号多页面弹窗、原始 Origin 主页面自动填充、原生文件选择上传、系统保存对话框下载、重新登录/Profile 与地址缓存清理和同窗聚焦。第三阶段本机 SSH/SFTP/日志已交付：同一设备密钥体系为主连接和单级跳板机发放一次性 SSH 凭据信封，App 从当前 Mac 直接支持全部现有认证方式、登录脚本、多会话与布局、断开重附着、命令历史/收藏、ZMODEM、本机录像、双栏 SFTP CRUD/上传下载及递归跨主机传输；环境日志复用 Web 配置和查看交互，由主进程重新读取可信配置并执行受控多文件 `tail`，最多同时保留 3 路流。第四阶段本机数据库与连接巡检已交付：数据库一次性信封覆盖密码、SSL 客户端材料、HTTP Tunnel 和数据库 SSH Tunnel 依赖，主进程从当前 Mac 执行对象浏览、查询/取消、表数据维护、导入导出、备份恢复与跨连接迁移；连接巡检以 5 并发在本机完成 SSH 认证或数据库 `SELECT 1`。第五阶段的 App 连接模式切换已交付：默认本机直连，可按设备与 Endpoint 切换为服务端转发；实时通道由主进程桥接，服务端运行资源按 App 执行实例隔离，切换前检测并关闭活动资源，Web 在中心不支持代理时保留本机执行，SSH/数据库等分项不可用时不静默回退。个人本机审计、组织可靠上报队列和完整安全收口仍未交付。仓库可以生成当前 Mac 架构的 Hardened Runtime 自签名 `.app` 与 `.dmg`，同一构建 Mac 复用稳定的本地签名身份；服务端版本/安装包接口以及 macOS/Windows App 的检查、下载、安装触发和临时文件清理链路已交付，Developer ID、公证、Windows 签名和正式分发验收仍属于后续阶段。

上段是当前交付状态摘要；当前能力以 README、当前实现约束以 TECHNICAL-DESIGN 为准。下列未标记“已交付”的执行模式、生命周期和安全条目均描述目标完成态，不表示当前 App 已经开放。

### 客户端与执行模式

| 客户端 | 默认执行方式 | 可选执行方式 | 目标连接从哪里发起 |
| --- | --- | --- | --- |
| 普通 Web | 服务端转发 | 无 | 中心服务所在机器 |
| macOS App | 本机直连 | 服务端转发 | 用户电脑或中心服务所在机器 |

普通 Web 没有直接访问用户本机网络和本机连接凭据的可信执行环境，因此 Web 入口、SSH、SFTP、日志和数据库只能使用服务端转发。中心服务关闭某项转发能力时，普通 Web 中对应的连接功能不可用，但环境、连接、组织、权限等数据管理能力继续可用，不能假装从浏览器本机直连。

App 默认使用本机直连。目标网站、SSH、SFTP、日志和数据库请求均由用户自己的电脑直接发出，中心服务只提供身份认证、权限、组织和连接配置、加密凭据及组织审计接收能力，不参与目标流量转发。本机网络能连接目标就建立连接，不能连接就显示真实错误，不自动改用服务端转发。

App 可以在设置中主动切换到服务端转发。该设置按“当前设备 + Endpoint”全局保存，不提供逐连接覆盖。切换前查询当前 App 执行实例的活动 Web、SSH、SFTP、日志和数据库资源；存在活动资源时列出数量并要求确认，关闭失败时停止切换并提示。工作台布局与编辑内容保留，Cookie、终端和数据库会话不迁移。Web 在中心不支持代理时继续本机直连；SSH、SFTP、日志、数据库及对应巡检分项不支持时显示不可用，不能静默回退。

### App 静态界面与网络边界

- 安装包包含完整的前端静态资源，包括登录页、页面结构、样式、脚本和路由；App 启动、登录、升级或异常恢复时都不从中心服务加载前端页面，也不存在“先知道 Endpoint 才能加载登录页”的前置条件。
- 登录页是本地静态页面，其中提供 Viron Endpoint 输入。用户填写 Endpoint 后，只有身份验证、版本与能力协商以及业务数据通过中心服务 API 获取。
- App 界面负责展示数据和提交用户动作，不直接向 Endpoint 或目标系统发起网络请求。App 主程序通过受控的本地接口接收动作并负责中心服务 API、Cookie、WebSocket、上传下载和审计上报，也负责本机 Web、SSH、SFTP、日志、数据库连接和连接巡检。由于中心 API 请求不是由本地页面的浏览器网络层发起，桌面 App 不需要通过放宽 CORS 或关闭浏览器安全策略来连接 Endpoint。
- Web 账号页面在独立的 Chromium 账号浏览区中运行。账号浏览区在视觉上嵌入 App 工作区，但不是页面中的 `iframe`；每个账号拥有独立 Profile，Cookie、LocalStorage、IndexedDB、缓存和 Service Worker 不能跨 Endpoint、Viron 用户或连接凭据复用。
- App 界面只能提交连接 ID、视图位置和受限动作。App 主程序必须根据当前登录用户的权限重新取得可信连接信息，不能使用界面传入的任意目标地址、密文、密钥或本地文件路径。

### Endpoint、登录与版本兼容

- Endpoint 接受不含用户名和密码的绝对 HTTP(S) Origin；HTTP/HTTPS、回环、局域网地址或域名由用户根据部署环境决定。App 不按协议或主机类型预先拦截，只通过真实健康检查、产品标识和 API 协议协商判断是否可用；拒绝非根路径、查询参数、Fragment、嵌入凭据和非 HTTP(S) 协议。
- App 主程序负责规范化并验证 Endpoint，通过固定健康与能力接口确认对端确实是 Viron、证书有效、产品版本可识别且 API 协议兼容。验证失败时保留在本地登录页，显示具体错误，不保存为成功 Endpoint，也不猜测或自动切换到其他服务。
- App 复用中心服务现有的 Session Cookie，不新增 App Token。Cookie 按规范化 Endpoint 使用独立、持久化的会话容器；不同服务的登录态、缓存和本地数据不得混用。登录成功后保存最近一次成功 Endpoint；App 重启时可以预填并验证该地址，Cookie 仍有效则直接恢复登录，失效则显示同一 Endpoint 的登录表单。App 不保存管理员明文密码。
- 切换 Endpoint 前必须关闭全部活动连接，再切换到目标 Endpoint 的独立会话和本地数据。旧 Endpoint 的 Cookie、账号 Profile、设备密钥和执行方式设置不能交给新 Endpoint。
- 仓库内服务端、普通 Web 和桌面 App 使用统一产品 SemVer，根目录 `package.json` 是唯一版本来源，发布 Git 标签固定为 `vX.Y.Z`。API 协议另用独立递增的正整数版本，不能用产品版本字符串替代。
- App 与中心服务分别声明支持的 API 协议最小值和最大值，并在登录前选择交集中的明确版本。范围无交集时阻止登录，提示升级 App 或中心服务；App 继续显示自己打包的本地页面，不加载服务端前端作为兼容回退，也不开放部分未协商的能力。
- 登录后由中心服务返回总能力和分项转发能力，App 只展示双方版本都支持且服务端已开启的选项。服务能力在会话中发生变化时，先关闭受影响的活动连接，再更新设置和界面状态。

### 服务端转发能力

- 中心服务启动时从配置读取服务端转发能力。总开关默认开启，以保持普通 Web 客户端现有能力；同时提供 `web`、`ssh`、`sftp`、`logs`、`database` 分项开关，总开关关闭时所有分项视为关闭。
- 健康与能力接口只返回非敏感的产品标识、产品版本、API 协议范围以及分项能力，不返回连接凭据、内部地址或权限外资源信息。
- 普通 Web 始终使用服务端转发。服务端关闭某分项后，Web 对应入口应明确显示“服务端未启用此能力”，不能尝试由浏览器本机连接，也不能影响其他数据管理页面。
- App 默认使用本机直连。用户选择服务端转发后，各能力按中心声明的分项开关决定实际执行位置；Web 不支持代理时明确保留本机执行，SSH、SFTP、日志和数据库分项不支持时显示不可用。
- 服务端转发模式下，中心服务负责建立目标连接、使用凭据、执行资源限制并生成审计；App 只接收受控结果或交互流。服务端转发与本机直连必须复用相同的权限检查和用户可见操作语义，但各自维护独立的活动连接和目标 Session，不迁移 Cookie、终端或数据库会话。

### 中心服务与本机执行职责

中心服务始终负责：

- 用户登录、Session、组织与个人工作空间、角色权限和资源授权。
- 环境、连接、Web 入口及其他共享配置的持久化和版本控制。
- 凭据的加密存储、访问权限复核、向可信设备发放一次性加密信封。
- 服务端转发能力声明，以及启用转发时的目标连接执行。
- 组织工作空间审计的接收、幂等确认、查询和保留策略。

App 主程序在本机直连模式负责：

- 通过当前 Endpoint 的隔离 Session 调用中心 API，并统一处理 Cookie、WebSocket、上传下载、超时、证书和网络错误。
- 根据中心返回的授权配置建立和关闭本机 Web、SSH、SFTP、日志及数据库连接，并执行按连接 ID 受控的本机巡检。
- 管理账号浏览区、终端、文件传输、日志流和数据库会话的生命周期与本机资源上限。
- 解密单次连接凭据，完成连接后尽快释放明文引用，不把秘密交给 App 界面或持久化日志。
- 保存个人审计，并在组织工作空间中向中心可靠上报审计。

App 不是离线配置副本。中心数据只能通过中心服务修改；App 本地只保存运行所需的 Endpoint 隔离状态、Session Cookie、设备密钥、执行方式、目标 Session、个人审计和待上报组织审计。

### 设备密钥与连接凭据

- 所有发往 App 主程序用于本机直连的连接秘密统一使用“每设备 RSA + AES-256-GCM”信封传输，包括 Web 用户名和密码、SSH 密码、私钥及私钥口令、数据库密码、客户端证书及其口令；日志连接复用其 SSH 凭据。服务端转发模式不向 App 下发这些秘密。
- App 为每个“设备 + Endpoint + Viron 用户”生成独立的 3072 位 RSA 密钥对和稳定的 `deviceId`。macOS 私钥只由 App 主程序使用，并通过当前安装独有的本机随机密钥进行 AES-256-GCM 加密；Windows 私钥继续使用当前用户的操作系统安全存储保护。公钥在用户登录后注册到中心服务。密钥不得通过所有客户端共用的环境变量、安装包静态文件或仓库配置分发，也不得跨设备、Endpoint 或用户复用。
- 公钥注册必须包含持有证明。中心服务用待注册公钥加密一次性随机挑战，并绑定当前用户、设备、Endpoint、公钥指纹和短有效期；App 解密并回传原挑战后才启用该密钥。换钥时先完成新密钥注册再撤销旧密钥，用户可以在中心服务查看和撤销自己的设备。
- 每次发放凭据时，中心服务重新校验 Session、工作空间、资源权限、设备公钥和凭据版本，生成随机 32 字节数据密钥和 12 字节 IV，使用 AES-256-GCM 加密规范化凭据载荷，再使用 `RSA-OAEP-SHA256` 加密数据密钥。信封附加认证数据至少绑定协议版本、`keyId`、`deviceId`、一次性 `requestId`、用户、工作空间、凭据、Endpoint、目标 Origin、凭据更新时间、签发时间和不超过 60 秒的过期时间。
- App 只接受与当前未完成请求完全匹配、未过期且认证成功的信封；成功或失败处理后都消费 `requestId`，拒绝重放、身份不符、Endpoint 不符、资源不符、版本过旧和认证标签错误的响应。二进制字段使用无填充 Base64url，受保护 JSON 使用稳定规范化编码，避免两端附加认证数据不一致。
- 明文秘密只允许短暂存在于中心服务的授权解密/重新加密过程、App 主程序的单次解密/连接过程以及目标协议必须使用的内存中。不得进入 App 界面、普通 API 明文响应、日志、审计、崩溃报告、剪贴板、跨操作缓存或本地配置。
- 信封加密是 HTTPS 之上的纵深保护，用于避免截获 API 报文后直接得到凭据，不能替代 TLS、证书校验、权限复核和审计。本方案不试图阻止用户完全控制自己的电脑、修改 App 或读取本机进程内存后主动提取其获准使用的密码。
- 组织 SSH 密钥由组织管理员导入、生成、导出、更新、删除并关联到组织连接，普通成员只能在获得连接使用权限后发起连接，不能访问密钥管理、查看或导出接口。本阶段组织密钥继续沿用 App 本机直连和一次性凭据信封：获准使用连接的普通成员设备会在 SSH 认证期间取得组织私钥明文，当前只保证界面、普通 API、日志和本地持久化不暴露私钥，不承诺阻止成员从其完全控制的本机进程中提取私钥。后续待办是引入远程签名或受控 SSH Agent，使普通成员保持本机直连目标主机的同时只提交签名请求、私钥不再下发到成员设备。

### 本机 Session、状态与中心断线

- Web 账号按“Endpoint + Viron 用户 + Web 凭据”使用独立持久化 Profile。同一账号在不同电脑上的目标网站 Cookie 不同步；关闭账号浏览区可以保留 Profile，重新登录、资源删除、失权或用户显式清理时才按规则清除。
- SSH、SFTP、日志和数据库会话只属于当前 App 实例和当前执行方式。App 重启不恢复活动连接，只能在中心重新授权并取得新的一次性凭据信封后重新连接。
- 中心连接中断时，已经建立的本机目标连接可以继续使用；禁止新建连接、重新取得或重新填充凭据、切换工作空间、修改中心配置以及切换执行方式。恢复后必须先重新验证登录态、权限和资源版本，再允许新操作。
- 退出登录时立即使中心 Session Cookie 失效并关闭全部活动目标连接，但保留最近 Endpoint、按 Endpoint 和 Viron 用户隔离的账号 Profile、设备密钥、执行方式、个人审计以及尚未确认的组织审计队列，以便同一操作系统用户再次登录同一账号。不得把这些数据交给其他 Viron 用户。
- 设置中提供明确的“清除本机数据”，用于关闭连接并删除保存的 Endpoint、Cookie、账号 Profile、设备密钥、执行方式和个人审计。存在未确认的组织审计时不能静默删除，必须先完成补传或明确阻止清理并说明原因。

### 个人与组织审计

- 审计归属由操作发生时的工作空间决定。个人工作空间的操作审计只加密保存在用户本机，不上传中心服务；组织工作空间的操作审计必须保存到中心服务，供有权限的组织成员查询。
- 审计记录保存身份、设备、Endpoint、工作空间、资源、执行方式、动作、时间、结果和必要错误摘要。SSH 保存执行命令，数据库保存 SQL，SFTP 保存文件路径和上传、下载、重命名、删除等动作，Web 保存打开、导航、重新填充、重新登录、下载和权限决定等元数据。
- 审计不得保存完整终端输出、SQL 查询结果、网页正文、Cookie、文件内容、密码、私钥、证书口令或其他秘密。错误摘要也必须脱敏。
- 中心断线时，组织审计进入本机加密队列；已经建立的组织连接可以继续，但每个后续动作必须先成功写入队列。队列按先入先出补传，并使用稳定事件 ID 实现幂等；只有收到中心服务明确确认后才删除本地记录。
- 每个“设备 + Endpoint”队列上限为 10,000 条或 50 MB，任一达到即视为已满；达到 80% 时持续告警。队列满后停止新的组织工作空间操作，不能静默丢弃、覆盖旧记录或降级为个人审计。恢复连接后先补传队列，再恢复新的组织操作。

### 安全边界

- App 界面、账号网站和中心服务返回的数据都不直接获得本机通用能力。所有本机动作经过 App 主程序的白名单接口、参数校验、当前用户权限复核和资源归属检查。
- 账号浏览区按账号隔离，不得访问 App 登录 Cookie、其他账号 Profile、设备私钥、未经过用户选择的本地文件或通用剪贴板。网站文件输入只能通过 Chromium 原生文件选择器取得用户明确选择的文件；弹窗和下载继续归属原账号。摄像头、麦克风、地理位置、客户端证书和外部协议等高权限默认拒绝，后续逐项设计。
- 目标地址必须来自中心服务中当前用户有权访问的最新连接配置。自动填充只发生在配置的原始 Origin 主页面；用户明确点击钥匙按钮时可在该 Origin 的当前活动页重新识别和填充。跨 Origin 页面、验证码、MFA、WebAuthn 和复杂 SSO 由用户处理，不通过关闭同源策略、证书校验或 Chromium 沙箱换取兼容。
- 所有执行方式都实施连接数、超时、上传下载大小和输出速率限制。本机直连与服务端转发分别统计；普通 Web 和启用转发的 App 统一计入服务端转发配额，不能借切换客户端或执行方式绕过权限与限制。
- 日志、审计、错误提示和诊断包默认脱敏。开发调试能力不得在生产安装包中暴露设备私钥、凭据明文、Session Cookie 或任意命令执行入口。

## 环境内 Viron Agent

目标是让用户配置自己的模型 API Key，并通过持久多轮 Agent 获得可审计、可授权、受限执行的跨资源辅助。当前 Pi Agent 内核、Viron MCP 紧凑工具网关、SSH/数据库专用工具和统一审批闭环已经接入，后续不再重复建设第二套模型、权限或执行 Runtime。

阶段 0 与阶段 1A 已接入桌面 App：支持 OpenAI-compatible 与 Anthropic 协议、本机加密保存用户模型配置、自动获取模型列表、全局悬浮聊天窗、快捷输入、流式回复和停止请求。会话按设备、Endpoint 与用户隔离，跨工作空间保留，并可在两种 Chatbox 中新建、切换、重命名和删除。界面不显示场景卡片；发送消息时才静默读取当前页面及可见 SSH/数据库工作台的受限摘要。SSH 输出会移除终端控制字符，执行行数/字节限制与常见凭据脱敏；结构化单行命令只能填入当前聚焦终端，不会自动发送回车或执行。

默认安全边界：

- Agent 审批策略和执行位置相互独立，并按当前设备、Endpoint 与用户保存。旧配置默认使用“请求批准 + 在对话中显示”。
- “请求批准”对每个执行动作只显示一次内联确认卡，点击“确认并执行”后不再打开第二个确认窗口；“帮我批准”自动执行可证明为低风险的只读动作；“完全访问权限”自动执行已实现且启用的动作。所有档位都不能绕过当前用户权限、工具白名单、资源绑定、执行模式和审计。
- 删除、更新、权限变更等写操作仍需对应领域先实现安全工具、影响预览和 L3 风险控制；当前“完全访问权限”不会放开尚未实现的写工具。
- 只发送当前用户有权访问且与任务相关的环境信息，不发送无关密码、私钥、完整连接串或其他敏感数据。
- API Key 加密存储，前端不长期持有明文，日志不得记录完整 Key。
- 界面明确展示模型提供商、模型、发送的上下文范围和数据出站风险。

阶段 1B 数据库只读 Copilot 已交付：发送消息时可以读取当前本机数据库工作台的受限 Schema、SQL 编辑器和结果预览摘要，生成并填入 SQL；单条 `SELECT` 或 `EXPLAIN SELECT` 按统一审批策略由 App 主进程重新授权并受限执行，写 SQL、多语句、文件输出和锁副作用查询均拒绝进入专用数据库执行工具。数据库瞬时提示与结果预览经过截断和脱敏；本机 Viron Agent 操作记录按 Endpoint 与用户隔离，默认保留 30 天并可手工清除。

阶段 2 已迁移到 Pi Agent：Pi 负责连续多轮 ReAct/tool loop，Viron 通过 11 个 MCP 紧凑工具向其提供当前业务目录、操作搜索、schema、读写/高危/安全执行和 Operation 生命周期能力；SSH/数据库继续使用专用工作台工具。需要批准时，工具 Promise 在同一个 Pi loop 中等待一次内联确认；批准后原地继续，自动批准时仍显示可取消状态。App 主进程每次重新校验当前用户、Endpoint、工作空间、执行模式、目标现场和工具策略。选择“在对话中显示”时使用受控后台通道；选择“直接操作工作台”时，SSH 和数据库把操作与原始结果保留在当前可见工作台，对当前绑定现场的 MCP SSH/SQL 执行也会改走同一条工作台路径。单次执行最多 64 次工具调用、总时限 20 分钟，并可随时取消。切换工作空间只终止旧工作空间中的活动执行，不清除当前历史会话；连接关闭、禁用 Agent、设置或策略变化、退出登录或执行模式变化也会让活动执行失效。多行 Shell 脚本仍只能安全填入，不自动执行。历史文件只保存经过限制和常见凭据脱敏的用户/助手文本，不保存工具结果或现场摘要。

- **目标**：通用 Viron 业务能力采用“同一实现直接共用”，不是只在名称和行为上人工对齐。`src/shared/mcp-tools.ts` 与 `src/shared/mcp-business-operations.ts` 作为网关、业务操作目录、业务 Schema hash、权限/风险分级和调用分派的唯一代码事实来源，内置 Agent、远程 MCP 和本机 MCP 只保留各自协议适配。
- **当前进度**：Pi Agent 已消费 `createVironMcpCompactGateway` 生成的同一组 11 个工具名称、标题、说明和调用回调，现有 198 个目录操作也来自共享目录；但 `src/desktop/agent-runtime.ts` 仍通过 `gatewaySchemas()` 和 `gatewayRisk()` 单独维护紧凑网关的 Pi 参数 Schema 与风险映射。这两处属于待消除的适配层重复，完成前只能认定为“核心链路共用”，不能认定为“全部工具元数据完全共用”。
- SSH、数据库以及后续 Web/日志/Redis 等“当前可见工作台”能力允许存在 Agent 专用薄适配器，用于绑定当前页签、把动作和原始结果显示到工作台、处理焦点与取消；适配器必须复用既有 Runtime、权限复核、命令/SQL/操作策略、结果模型和审计，不得形成第二套通用业务目录。
- 新增可被内置 Agent 和外部 AI 使用的普通业务操作时，先进入共享 MCP 操作目录，再由两类 Agent 自动获得；不得先实现 Agent 私有工具后长期依靠手工同步。纯界面状态，例如打开 Chatbox、切换历史会话、移动悬浮按钮和界面动效，不属于 MCP 业务工具。
- **剩余验收**：同一业务操作必须验证内置 Agent 与远程/本机 MCP 在参数校验、Schema hash、工作空间绑定、权限、风险等级、审批、执行位置、结果限制、错误码、审计和生命周期回收上的一致性；允许不同的只有协议转换、交互呈现和当前工作台绑定方式。

## 日志查看增强

当前版本支持每个环境日志配置保存 1–10 个绝对文件路径，并通过指定 SSH 连接执行受控的多文件 `tail`；默认行数上限为每个文件最近 200 行，用户可在 1–5,000 范围内修改，之后持续跟随新增内容，同一上限也控制当前屏幕展示窗口。客户端自动高亮日志级别、时间戳、IP、常见标识、耗时和 HTTP 状态字段；当前屏幕支持固定关键字过滤、区分大小写、0–200 行上文/下文/上下文、关键字高亮，并可下载当前屏幕文本。后续候选能力包括：

- 时间和日志级别过滤。
- 为多文件输出中的每一行增加稳定来源标识，并支持按日志时间排序；当前只保留 `tail` 文件头和到达顺序。
- 脱敏和受控历史保留。

普通文件 `tail` 不具备 `kubectl logs --since/--since-time` 的时间查询语义。实施时间范围前必须先定义允许的日志时间格式和时区、跨行日志归属、无法识别时间戳时的处理方式，以及大文件扫描和输出速率上限；在这些约束确定前不得按文件修改时间或猜测行首时间来近似实现。

## 现有能力的候选增强

这些条目用于记录已知边界，不承诺进入近期版本：

- 连接巡检：定时巡检、运行取消、历史趋势、通知和报告导出。
- SSH 命令历史：在输入辅助之外，提高自定义 Shell 提示符和复杂补全场景的识别兼容性。
- ZMODEM：对超大文件改用流式本地写入或服务端临时文件中转，避免浏览器聚合完整 Blob。
- 数据库对象收藏：失效目标检测、手工排序和共享策略。
